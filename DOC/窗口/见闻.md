# 见闻 CollectionWindow

> 类型：实现 | 状态：已实现 | 核对：2026-11-10
> 何时读：改见闻窗口、解锁规则、怪物/魂灵图鉴
> 关键词：见闻 图鉴 解锁 CollectionDB manifest soul monster tooltip 放入仓库 筛选 content_id mod
> 代码：`Scripts/collection_db.gd`、`Windows/Collection/`、`base_mods/core/mod.json`
> 不覆盖：掉落规则（见 `怪物/怪物.md`）

这个窗口用来展示已遇见的怪物和魂灵；条目网格是窗口主体，右侧预留筛选区。

## 数据来源

| 层 | 位置 | 说明 |
|---|---|---|
| 清单 | `base_mods/core/mod.json` | core mod 的 `content.souls` / `content.monsters`；第三方 mod 用各自的 `mod.json` |
| 数据 | `SoulData` / `MonsterData` | 魂灵 tooltip 正文在 `SoulData.tooltip_blocks`；怪物数据在 `game/content/monster_data.gd` |
| 索引与状态 | `Scripts/collection_db.gd`（Autoload `CollectionDB`） | 从 `ModLoader` 条目构建目录、记录已遇见；解锁后由 `SaveManager` 统一写存档 |

## 解锁规则

- 怪物：战斗里**首次刷出**即记录（`BattleWindow._spawn_enemy()`）；
- 魂灵：**首次进入背包**即记录（监听 `GBIS.sig_inv_item_added`）；
- 状态存进统一存档 `user://saves/slot_0.json` 的 `collection` 段，键是 `content_id`（core 如 `snake_monster`、`xiao_lu_soul`）；旧怪物 ID `snake_data` / `fu_data` 由 `CollectionDB` 别名迁移；旧 `user://collection.cfg` 首次加载时只读迁移；
- `CollectionDB.unlock_all_for_testing` 默认 `false`：按真实进度显示；调试窗口“设置”页或 `TestAPI.set_unlock_all()` 可临时切换成全解锁。该开关只影响显示、不写存档；已打开的见闻窗口需要切页签/重开才会刷新。

## 界面

- “怪物 / 魂灵”两页；未遇见条目占位显示 `？？？`，不暴露名字和图标；
- 条目只有图标和名字，窗口不再有详情面板；
- 魂灵页的已遇见条目：悬停显示与仓库窗口一致的 tooltip（标题 + `SoulTooltip.build()` 正文，层级 `TooltipWindow.Layer.ITEM`）；未遇见条目不显示；
- 魂灵页的已遇见条目：右键放入仓库（`Warehouse.add_item()`，从第 1 页开始找空位），每次一颗；放入后走正常入包流程；成功时从条目图标播放一个向右的抛物线动画（纯视觉反馈，失败不播）；窗口底部固定提示「右键已遇见魂灵：放入仓库」；
- 怪物页不显示 tooltip，也不响应右键；
- `Root/VBox/Body/FilterPanel`（240 宽、空容器）预留给后续筛选功能。

## 注意

- 新增/删除魂灵/怪物时同步改 `base_mods/core/mod.json`；ID 由 manifest 决定，文件名不再参与存档键。
- `GBIS.add_item()` 会 `duplicate()` 物品，副本没有 `resource_path`，但 `content_id` 随副本保留，魂灵解锁直接读它；
- 单条解锁走 `CollectionDB.entry_unlocked`；读档整体替换“已遇见”状态时走 `state_reloaded`，窗口刷新当前页；
- 怪物数据抽成 `MonsterData` 后，战斗场景只负责碰撞体和节点结构，刷怪时由 `_spawn_enemy()` 把名字、数值和贴图注入 `BattleUnit`。
