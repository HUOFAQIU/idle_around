# 见闻 CollectionWindow

> 类型：实现 | 状态：已实现 | 核对：2026-11-15
> 何时读：改见闻窗口、解锁规则、怪物/魂灵/魂器图鉴
> 关键词：见闻 图鉴 解锁 CollectionDB manifest soul monster vessel 魂器 tooltip 放入仓库 筛选 content_id mod
> 代码：`Scripts/collection_db.gd`、`Windows/Collection/`、`base_mods/core/mod.json`
> 不覆盖：掉落规则（见 `怪物/怪物.md`）

这个窗口用来展示已遇见的怪物、魂灵和魂器；条目网格是窗口主体，右侧预留筛选区。

## 数据来源

| 层 | 位置 | 说明 |
|---|---|---|
| 清单 | `base_mods/core/mod.json` | core mod 的 `content.souls` / `content.monsters` / `content.vessels`；第三方 mod 用各自的 `mod.json` |
| 数据 | `SoulData` / `MonsterData` / `SoulVesselData` | 魂灵 tooltip 正文在 `SoulData.tooltip_blocks`；怪物数据在 `game/content/monster_data.gd`；魂器数据在 `SoulVesselData` |
| 索引与状态 | `Scripts/collection_db.gd`（Autoload `CollectionDB`） | 从 `ModLoader` 条目构建目录、记录已遇见；解锁后由 `SaveManager` 统一写存档 |

## 解锁规则

- 怪物：战斗里**首次刷出**即记录（`BattleSession._spawn_enemy()`）；
- 魂灵：**首次进入背包**即记录（监听 `GBIS.sig_inv_item_added`）；
- 魂器：**首次进入任意容器**（仓库或角色魂器网格）即记录；魂器内部的魂灵同时解锁；
- 状态存进当前活动槽（`user://saves/slot_N.json`）的 `collection` 段，键是 `content_id`（core 不带前缀，第三方带 `<mod_id>:` 前缀）；
- 标题栏「全解锁」按钮：调用 `CollectionDB.unlock_all()`，把目录里的全部魂灵/怪物/魂器写入已遇见并立即存档；一次性永久解锁，不提供还原；
- `CollectionDB.unlock_all_for_testing` 默认 `false`：按真实进度显示；调试窗口“设置”页或 `TestAPI.set_unlock_all()` 可临时切换成全解锁。该开关只影响显示、不写存档；已打开的见闻窗口需要切页签/重开才会刷新。

## 界面

- 标题栏：关闭按钮左侧有「全解锁」按钮（`add_title_bar_button()`），永久解锁全部见闻并保存；
- “怪物 / 魂灵 / 魂器”三页；未遇见条目占位显示 `？？？`，不暴露名字和图标；
- 条目只有图标和名字，窗口不再有详情面板；
- 魂灵页的已遇见条目：悬停显示与仓库窗口一致的 tooltip（标题 + `SoulTooltip.build()` 正文，层级 `TooltipWindow.Layer.ITEM`）；见闻是图鉴，固定显示基础值，不叠加战斗运行期加成，也不做“装上后”预览；未遇见条目不显示；
- 魂器页的已遇见条目：悬停显示 `VesselTooltip`；见闻展示的是模板，没有运行时内容，内部网格会显示满格 `*`；
- 魂灵/魂器页的已遇见条目：右键放入仓库（`Warehouse.add_item()`，从第 1 页开始找空位），每次一件；放入后走正常入包流程；成功时从条目图标播放一个向右的抛物线动画（纯视觉反馈，失败不播）；
- 底部提示按页签切换：怪物「怪物：首次刷出即解锁」、魂灵「右键已遇见魂灵：放入仓库」、魂器「右键已遇见魂器：放入仓库」；
- 怪物页不显示 tooltip，也不响应右键；
- `Root/VBox/Body/FilterPanel`（240 宽、空容器）预留给后续筛选功能。

## 注意

- 新增/删除魂灵/怪物/魂器时同步改 `base_mods/core/mod.json`；ID 由 manifest 决定，文件名不再参与存档键。
- `GBIS.add_item()` 会调用 `ItemData.make_instance()` 复制物品（普通物品等价于 `duplicate()`，魂器会连同内部魂灵复制），副本没有 `resource_path`，但 `content_id` 随副本保留，解锁直接读它；
- 单条解锁走 `CollectionDB.entry_unlocked`；读档整体替换“已遇见”状态时走 `state_reloaded`，窗口刷新当前页；
- 怪物数据抽成 `MonsterData` 后，战斗场景只负责碰撞体和节点结构，刷怪时由 `BattleSession._spawn_enemy()` 把名字、数值和贴图注入 `BattleUnit`。
