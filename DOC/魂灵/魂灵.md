魂灵没有部位限制，只按占格大小占用魂器内部容器；尺寸同时决定 tooltip 头部显示。


# 规范描述
主动魂灵都拥有冷却，冷却结束会释放技能，技能拥有至少一个效果。主动魂灵也会有触发效果。
（实现状态：`SoulData.triggers` 主动/被动魂灵通用；属性型 `passive_effects` 仍只有 PassiveSoulData 支持。）
被动魂灵拥有被动效果或者是至多 6 条属性，这两者不会同时存在。

# 类型
魂灵可以带类型（`SoulData.types`，`StringName` 数组），用于让特定效果只在这些魂灵上触发；类型按需配置，不强制每颗魂灵都有。
类型不做层级分类，直接用 `Soul.types` 前缀。

一个魂灵可以同时带多个语义类型，例如同时带 `Soul.types.Wolf` 和 `Soul.types.Animal`；类型数量不做限制。
类型中文名统一在 `Scripts/soul_text.gd` 的 `SoulText.TYPE_NAMES`，tooltip / 见闻 / 调试共用；未知类型回退到 ID 最后一段。


# 标签
每个魂灵都有标签，用于作为见闻窗口的筛选功能，能筛选相应标签的魂灵，快速检索。
直接用 `Soul.tags` 前缀。

能够造成伤害的具有`Soul.tags.Damage`，`Soul.tags.DamageReference`
能够造成灼烧的具有`Soul.tags.Burn`，`Soul.tags.BurnReference`
等等
其他类似也一样

当前实现的效果标签：`Soul.tags.Damage` / `Soul.tags.DamageReference`、`Soul.tags.Burn`、`Soul.tags.Poison`、`Soul.tags.Freeze`、`Soul.tags.Heal`、`Soul.tags.Regen`、`Soul.tags.Shield`、`Soul.tags.Haste`、`Soul.tags.Slow`、`Soul.tags.Charge`。Reference 表示与对应效果相关但不直接产生该效果。


## 尺寸

按占格宽度判定，所有魂灵都带且只带一个尺寸标签：

| 尺寸标签 | tooltip 显示 | 占格 |
|---|---|---|
| `Soul.tags.Small` | `[小型]` | 1 列 × 2 行 |
| `Soul.tags.Medium` | `[中型]` | 2 列 × 2 行 |
| `Soul.tags.Large` | `[大型]` | 3 列 × 2 行 |

尺寸中文名在 `SoulText.SIZE_NAMES`，由 `SoulData.size_tag()` 取；`ModLoader` 要求每颗魂灵恰好一个尺寸标签。占格仍由 `ItemData.columns / rows` 决定，魂器内部容器按这个形状放魂灵。

当前卡面按尺寸统一使用 `Assets/soul_small.png`、`soul_medium.png`、`soul_large.png`；魂灵名称由 `ItemView` 的 `SoulNameLabel` 叠在卡面上，背包、魂器容器、角色魂器网格、拖拽幽灵四处一致。

## Tooltip

鼠标悬停在魂灵卡面上时显示；标题（魂灵名）由终端顶部的跨格大字绘制，正文由 `Windows/Tooltip/soul_tooltip.gd` 的 `SoulTooltip.build()` 统一生成：

```
<魂灵名>                    ← 终端顶部跨格大字（TooltipWindow.TITLE_SPAN_ROWS = 2 行高，带下划线）
[大型][狼][动物]            ← 尺寸标签在前，再按 soul.types 显示；都可选
(空行)
暴击率，<crit_chance × 100> %
攻击距离，<技能 TargetRule.max_range；非 TargetRule 为 0>
===================================
<SoulData.tooltip_blocks[0]，其中 {cooldown}/{cast_times}/{damage}/{damage_per_soul} 已替换成对应数据>
===================================
<SoulData.tooltip_blocks[1]>
===================================
← 最后一段之后也有结尾分隔线
```

- 头部第一项是尺寸，中文名由 `SoulText.size_name()` 提供；后面按 `SoulData.types` 的顺序显示语义类型，中文名由 `SoulText.type_name()` 提供。
- 魂灵不再显示部位行，`SoulData.equip_part` 已删除。
- 正文段落来自 `SoulData.tooltip_blocks`，格式化器在段落之间和最后一段之后都用 `===================================` 分隔；`{cooldown}` / `{cast_times}` 来自技能，`{damage}` / `{damage_per_soul}` 来自技能里第一个 `SoulDamageExecution`（`base_damage` / `bonus_per_matching_soul`），数字不要在文案里写死。只有 `cast_times > 1` 的魂灵才写「多重触发」这一行。
- 动态伤害：悬停魂器窗口内的 COMBAT 魂灵时，`TooltipWindow` 调 `SoulDamagePreview`，`is_dynamic = true` 时在数字前加 `*`（如 `*50`）。战斗中且魂器已装备时用 `SoulRuntimeDB.get_runtime(soul)` 的运行期值（最准，含临时 buff）；仓库/未开战时按“装上这份魂器后”静态预览：匹配数量与玩家被动加成用当前角色魂器网格 + 这份魂器的魂灵，魂器加成取这份魂器。背包里的散装魂灵、见闻、TOOL 魂器，以及拿不到魂器上下文时仍显示基础值，不加 `*`。
- 静态预览的玩家 `damage_bonus` 只汇总 `PassiveSoulData.passive_effects` 里 `modifiers` 的 STATIC 数值，所以只有 STATIC 修正能精确复现；`SET_BY_CALLER` / `ATTRIBUTE_BASED` 或自定义 execution 改的属性预览不到，战斗中仍以运行期值为准。
- 预览值不含暴击，向下取整。
- 没有 `tooltip_blocks` 的魂灵只显示头部 + `无`，后面同样补一条结尾分隔线。
- 分隔线由格式化器插入，标点为中文全角，数字去掉小数尾零；新增魂灵只填数据，不改 UI 代码。
- 魂灵的文案全部在魂灵资源的 `tooltip_blocks` 里，数值用占位符，技能资源只存实际数值。
- 见闻窗口的魂灵条目、仓库/魂器窗口的悬停提示都复用同一份 tooltip；未遇见条目不显示。

```text
tooltip_blocks = Array[String]([
	"( {cooldown} 秒 )\n> 对最近的怪物造成 {damage} 伤害\n> 多重触发: {cast_times}\n\n- 每有一个匹配类型的魂灵，此魂灵+{damage_per_soul} 点伤害",
])
types = [&"Soul.types.Wolf", &"Soul.types.Animal"]
tags = [&"Soul.tags.Large", &"Soul.tags.Damage"]
```

类型/尺寸中文名不在魂灵资源里重复填；在 `Scripts/soul_text.gd` 的 `TYPE_NAMES` / `SIZE_NAMES` 里维护一次，所有界面共用。

正文控件是 `TooltipWindow` 内嵌的 `TerminalView`：仓库/见闻悬停时传 `SoulTooltip.build(soul, TooltipText.Format.PLAIN)` 的纯文本，`TooltipWindow` 再调 `TooltipText.to_ansi()` 按字符网格排版（调试网格已开启）。标题也由同一个 `TerminalView` 用 `TerminalSpan` 画在顶部，占 2 行字符高并带下划线（当前画在 span 块底部）；正文从第 2 行开始，不再有单独的 `TitleLabel`。`SoulTooltip.build(soul, TooltipText.Format.BBCODE)` 仍返回 BBCode，`Format.ANSI` 返回终端 ANSI SGR，供 TestAPI 对比。三种输出共用同一套 `GameColors` 色板，色板同时供战斗日志、头顶飘字、状态条使用，定义在 `Scripts/game_colors.gd`：

| 关键词 | 颜色 | 情绪 |
|---|---|---|
| 伤害 | `#f5503d` | 忿怒 |
| 灼烧 | `#ff9f45` | 怒火 |
| 剧毒 | `#0ebe4f` | 怨毒 |
| 加速 | `#00ecc3` |  |
| 减速 | `#cb9f6e` |  |
| 充能 | `#00ecc3` |  |
| 生命再生 | `#8eea31` |  |
| 治疗 | `#8eea31` | 怜悯 |
| 暴击率 / 暴击 | `#f5503d` |  |
| 冻结 | `#3fc8f7` | 冷漠 |
| 护盾 | `#f4cf20` | 担忧 |

- 长词优先匹配（`暴击率` 不会被拆成更短的「暴击」）；标题、类型行、攻击距离不参与状态词上色。
- 分隔线使用暗色 `#4a4f58`；`( X 秒 )` 冷却行用粗体强调（正文 16），标题由 2 行高跨格大字绘制，字号按块高反推。
- `暴击率，X %` 整行使用暴击色 `#f5503d`，其余行只给关键词上色。
- BBCode 模式下正文里的 `[` / `]` 会转义成 `[lb]` / `[rb]`，保证 `[狼]` 按原文显示；ANSI 模式不转义，直接按原文输出。
- `SoulTooltip.build(soul)` 默认返回纯文本，是 TooltipWindow 的实际输入；`SoulTooltip.build(soul, TooltipText.Format.ANSI)` 仍可用于直接喂终端。
- ANSI 模式下冷却行用粗体代替 20 号字，分隔线/暴击率/状态词使用与 BBCode 相同的颜色（truecolor `38;2`）。
- `tooltip_blocks` 只写纯文本 + 占位符，不写 BBCode/ANSI；行宽控制在约 72 半角列内（终端窗口 90 列，中文按 2 列算）。`TooltipText` 读取时统一 CRLF → LF，避免 `\r` 在终端里把光标拉回行首。
- 共用的数字/分隔线/关键词着色逻辑在 `Windows/Tooltip/tooltip_text.gd` 的 `TooltipText`，魂器 tooltip 复用同一套；`TestAPI.get_soul_tooltip_text/bbcode/ansi()` 可分别验证三种输出。
