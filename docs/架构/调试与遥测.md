## 1. 数据流与核心契约

```text
模拟层 (BattleManager/BattleUnit/AutoCastAbility/SoulTriggerAbility/BattleBrain)
  └─ BattleEventBus ─┬─ CombatTelemetryAdapter ─► CombatTelemetry (环形缓冲/JSONL) ─► TestAPI / Terminal (`debug.state`)
                     ├─ BattleLogAdapter ───────► InfoWindow ─► TerminalView
                     ├─ CombatConsoleAdapter ───► print_rich
                     └─ CombatNarrator ─────────► 中文 log/line（回总线）
SoulLoadout ─► SoulRuntime ─► SoulRuntimeDB (仅玩家已装备注册；怪物不注册，快照读 loadout)
```

- **不侵入 & 不存 Node**：模拟层只发 `BattleEvent`，不直连 `CombatTelemetry`/`InfoWindow`/`print_rich`；关 `CombatTelemetry.enabled` 后 `record()` 立即返回。入缓冲前经 `CombatTelemetrySchema.unit_info()` 转 `{id, name, team}`。
- **因果链（`CombatTrace`）**：id 全局自增不按场重置；`AutoCastAbility` 建 `cast:<技能名>`，效果 spec 用 `SoulEffectContext`（`GameplayEffectContext` 子类）传递 trace；周期效果施加时 `calculated_deltas` 仅是预览，不伪造伤害事件。
- **挂载时序**：观察者须在生成单位前挂到总线（否则漏 `unit_asc_ready`）；`bind_ability()` 须在 `SoulRuntime` 建好后调用。

## 2. 事件字段与接入点

- **统一字段**：`seq`、`run_id`、`frame`、`t`、`category`（`battle/cast/soul/trigger/effect/attribute/tag/cue/log/system`）、`type`、`importance`（`important`/`detail`）、`actor/target/unit`、`soul/ability/ability_tag/effect`、`amount/*_delta`、`trace_id/parent_trace_id/root_trace_id`、`detail`、`color`。
- **重要度过滤**：玩家相关为 `important`；敌人细节（属性/周期 tick/跨格移动/充能）为 `detail`，仅 `watch_unit_id` 命中或 `record_detail_globally = true` 才入缓冲（未命中在 `duplicate`/归一化前直接丢弃）。模拟层发出前先用 `CombatTelemetry.is_unit_detailed(unit)` 拦截（我方、关注单位、全局开关任一命中才发出），敌人施法步骤与 `soul/*` 细节事件不再构造。

| 来源 | 发出 / 绑定内容 |
|---|---|
| `BattleManager` / `BattleBrain` | `battle/unit_added|moved|enemy_in/out_of_range|drop_roll|drop`、`log/line`；`soul/pending|flush_skip` |
| `AutoCastAbility` / `SoulTriggerAbility` | `cast/attempt|activate|release|cast_start|empty|targets|crit|projectiles`、`soul/used`；`trigger/fired` |
| `BattleUnit` / `ChargedAbility` / GAS ASC | `unit_asc_ready`、`soul_runtime_created`；适配器转译 `soul/*`、属性/标签/ActiveEffect/周期 tick/能力事件 |
| `CombatNarrator` | 订阅业务事件生成中文 `log/line`（含魂灵步骤空放总播报，纯单位技能仅我方播报） |

## 3. 性能约定与新增事件

- **性能硬边界**：不记每帧充能（只记外部充能/状态/激活/触发）；敌人只绑 `died`，`watch_unit()` 再补绑详细 ASC 信号；缓冲默认 5000 条，溢出一次裁 10% 累计 `dropped_events`；JSONL 每 50 行 flush；充能统计由 `ChargedAbility._on_charge_received()` 写 `SoulRuntime`，遥测不改玩法计数。
- **新增事件 4 步**：1) `game/battle/battle_event.gd` 选/加 `CATEGORY_*` → 2) 模拟层调 `battle.events.emit_event(...)`（不绕过总线）→ 3) 需进日志用 `CATEGORY_LOG` 并在 `combat_narrator.gd` 写中文 → 4) 仅新增订阅者或改路由时更新本文 §1。
- **已知边界**：`GameplayCueManager` 未暴露播放信号，调试窗仅展示注册表与效果挂点；`SoulRuntime.counters` 暂用字典；测试查询入口见 `scripts/test_api/debug.gd`。

## 4. 启动耗时打点

`scripts/debug/startup_timing.gd`（`StartupTiming`）以 `Time.get_ticks_msec()` 为基准，在 `ModLoader._init`、`CollectionDB._ready`、`GameFlow._ready`、主场景 `_ready` 与首帧 `frame_post_draw` 打印耗时到 Output 面板；调用点用 `preload` 保证 `--script` 模式可用。
