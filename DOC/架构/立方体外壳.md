## 1. 场景结构

主场景是 `Main/Cube/Scenes/main.tscn`（Node3D），`Main/control.tscn` 是主视口里的游戏 UI 覆盖层，不是面片内容。

```text
Main/Cube/Scenes/main.tscn
├─ CubeView（CanvasLayer，layer=1024）
│  ├─ ViewportContainer（SubViewportContainer，全屏、stretch、mouse_filter=IGNORE）
│  │  └─ CubeViewport（SubViewport，transparent_bg、own_world_3d、MSAA 4×）
│  │     ├─ WorldEnvironment / KeyLight / FillLight / RimLight
│  │     ├─ Cube（FloatingMotion，缩放和位置由 CubePlacement 每帧设置）
│  │     │  └─ CubeRig
│  │     │     ├─ OrientationPivot
│  │     │     │  ├─ Body + 12 × Edge
│  │     │     │  ├─ Front/Left/Right/Top/Bottom
│  │     │     │  │  └─ Face3D → Viewport(512×512) → FaceUI
│  │     │     │  └─ Back（面 02）
│  │     │     │     └─ PetFace3D(ui_capture) → Viewport(300×300) → PetPanelContent
│  │     │     │                                            └─ Main/pet_panel.tscn
│  │     │     └─ DragHandle（CanvasLayer）→ Dot（屏幕空间拖动圆点）
│  │     └─ Camera3D
│  └─ InputSurface（Control，全屏，自定义 `_has_point`）
├─ GameUI（CanvasLayer，layer=1）
│  └─ Main/control.tscn（游戏 UI 全屏覆盖层）
├─ HUD（CanvasLayer，layer=2，只剩底部 Toast）
├─ CubePlacement
└─ WindowPassthrough
```

- 立方体渲染进 `CubeViewport`，再由 layer=1024 的 `CubeView` 合成到主视口：它压住 `GameUI`（1）和 `HUD`（2），但仍低于 `DragLayer`（1025）和 `TooltipLayer`（1026）。
- `InputSurface` 只在立方体屏幕轮廓（含拖动圆点）内参与 GUI 拾取；命中后把鼠标事件推进 `CubeViewport`，由 `CubeRig` 按原逻辑处理。轮廓外的事件仍落到游戏 UI，因此视觉层级和输入层级一致。
- 主场景里立方体子树的节点路径集中在 `cube_scene_paths.gd`；`CubePlacement` / `WindowPassthrough` / `CubeInputSurface` 通过 `CubeScenePaths.resolve()` 解析，改 main.tscn 里的子树只改这一份（cube.tscn 内部的拖动圆点路径仍由 `CubeRig` 维护）。`TestAPI.get_cube_layering_state().input_ready` 可检查解析结果。
- 面 02 是背面（`face_index = 1`），承载原来的 PetPanel 主菜单；立方体承接 PetPanel 的浮层职责，其余五面保持原 FaceUI 的内容和行为。
- 初始朝向 `OrientationPivot.rotation_degrees = (0, 180, 0)`，开局背面正对屏幕；松手接近某个面时仍按原 25° 阈值自动回正。
- 游戏 UI 的窗口、Tooltip、拖拽幽灵都在主视口里，不再被立方体面片裁剪；被立方体盖住的面板区域不可见、也不接收 hover/点击。
- HUD 的左上标题卡已删除；`CubeHud.get_overlay_rects()` 只返回可见 Toast。

## 2. 模块与内容

`Main/Cube/` 是自包含模块：

```text
Main/Cube/
├─ Scenes/
│  ├─ main.tscn                主场景
│  ├─ cube.tscn                立方体、六面、边光、拖动圆点
│  ├─ face_3d.tscn             普通面模板（512×512 FaceUI）
│  ├─ pet_face_3d.tscn         面 02 模板（300×300 主菜单）
│  └─ UI/
│     ├─ face_ui.tscn          普通面内容
│     ├─ pet_panel_content.tscn 面 02 内容
│     └─ hud.tscn              底部 Toast
├─ Scripts/
│  ├─ main.gd                  装配：面识别 → HUD，主菜单请求 → GameUI
│  ├─ cube_rig.gd              射线、旋转/点击分流、UI 输入转发
│  ├─ cube_input_surface.gd    顶层输入代理：轮廓命中 + 事件推进子视口
│  ├─ cube_projection.gd       8 角屏幕凸包；穿透与输入命中共用
│  ├─ cube_scene_paths.gd      主场景内立方体子树的规范 NodePath
│  ├─ cube_orientation.gd      自由旋转、惯性、回正
│  ├─ cube_placement.gd        屏幕锚定、按视口换算缩放、位置持久化
│  ├─ cube_settings.gd         [cube] 位置读写
│  ├─ face_3d.gd               面片 + 子视口 + 指针映射
│  ├─ face_content.gd          面内容基类
│  ├─ face_ui.gd               普通面 UI
│  ├─ pet_panel_content.gd     面 02 内容：转发 PetPanel 的按钮请求
│  ├─ floating_motion.gd       漂浮
│  ├─ drag_handle.gd           屏幕空间拖动圆点
│  ├─ hud.gd                   面识别 Toast
│  └─ window_passthrough.gd    窗口鼠标区域
└─ Resources/UI/               字体、主题、两个 canvas shader
```

- `FaceContent` 只约定 `identify_requested` 信号和 `setup(index, name, accent)`；`Face3D` 不再硬绑 `FaceUI`。
- `FaceUI` 继承 `FaceContent`；`PetPanelContent` 继承 `FaceContent` 并转发 `PetPanel.panel_requested`。
- `Main/pet_panel.tscn` 是从原 `control.tscn` 抽出的主菜单（300×300），只负责按钮和 `panel_requested(panel_id)`，不再自己拖动/持久化。
- 立方体主题 `cube_theme.tres` 只挂在 FaceUI / HUD 根节点，不作为项目全局主题，避免改变游戏 UI 的默认字体和配色。

### 2.1 面 02 的尺寸与屏幕锚定

| 项 | 值 |
|---|---|
| 面片 QuadMesh | 1.9 × 1.9（正方形） |
| SubViewport | 300 × 300 |
| 碰撞盒 | 2 × 2（沿用整面，射线在留白边也命中） |
| 面 02 屏幕投影 | 约 300 × 300 px（由 `CubePlacement` 按视口高度换算） |
| 默认位置 | 左下角，边距 `GameGlobal.WINDOWPOSOFFSET` = 5px |

- `CubePlacement` 把立方体中心锚定在屏幕坐标上，位置存在 `user://Settings.cfg` 的 `[cube]` 段、`screen_position` 键；拖动圆点移动，松手写入。
- 子视口由 `SubViewportContainer.stretch` 跟随主视口，1:1；屏幕锚定和夹取用主视口尺寸，投影换算用子视口里的相机。
- 默认位置按**面 02 中心**反算：面 02 是近端面，透视下会比立方体中心更靠外，直接放立方体中心会把菜单裁掉；反算后菜单落在原 PetPanel 的 5px 边距内。
- 缩放按当前视口高度和相机 FOV 反解，使面 02 在屏幕上的投影保持约 300px；改窗口分辨率不需要改场景。
- 面片是 1.9、房间侧面是 2，所以面片四周留约 0.05 单位的立方体本体；留白边和碰撞盒边缘用于拖动旋转。
- 菜单按钮保持 80px 视觉尺寸，和原 PetPanel 一致。

## 3. 输入链路

立方体的输入分两段：主视口的 `CubeInputSurface` 负责命中和优先级，子视口里的 `CubeRig._unhandled_input()` 负责射线与面内转发。游戏 UI 在主视口里，轮廓外仍走 Godot 原生输入。

0. 主视口 GUI 拾取先命中 `InputSurface`（layer 1024）的 `_has_point()`：立方体投影凸包或拖动圆点。
   - 命中：`_gui_input()` 把事件 `push_input` 给 `CubeViewport`，随后 `accept_event()`；被立方体盖住的面板收不到 hover/点击。
   - 未命中：事件继续落到 `GameUI`/`HUD`，行为同旧版。
   - 按住后拖出轮廓：Godot 的 GUI mouse_focus 继续把事件送到 InputSurface，旋转/拖动不断。
1. 左键按下（`CubeRig` 收到后）：
   - 先检测拖动圆点；命中则进入移动立方体。
   - 否则射线命中 Face3D。若该面 `ui_capture = true` 且 `Face3D.ui_hit_at()` 查到指针下有可交互控件，则把按下转发给面内 UI，记入 `_ui_face`，**不进入旋转**。
   - 空白区域、留白边、其它面走原逻辑：按下转发给面内容；拖动超过 7px 取消按钮并旋转。
2. UI 捕获期间：鼠标移动、松开都按面所在平面换算世界点后转发，移出面片也不丢事件；松开后若指针已离开内容区则补发 `notify_mouse_exited()`。
3. 右键/滚轮：命中 `ui_capture` 面且落在内容区时，复制原事件（保留右键、滚轮、双击、Shift/Ctrl/Alt 修饰）转发给子视口。
4. 其它五面保持原交互：按下转发、拖动超阈值取消并旋转，松手点击面内按钮。
5. 鼠标离开窗口/失焦：取消当前 UI 捕获或旋转，清理 hover；主视口的 `InputSurface` 会把这两个窗口通知转发给子视口里的 `CubeRig`。
6. 主菜单按钮点击后，`PetPanel.panel_requested` 经 `PetPanelContent` → `main.gd` → `GameUI.open_panel()`，窗口在主视口打开/关闭，和以前 PetPanel 的按钮行为一致。
7. 指针离开立方体轮廓：`InputSurface.mouse_exited` 通知子视口并调 `CubeRig.pointer_left()` 清 hover；拖动和 UI 捕获期间不打断。

`Face3D` 负责映射：

- 面片尺寸和子视口尺寸从场景读取，不再硬编码 512。
- 子视口像素坐标 = `((local.x / quad.x + 0.5) * viewport.x, (0.5 - local.y / quad.y) * viewport.y)`。
- 控件优先判断用 `SubViewport.gui_get_hovered_control()`；转发后 `SubViewport.is_input_handled()` 可用于调试确认。

## 4. 透明窗口与点击穿透

- `WindowPassthrough` 负责全屏透明窗口的鼠标区域：
  1. 把立方体本地包围盒 8 个角（`CubeProjection.HALF_EXTENT = 1.03`）投影成屏幕凸包；相机在 `CubeViewport` 里，`WindowPassthrough` 和 `CubeInputSurface` 共用 `CubeProjection`；
  2. 加上可见游戏面板、`TooltipWindow`、`ItemWindow`、可见 HUD Toast 和拖动圆点的屏幕矩形；
  3. 立方体凸包外扩 `REGION_PADDING = 28px`，UI 矩形外扩 `UI_REGION_PADDING = 8px`，由 `Scripts/ui/ui_region.gd` 用 2px 走廊合并成一个顺时针多边形，写入 `Window.mouse_passthrough_polygon`；
  4. 按下鼠标时临时扩成整个客户区，松开/旋转结束后恢复。
- 应用内层级和 OS 穿透是两件事：立方体压住面板时，`InputSurface` 先吃掉轮廓内的事件；OS 层的区域仍取「凸包 + UI 矩形」的并集。
- 游戏 UI 窗口的矩形每帧对比一次，窗口开关/拖动、Tooltip 跟随都会触发区域重建；立方体子视口尺寸变化也会触发。
- TestAPI：`set_cube_passthrough_enabled()` / `is_cube_passthrough_enabled()` / `get_cube_passthrough_state()`。

### 4.1 全屏坑（Godot 4.7）

- `project.godot` 不能同时启用 `window/size/resizable=false`、`window/size/maximize_disabled=true`、`window/size/always_on_top=true`，否则 `mode=3` 启动后会降级成接近屏幕大小的窗口，透明覆盖层失效。
- 主窗口必须 `borderless=true`；不要运行期改窗口 `position`/`size`，Windows 上会破坏逐像素透明。
- 从编辑器运行前关闭 Game 面板的 Embed Game。

## 5. 渲染与工程设置

- 渲染：Forward Plus / Windows D3D12，透明清屏色；保留游戏原有的 `textures/canvas_textures/default_texture_filter=0` 和 `run/max_fps=60`。
- 立方体世界在 `CubeViewport` 里：`transparent_bg=true`、`own_world_3d=true`、`msaa_3d=2`（4×，对齐原工程设置）、`render_target_update_mode=ALWAYS`。`CubeView` 用 layer=1024 合成到主视口，上面是 `DragLayer`（1025）和 `TooltipLayer`（1026）；要改上下层只动 `CubeView.layer`，但输入代理和渲染在同一个 CanvasLayer 下，不要拆开。
- 相机 `fov = 12°`：立方体停在左下角时，视线与面 02 法线约 10°，菜单不会看起来歪；FOV 同时影响 `CubePlacement` 的缩放和漂浮的屏幕幅度，改 FOV 后要重新核对 `FloatingMotion` 的 `bob_height`/`sway_width`。
- 3D 物理沿用 Godot 默认引擎，立方体射线只依赖 Area3D，不引入 Jolt；射线在子视口的 `World3D` 里。
- 窗口：`mode=3`、`borderless`、`transparent`、`per_pixel_transparency`、`viewport 1×1`、`stretch/mode="disabled"`。
- 立方体缩放不再写死在场景里：`CubePlacement._process()` 每帧按视口高度重算，场景里的 Cube 保持单位缩放。
- 透明子视口多一次全屏合成；立方体本身很轻，但改渲染设置后要看 FPS。glow/MSAA 的观感以实际画面为准。

## 7. 已知限制

- 立方体压住的面板区域不可见、不可点，下层面板的 Tooltip 也不会从立方体下面弹出；这是顶层输入代理的预期行为。
- Tooltip（1026）和拖拽幽灵（1025）仍在立方体之上；从旁边弹出的 Tooltip 可以盖住立方体。
- 主菜单在面 02 上，转到其它面时菜单不可用；需要转回背面。
- 立方体默认在左下角，面 02 会因相机视角有轻微透视；越靠屏幕中心越正。
- 面 02 子视口每帧重绘（UPDATE_ALWAYS），但只有 300×300。
- 拖动圆点只负责移动立方体；面 02 的空白区域拖动是旋转。
- 终端窗口目前没有键盘输入，因此没有转发键盘事件；后续接入输入时在 `CubeRig` 增加按键转发。
