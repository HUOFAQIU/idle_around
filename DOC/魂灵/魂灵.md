# 魂灵

> 类型：设计 | 状态：部分实现 | 整理：2026-11-03
> 何时读：确认四部位定位（头充能、身防御、手伤害、腿加速）、魂灵类型与见闻标签
> 关键词：魂灵 部位 头部 身体 手部 腿部 装备 类型 types 标签 tags 尺寸 Soul.types.Property Soul.tags.Small Soul.tags.Medium Soul.tags.Large
> 代码：`Windows/Inventory/grid_base_inventory_system/core/model/item/soul_data.gd`、`Windows/Equipment/`
> 相关：`魂灵/主动魂灵.md`、`魂灵/被动魂灵.md`

魂灵是能装备的，装备在魂灵窗口。

魂灵是分部位的，角色身上目前有 4 个部位，各有自身的功能趋向
1、头，充能
2、身，防御
3、手，伤害
4、腿，加速


# 规范描述
主动魂灵都拥有冷却，冷却结束会释放技能，技能拥有至少一个效果。主动魂灵也会有触发效果。
（实现状态：`SoulData.triggers` 主动/被动魂灵通用；属性型 `passive_effects` 仍只有 PassiveSoulData 支持。）
被动魂灵拥有被动效果或者是至多 6 条属性，这两者不会同时存在。

# 类型
每个魂灵都有类型（`SoulData.types`，`StringName` 数组），用于让特定效果只在这些魂灵上触发。
类型不做层级分类，直接用 `Soul.types` 前缀。

例如，冰车`Soul.types.Property`，其他类似也一样


# 标签
每个魂灵都有标签，用于作为见闻窗口的筛选功能，能筛选相应标签的魂灵，快速检索。
直接用 `Soul.tags` 前缀。

能够造成伤害的具有`Soul.tags.Damage`，`Soul.tags.DamageReference`
能够造成灼烧的具有`Soul.tags.Burn`，`Soul.tags.BurnReference`
等等
其他类似也一样

当前实现的效果标签：`Soul.tags.Damage` / `Soul.tags.DamageReference`、`Soul.tags.Burn`、`Soul.tags.Poison`、`Soul.tags.Freeze`、`Soul.tags.Heal`、`Soul.tags.Regen`、`Soul.tags.Shield`、`Soul.tags.Haste`、`Soul.tags.Slow`、`Soul.tags.Charge`。Reference 表示与对应效果相关但不直接产生该效果。


## 尺寸

按占格宽度判定，所有魂灵都带且只带一个尺寸标签：

`Soul.tags.Small`
`Soul.tags.Medium`
`Soul.tags.Large`

当前卡面按尺寸统一使用 `Assets/soul_small.png`、`soul_medium.png`、`soul_large.png`；魂灵名称由 `ItemView` 的 `SoulNameLabel` 叠在卡面上，背包、装备槽、拖拽幽灵三处一致。


## Tooltip

鼠标悬停在魂灵卡面上时显示；标题（魂灵名）用大字号，正文由 `Windows/Tooltip/soul_tooltip.gd` 的 `SoulTooltip.build()` 统一生成：

```
攻击距离，<技能 TargetRule.max_range；非 TargetRule 为 0>
暴击率，<crit_chance × 100> %
-----
[ <cooldown_seconds> ]
- <SkillDefinition.tooltip_lines 每条>
-----
<PassiveTrigger.tooltip_text>
-----
...
```

- 技能段来自 `SkillDefinition.tooltip_lines`，触发段来自 `PassiveTrigger.tooltip_text`，按 `SoulData.triggers` 顺序输出。
- 没有技能段和触发段文案的魂灵只显示头部 + `无`。
- 分隔线固定 `-----`，标点为中文全角，数字去掉小数尾零；新增魂灵只填数据，不改 UI 代码。
- 温泉是第一个配置完整正文的魂灵：技能文案在 `wen_quan_skill.tres`，两条触发文案在 `wen_quan_trigger.tres` / `wen_quan_freeze_trigger.tres`。
