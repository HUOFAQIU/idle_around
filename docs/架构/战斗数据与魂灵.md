## 1. `SkillDefinition` 与步骤执行

`SkillDefinition`（`game/content/skill_definition.gd`）= 共享配置 + 有序 `steps` 数组（`UnitSkillStep` / `SoulSkillStep`），字段以脚本 `@export` 为准。

- **执行流**：`AutoCastAbility._release_once()` 创建 `SkillCastContext`，按序分派 `_run_step()`（`SkillStep` 仅作类型标记，运行时状态存 `context.blackboard`，禁写共享资源）。任一 step 命中即算命中，全空才记空放；含魂灵步骤总是播报空放，纯单位技能仅播报我方。投射物落地回调绑定发起 step。
- **校验与显示名**：`ModLoader` 强制校验 step 类型、目标规则域与必填字段（`steps` 与 `self_effects` 不可同空）；显示名取魂灵 `ItemData.item_name`（空则回退 `SkillDefinition.id`）。`hit_cue_tag` 按 step 自身命中次数交替方向（右→左 / 左→右），击杀时改挂战场单位层防随单位销毁。

## 2. 目标规则（`TargetRule` / `SoulTargetRule`）

两者均继承 `TargetRuleBase`（消费端按 `domain()` 分派：`UNIT` / `SOUL`，`max_range_cells()` 供 tooltip 读取）。

- **`TargetRule`**：`resolve()` 返回批次数组 `Array[Array[BattleUnit]]`；`RANDOM / LOWEST_HP_PERCENT / ALL / NEAREST` 返回 1 批次，`REPEAT` 返回 `count` 批次以保证独立暴击/飘字/日志（绕开框架 `get_target_nodes()` 去重）。筛选以 `is_dead` 为准，`NEAREST` 取 1 时单次扫描不排序。
- **`SoulTargetRule`**：候选为 `caster.unit_soul_abilities` 中 `cooldown > 0` 的主动魂灵（玩家来自角色魂器网格，怪物来自 `MonsterData.soul_entries`）。`LEFT / RIGHT / BOTH_SIDES` 走统一函数 `SoulTargetRule.is_adjacent(a, b)`，仅限同一 `soul_container` 且按 `SoulSlot` 列区间紧邻判定（前提为 2 行魂器）；无目标则空放照常扣冷却。

## 3. 魂灵触发器事件注册表（唯一权威节）

`SoulData.triggers` 配 `PassiveTrigger`，主/被动魂灵通用。`SoulLoadout` 为每条生成 `SoulTriggerAbility` 挂到 ASC（不进 `BattleBrain.abilities`），仅由 `ASC.send_gameplay_event()` 按 `trigger_event_tag` 唤醒（仅当 ASC 存在对应监听者时才发事件，payload 至少含 `target` 与 `trace`）：

- `Event.Movement.UnitMoved`：`BattleUnit.on_enemy_moved()` 仅对敌方移动发送，仅派发给已注册到 `BattleManager` 的监听单位。
- `Event.Health.BelowPercent`：`attribute_changed` 生命下降时发送（含旧值/新值/比例），按 `threshold_ratio` 严格小于判定，`once_per_battle` 控制单场一次。
- `Event.Combat.SoulUsed`：另一魂灵技能激活（含空放）时由 `AutoCastAbility._notify_soul_used()` 发送；排除来源自己，校验 `required_soul_types` 与 `require_adjacent`。命中按 `charge_source_seconds` 充能，满后走 `BattleBrain.request_activation()` 帧末释放（受 20 刻激活锁限制）。
- `Event.Combat.FreezeApplied`：任意单位被冻结时向敌对监听者发送（`BattleManager` 维护监听者表，不扫全场）；每冻住一个目标触发一次，重复冻结也算。
- `Event.Combat.SlowApplied`：魂灵级减速（`ChargedAbility.apply_slow()`）施加时向敌对监听者发送（单位级 `State.Sluggish` 不发此事件）。

**通用字段**：`target_scope` 支持事件目标/自己/全体敌人；`max_range`（0=不限）过滤距离；数值经 SetByCaller `Data.TriggerMagnitude` 传递；被动魂灵忽略 `charge_source_seconds`；`trigger_name` 非空才写触发日志。

## 4. 执行器、持续效果资源与被动挂载

- **执行器映射**：直接伤害 `SoulDamageExecution`、伤害+剧毒 `PoisonDamageExecution`、护盾 `ShieldExecution`、施加异常 `StatusApplyExecution`、治疗 `HealExecution`；暴击倍率与标签统一走 `game/battle/crit_resolution.gd`。周期状态继承 `PeriodicStatusTickExecution`（`BurnTickExecution` / `NetStatusTickExecution`），新增周期状态只需继承基类不改 `BattleUnit`/`CombatNarrator`。
- **效果资源约定（不填 `resource_name`）**：
  - 冷却不再使用 `GameplayEffect`，`SkillDefinition.cooldown_seconds` 为唯一时长来源。
  - `burn_apply / poison_apply / regen_apply.tres` 为 `INSTANT`，数值优先级 `Data.SkillMagnitude > Data.TriggerMagnitude > base_amount` 后乘暴击；`*_tick.tres` 为 `INFINITE`（`max_stacks=1`）；`freeze_unit.tres`（1s `State.Frozen`）、`swift_unit / sluggish_unit.tres`（`move_speed ±50%`）；`trigger_damage_50.tres` 固定 50 吃 `damage_bonus` 与暴击。
- **被动挂载**：`PassiveSoulData.passive_effects`（标记类 `PassiveEffect`）在血条绑定与 `_connect_asc()` 前挂到玩家 ASC，避免开场刷日志；被动魂灵不写扫描线但阻断相邻。

## 5. 掉落、见闻、地图与情绪数据流

- **掉落与见闻**：`MonsterData.soul_entries` 同时产出虚拟魂灵栏（`soul_list()`）与掉落（`drop_entries()` → `DropEntry`）；怪死时 `LootRoller.roll()` 独立掷骰入 `Warehouse.add_item()`（10 页全满记丢失）。`CollectionDB` 从 `ModLoader` 构建索引，怪物首次刷出、魂灵/魂器首次入容器时按 `content_id` 解锁（`make_instance()` 保留 `content_id`）。
- **地图目录**：当前硬编码在 `game/content/map_catalog.gd::MapCatalog`（未进 mod manifest），条目 `monster_id` 运行时由 `CollectionDB` 解析。
- **情绪实现流**：模板声明 `SoulData.emotion_ranges`，实例构成 `SoulData.emotions`（`make_instance()` 深拷贝）；掉落时 `SoulEmotionRoller.roll()` 按 `MapData.rarity` 分配，读值走 `SoulEmotionValues`（未声明回退技能模板，冷却缺项取范围左端）；`SoulDamageExecution` 经 `spec.context.soul_runtime.soul` 读实例值不改共享技能；`SaveCodec` 仅在构成非空时持久化 `emotions`。
