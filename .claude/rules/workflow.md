# 改动流程

- 方案先行：功能改动（新增文件、改接口、动场景结构）先出方案、等确认再改代码；需求含糊先按 `DOC/spec/README.md`「先拷问再写」问清。
- 临时探针：用完即拆的调试代码可直接插、运行并删除，跑完报「探针已拆、git diff 干净」；期间 `addons/` 保持只读。
- 直接替换：旧代码、旧命名、旧迁移与旧文档随改动一起删除，只留一套命名（保留项见 `DOC/指南/开发约定.md` §2）。
- 同步测试与文档：新增功能/内容同步 TestAPI（域模块 + 门面转发）并更新文档头核对日期，细则见 `DOC/指南/文档规范.md`。
- 收尾顺序：`bash tools/check.sh --all` → review → spec 退出 → commit → 交接；一批改动只跑一轮全量检查，失败后再修。
