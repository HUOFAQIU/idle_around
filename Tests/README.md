# E2E 测试

按 `CLAUDE.md` 的三条来：**不写单元测试**、**以 E2E 为唯一验证手段**、**跑完留下可复核可重跑的产物**。
所以这里没有断言内部实现的测试，只有「从真实入口把游戏跑起来、像人一样操作它、把看到的截图存下来」。

## 怎么跑

```bash
"U:/Steam/steamapps/common/Godot Engine/godot.windows.opt.tools.64.exe" --path . res://Tests/e2e_warehouse.tscn
```

跑完会在 `Tests/shots/<场景名>/` 留下（**一个场景一个目录**，不然两个场景的 report.txt 会互相覆盖）：

| 文件 | 是什么 |
|---|---|
| `report.txt` | 每一步做了什么、判定结果、每张图**该长什么样** |
| `NN_名字.png` | 那一步的截图，对着上面的描述看就知道对不对 |
| `.gdignore` | 让 Godot 别把截图当资源扫（不然每张图旁边会多一个 `.import`） |

终端里也会把同样的内容打一遍，最后一行是 `失败 N 条`。

> 前提：跑的时候要有个真窗口（别用 `--headless`），因为要真渲染截图。鼠标会被脚本「借用」：它**不动你的鼠标**，
> 而是把游戏窗口挪到光标底下 —— 所以跑的时候别去碰鼠标，也别把光标挪到屏幕最边上（窗口会摆不下）。

## 现在有哪几个场景

### `e2e_warehouse.tscn` —— 仓库 / 装备窗口

| 步骤 | 在验什么 | 该看到什么 |
|---|---|---|
| 1 | 点主界面「仓库」按钮 → 窗口开 | `01`：第一页六个部位各一件 + 三颗散魂灵 |
| 2 | **落点收边**：按住锁子甲往右拖过头 | `02`：锁子甲跟着光标挂到窗口外，绿框贴在还放得下的最靠右那列 |
| 3 | **装备拖不出仓库窗口**：再拖一次，然后把窗口挪开让光标出去 | `03`：锁子甲还在最右边那列（这次拖动作废了），没被带走 |
| 4 | **右键换装 + 右键卸装**：右键仓库里的弓（换上）→ 右键装备槽（卸下） | `04` 仓库里少一件；`05` 武器槽里有弓；`06` 武器槽空了；`07` 仓库左上角冒出红色的「临」 |
| 5 | **拖魂灵不留残影**：拖一颗魂灵到空行上（放不下）松手 | `08` 拖动中那行浮着魂灵；`09` 松手后跟没拖过**逐像素一样** |
| 6 | **hover 提示框**：悬停锁子甲 / 悬停一颗魂灵 / 悬停空格子 | `10` 装备弹**装备那个**：名字 + 一整片魂灵区；`11` 魂灵弹**魂灵那个**：名字 + 冷却 + 技能说明（照 `soul_tooltip.tscn` 的版面）；`12` 移到空处两个都收起来 |
| 7 | **悬停高亮该被东西挡住**：悬停魂灵 vs 悬停空格子 | `13` 魂灵那块跟没悬停时**逐像素一样**（白框压在它底下）；`14` 空格子上白框照旧看得见 |

> 步骤 6 有个前提要知道：提示框本来是**鼠标移动事件**驱动 `InventoryGrid._update_hover()` 弹出来的，
> 而这个测试台造不出能送进子窗口的移动事件（按下 / 松开能送进去，移动送进去没人收——`push_input`、
> `Input.parse_input_event()`、根 Viewport 都试过）。
> 所以这一步直接调 `_update_hover()`，走的还是真实那条路（找物品 → 按类型挑提示框 → 填内容 → 摆位），
> 只是触发的人从鼠标换成了测试。**「指针悬停」这个交互本身没被覆盖**，验的是提示框的内容和显隐。
> （真光标的悬停走 `e2e_hover.tscn`，那条是补这个盲区的。）

> 步骤 7 比像素前会先 `_hide_tips()` 把提示框请走：提示框每帧在 `_process` 里**跟着真光标**走
> （`tip.place_near(get_local_mouse_position(), ...)`），而这条场景没在动真光标，它会停在别处，
> 混进比较里就分不清哪块是高亮画的了。只藏框，`_hover_cell` 不动，高亮照样画。

判定只看用户看得见的东西：东西落在哪一格、窗口开没开、临时页按钮出没出现、截图对不对得上。
（测试里读 `grid.pages` 只是为了**找到要操作的那件东西**，不是拿内部状态当断言。）

### `e2e_windows.tscn` —— 窗口打开在哪儿

| 步骤 | 在验什么 | 该看到什么 |
|---|---|---|
| 1 | 点「人物」按钮 | `01`：窗口开在 **(1310, 160)**、尺寸还是 300×300（空壳窗口截图本来就一片灰，看坐标断言） |
| 2 | 再点两次（收起 / 再开） | 收得起来，再开还在 (1310, 160) |
| 3 | 点「仓库」、点「装备」（都配了 `open_position`） | `02` 仓库开在 (1683, 291)；`03` 装备开在 (1266, 150) —— 配了就用配的，不是居中 |
| 4 | 居中兜底：临时把仓库的 `open_position` 清成 (-1, -1) 再点开 | `04`：同一扇窗口回到屏幕正中 |

> 步骤 4 有个前提要知道：四个窗口现在**都**配了 `open_position`，没有「没配」的真窗口可测了。
> 所以这一步把仓库那个字段临时清掉再开——点的是真按钮，走的是真 `popup_window()` → `open_window()`，
> 只有那个字段换了个值，验的是「没配就居中」这条兜底分支还在。验完把值还原。
> 容差给 40 像素：Godot 居中算的是**带标题栏的整窗**，客户区自然低二十来像素（实测差 23.5），属正常。

### `e2e_hover.tscn` —— 真实的鼠标悬停

> ⚠️ 这条场景跟别的不一样：**它会真的动你的鼠标**（`DisplayServer.warp_mouse`），跑的时候别碰鼠标。

| 步骤 | 在验什么 | 该看到什么 |
|---|---|---|
| 1 | 点「仓库」 | 窗口打开 |
| 2 | 真光标停到一颗散魂灵上 | `01`：弹**魂灵**提示框（名字 + 冷却 + 技能说明），装备那个不许跟着浮出来 |
| 3 | 真光标移到一件装备上 | `02`：换成**装备**提示框（名字 + 整片魂灵区），魂灵那个收起来 |
| 4 | 真光标移到空白处 | 两个都收起来 |
| 5 | 右键把锁子甲换上，真光标移到它身上那颗魂灵上 | `03`：装备窗口里弹的也是**魂灵**提示框 |

**为什么单开这一条**：`e2e_warehouse` 里 hover 是**直接调 `_update_hover()`** 触发的
（当时以为测试台送不进能被子窗口收到的移动事件），所以「指针真的移上去」这一环一直没覆盖。
这里用真光标走真实那条路进 `_gui_input`。

两个坑，改这条场景时别踩：
1. **挪窗口不产生移动事件**。测试台别处一直是「不动鼠标、把窗口挪到光标底下」，但那样 hover 起不来
   （实测挪完 `_hover_cell` 还是 `(-1,-1)`）—— 挪窗口不算「鼠标动了」，操作系统不送 `WM_MOUSEMOVE`。所以这里得真 warp。
2. **`warp_mouse()` 收的是「相对当前聚焦窗口」的坐标，不是屏幕坐标**，而且 `grab_focus()` 是异步的。
   不等焦点稳住就 warp，光标会飘到别的窗口上（表现为偶发失败）。所以要 `grab_focus()` → 等几帧 → 再 warp。
3. **移动事件是分几帧陆续到的**，等 3 帧时会出现「上一步的坐标才刚送到」，看着像提示框不跟着走 —— 那是等太短，不是 bug。现在等 8 帧。

## 测试台怎么控制鼠标（`e2e_kit.gd`）

Godot 里没法凭空点别的窗口上的按钮，试出来的路子是这三条：

1. **定光标位置 —— 不动鼠标，挪窗口**：`put_cursor_at(win, 窗口内坐标)` 把窗口摆到光标底下。
   App 眼里的「光标在窗口里哪儿」就跟真人操作一模一样。
2. **按下 / 松开**：全局按键状态用 `Input.parse_input_event()` 注入（**要等一帧才生效**，不等的话
   `_process` 会在同一帧把它当成「已松手」），事件本身用 `Window.push_input()` 投递给那个窗口（控件才收得到）。
3. **拖动中移动 —— 还是挪窗口**：窗口往左挪一格，光标在窗口里的位置就右移一格。

### 踩过的坑（改测试时注意）

- **别拖太远**：拖动中「挪窗口」等于让光标在窗口里移动，挪过头就把光标**推出了窗口** ——
  装备一出窗口就被判作废（那是对的行为），测试会莫名其妙地失败。步骤 2 拖 17 格就是这个原因：
  刚好越过收边阈值，光标还在窗口里。
- **截图前要定住冷却线**：魂灵的冷却线每帧都在动，做逐像素比较前得把每一行的 `cooldown_seconds` 设大（等于不推进）、魂灵的 `cd_progress` 归零。
  魂灵自己不带时长——节奏是装备面板上的一个固定值（`SlotCell.cooldown_seconds`）。
- **坐标有两套**：格子坐标是 `grid` 局部的，光标要的是**窗口**坐标，中间差着边距 + 分页栏，
  用 `_grid_point()` 换算。
- 右键只要「按下」就能触发（不用等松开），但投递松开也无害。
- **写了逐像素断言，就把 bug 放回去跑一遍**：一条不会失败的断言等于没写。步骤 7 就是这么验的——
  第一次写出来的版本，把 bug 放回去照样「通过」（比错了区域 / 提示框混进来了），改对之后才 FAIL。
  具体做法：临时把改动还原（往往是**两处**，比如「画在哪儿」和「什么时候重画」要一起还原），
  跑一遍确认 FAIL，再把改动放回来跑一遍确认 0 失败。

## 加新步骤

在 `Tests/e2e_warehouse.gd` 里加一个 `_step_xxx()`，在 `_ready()` 里按顺序 `await` 它，
用 `kit.note()` 说清这一步在验什么、`kit.shot(win, "NN_名字", "这张图该看到什么")` 留证据、
`kit.check(...)` 判可见的结果。跑完 `kit.finish("标题")` 会写报告。

场景名在建 kit 时就定了：`var kit := E2EKit.new("windows")` —— 产物就落在 `Tests/shots/windows/`。

场景复杂到要拆文件时，复制 `e2e_warehouse.tscn` 改个名即可（root 是 Control，`_ready()` 里
`load("res://control.tscn")` 起真实主场景）。
