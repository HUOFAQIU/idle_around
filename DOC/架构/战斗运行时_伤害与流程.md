## 1. 伤害、异常、开战与死亡

### 1.1 暴击、伤害、护盾与异常状态

- `SkillDefinition.crit_chance`（默认 0）与 `crit_multiplier`（默认 1.5）。
- `PlayerStatsAttributeSet.damage_bonus`（默认 0）是己方魂灵的固定伤害加成；被动魂灵可以增加这个属性。
- 每份直接伤害效果挂一个 `SoulDamageExecution`：
  - `base_damage` 写在 execution 资源里；
  - `execute()` 从施法者 ASC 读 `damage_bonus`，从 spec 读 `Data.CritMultiplier`；
  - 最终 `damage = (base_damage + damage_bonus) × crit_multiplier`；
  - 结果交给 `DamageResolver.split_damage(target, damage, 1.0)`，在入口向下取整后先扣护盾再扣生命。
- 护盾获得效果挂 `ShieldExecution`：`floor(base_shield × 暴击倍率)`，不吃 `damage_bonus`。
- 伤害 + 剧毒效果挂 `PoisonDamageExecution`：先按 `SoulDamageExecution` 得到最终伤害，再按 `poison_ratio`（默认 1）换算成整数剧毒写入目标的 `poison`；换算结果不足 1 点时保底 1 点。
- 单独施加灼烧/剧毒/生命再生挂 `StatusApplyExecution`：支持触发器传入数值，也支持主动技能按释放时暴击倍率放大，结果向下取整。
- 治疗挂 `HealExecution`：治疗量 = `floor(base_heal × 暴击倍率)`；净化量 = `floor(治疗量 × 5%)`，从治疗目标的 `burn` / `poison` 中分别扣除。生命再生不是治疗，不会触发净化。
- **数值落地口径**：计算过程允许小数（暴击倍率、比例、冷却、位置等），但写入属性的伤害/治疗/护盾/状态数值统一向下取整；飘字和日志读到的也是取整后的整数。伤害在 `DamageResolver` 入口取整；治疗、护盾、状态施加、剧毒/生命再生每跳各自 `floorf`；两个属性集的 `pre_attribute_change()` 再做一次兜底。不要只在属性层取整，否则 7.5 伤害会变成扣 8 点。
- `AutoCastAbility` 对每个目标独立掷一次暴击，把倍率写进 spec 的 `Data.CritMultiplier`；不暴击时写 1.0。
- 暴击时 execution 会 `inject_tag(GameplayTags.Event_Combat_Critical)`；`BattleUnit` 用它给日志加暴击样式，`UnitPresenter` 用它给飘字加暴击样式。
- **异常状态的暴击只在释放时判定**：施加时把暴击后的数值写进状态；之后灼烧/剧毒/生命再生的每跳都不再暴击。
- 治疗、灼烧、剧毒、生命再生周期本身不挂直接伤害 execution；灼烧/剧毒/生命再生各自走 `BurnTickExecution` / `PoisonTickExecution` / `RegenTickExecution`。
- 剧毒与生命再生直接相减：每跳只由数值大的一方生效，按差值 × 每点数值向下取整后结算；属性原值、状态标签和状态条都保留，和加速/减速同时存在时相互抵消的表现一致。相等时两边都不结算。
- 灼烧层数归零后，`BattleUnit` 在 `periodic_effect_ticked` 里移除 `burn_tick`；`State.Burning` 和持久火焰 Cue（`Cue.Status.Burn`）一起结束。
- 剧毒被治疗净化到 0 后，`BattleUnit` 同样在 `periodic_effect_ticked` 里移除 `poison_tick`；`State.Poisoned` 和中毒气泡 Cue（`Cue.Status.Poison`）一起结束。施加剧毒时 `poison_tick` 先播一次飞溅 Cue（`Cue.Combat.PoisonApply`）。
- 伤害分流规则：
  - 普通伤害：1 点护盾吸收 1 点伤害，护盾不够的部分进生命；
  - 灼烧：总伤害在 `DamageResolver` 入口向下取整，对护盾伤害再减半并向下取整，破盾后剩余伤害按“1 护盾抵 2 灼烧”进生命；
  - 剧毒：每秒先与生命再生按整数相减，剧毒更多时按差值向下取整后直接扣生命，无视护盾，不衰减；
  - 生命再生：每秒先与剧毒按整数相减，生命再生更多时按差值向下取整后恢复生命，不衰减，溢出部分由生命上限丢弃。
- 普通伤害/治疗叙事走 `ASC.effect_received`；周期伤害/生命再生每跳走 `periodic_effect_ticked`；`attribute_changed` 只负责血条和死亡判断。`CombatNarrator` 订阅同两个信号写日志，`UnitPresenter` 订阅它们生成飘字。
- 致命一击的伤害飘字与命中 Cue 一样改挂战场单位层（`UnitPresenter` 传给 `DamageNumber.setup()` 的 `anchor`），避免目标帧末释放时数字一起消失；非致命伤害仍挂在单位下。
- 周期效果可能比施加者活得久（怪物死了，毒还在玩家身上）；`BattleUnit._source_name()` 和 `SoulDamageExecution._source_asc()` 取 `context.instigator/causer` 前先 `is_instance_valid()`，来源已释放时日志显示“未知来源”。

### 1.2 冻结语义

- `State.Frozen` 已注册到标签表，`ChargedAbility.FROZEN_TAG` 直接引用 `GameplayTags.State_Frozen`（`BattleBrain.FROZEN_TAG` 是别名）。
- 魂灵级冻结：`ChargedAbility.freeze_units` 计时，`is_frozen()` 在自身计时 > 0 时为真；只停这一颗魂灵的充能和释放。仙子用。
- 单位级冻结：`base_mods/core/effects/freeze_unit.tres`，`policy = DURATION`、3 秒、`granted_tags = [State.Frozen]`、`persistent_cue_tags = [Cue.Status.Freeze]`；整个单位不充能、不释放、不移动。需要冻结全场时用。
- 两种冻结期间：
  - 自身不累加自然充能；
  - 不能释放技能；
  - 外部仍然可以直接调用 `add_charge()` 充能（外部充能技能走的就是这个接口）；
  - 加速/减速/冻结自身的计时照常减少。
- 解冻后如果充能已满且 20 刻激活锁已走完，主循环会立刻释放；锁未走完则等它走完。
- 冻结不中断已经在飞的投射物或已经进入吟唱的技能，只停之后的自然充能和释放。
- 单位冻结效果没有属性修改，日志/调试显示名由 `CombatNames.effect_name()` 统一解析（优先 execution 元数据，其次 `State.Frozen`，最后回退 `display_name`），显示为“冻结”；结束由 GAS 移除效果、摘标签并回收持久 Cue。

### 1.3 玩家与怪物场景

两个场景的根都是 `BattleUnit`，走同一条 `setup_from_scene()` 初始化管线。
`setup_from_scene()` 的第二个参数是可选 `passive_effects`，只有玩家会传：属性效果在血条绑定前挂到 ASC。魂灵触发器不再走这个参数，而是由 `SoulLoadout` 从 `SoulData.triggers` 统一登记；玩家和怪物共用。

**`game/content/Player/player.tscn`**

```
Player (BattleUnit, CharacterBody2D)  team = PLAYER(0)；unit_name/max_health 由 BattleSession 从 PlayerProfile 注入（“小煤灯”，500）
├─ AbilitySystemComponent    attribute_sets = [PlayerStatsAttributeSet]
├─ BattleBrain
├─ CollisionShape2D          CircleShape2D 半径 14
└─ Body (Sprite2D)           tokens.png 区域 (32,0,32,32)，绿色
```

- 没有 `HealthBar` 子节点：角色血条显示在 `BattleWindow` 左下角的 `PlayerHealthBar`。
- 没有预挂技能：技能全部来自魂器里的魂灵。
- `PlayerStatsAttributeSet` 还有 `damage_bonus`（默认 0），供被动魂灵增加己方魂灵伤害。

**`base_mods/core/monsters/snake/`**

怪物数据已经拆成“数据 + 场景”两层：

- `snake_monster.tres`（`MonsterData`）：`display_name`、`icon`（图鉴图标 + 战斗贴图）、`max_health`、`attack_range`、`move_speed`、`soul_entries`（魂灵 + 各自掉落几率）、`battle_scene`；
- `snake.tscn`：只保留碰撞体和节点结构；名字、数值、贴图都不再写进场景。

```
Snake (BattleUnit, CharacterBody2D)  team = ENEMY(1)
├─ AbilitySystemComponent    attribute_sets = [MonsterStatsAttributeSet]
├─ BattleBrain
├─ CollisionShape2D          CapsuleShape2D 半径 8
├─ Body (Sprite2D)           贴图由 MonsterData.icon 注入
├─ HealthBar (UnitHealthBar) 位置 (0,20)
└─ Name (Label)              头顶名字，偏移 -32,-34 ~ 32,-18
```

- `BattleSession._spawn_enemy()` 从 `CollectionDB.pick_random_monster()`（`spawn_weight > 0` 且 `is_rare = false` 的常规池）或排队中的稀有怪取数据，实例化 `battle_scene` 后把 `unit_name / max_health / attack_range / move_speed`、`monster.soul_list()`、`monster.drop_entries()` 注入 `BattleUnit`，并用 `monster.icon` 设置 `Body.texture`，再 `setup_from_scene()`；
- 魂灵通过 `SoulLoadout` 生成 `AutoCastAbility`，怪物因此获得对应技能；
- 怪物没有真实的魂灵容器：`SoulSlot.virtual_slots()` 按配置顺序生成一行虚拟魂灵栏，`SoulTargetRule` 因此对怪物也能选魂灵；配了哪些魂灵就排哪些；
- 移动不再由场景里的能力节点负责：`BattleManager._physics_process()` 统一驱动怪物朝角色直线移动，碰撞体负责互相阻挡；进入 `attack_range` 后停下并开启 `BattleBrain`，怪物的魂灵这时才开始冷却。
- 掉落物也可以是魂灵；掉进仓库任意空位后，玩家可以把魂灵拖进魂器，再把战斗魂器装进角色魂器网格。

### 1.4 开战、关窗、死亡

战斗生命周期由 `BattleSession` 负责，`BattleWindow` 只处理 UI 与魂灵槽位读取。

**开战（▶）**

`BattleWindow._start_battle()` 清空 `InfoWindow` 日志，把魂灵槽位交给 `BattleSession.start()`：

1. `BattleSession.stop()`：清掉上一场所有单位、`BattleManager`、扫描线状态，并 `run_id += 1`（作废还没执行的重开等待）；
2. 创建 `BattleManager`，接上地图、刷怪回调与掉落入包动作；把遥测/战斗信息窗/控制台三个观察者挂到 `BattleManager.events`（必须在生成单位之前）；
3. 从角色窗口的 `vessel_cells` 魂器网格读战斗魂器（魂器按占格从上到下、从左到右排序），再读每个魂器的内部容器，收集 `SoulSlot`（由 `BattleWindow._equipped_souls()` 读取）；实例化 Player 场景，`setup_from_scene()`，放到中心格 `(0,0)`；`player_spawned` 信号让窗口绑血条；
4. `CombatTelemetry.begin_run()` / `watch_unit()`；
5. `start_battle()`：所有单位充能从 0 开始；
6. 立刻 `spawn_one()` 刷第一只，避免空场等待；
7. `battle_started` 信号让窗口打开扫描线、按钮文字改成“重开”。

**关窗**

- 标题栏 ×、主界面按钮再次点击，最终都是 `hide()`；
- `visibility_changed` → `_end_battle()` → `BattleSession.stop()`：`run_id += 1`、清场，`battle_ended` 让窗口关扫描线、按钮恢复 `▷`；
- 下次打开窗口就是这一关的初始状态。

**角色死亡**

- `BattleUnit._die()` 加 `State.Dead`、发 `died`；
- `BattleManager._on_unit_died()`：如果是玩家，`is_running = false`（停止刷怪）；如果是怪，`LootRoller.roll()`、从名册移除、释放节点；
- `BattleSession._on_enemy_died()`：常规怪死亡计数，每满 10 只排队一只稀有怪，下一拍刷怪时替换刷出；`is_rare = true` 或 `spawn_weight = 0` 的怪死亡不计数；
- `BattleSession._on_player_died()`：日志提示，等 `REVIVE_DELAY = 3` 秒；关窗/重开会改变 `run_id`，这次等待作废；否则用同一批槽位整场重开。
