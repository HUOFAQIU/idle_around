# 调试窗口 DebugWindow

> 类型：指南 | 状态：有效 | 核对：2026-11-27
> 何时读：想知道战斗里发生了什么、某颗魂灵为什么没放、触发器/状态/充能怎么走
> 关键词：调试窗口 DebugWindow 时间线 因果链 魂灵 触发器 状态 导出
> 代码：`windows/Debug/debug_window.gd`、`windows/Debug/soul_status_row.gd`、`scripts/debug/`
> 相关：`架构/调试与遥测.md`、`指南/AI测试接口.md`

## 打开

主界面 3 列功能区的第 6 个按钮（显示“调试”）。窗口默认隐藏，不抢焦点；关闭窗口不会暂停战斗。

## 工具栏

| 控件 | 作用 |
|---|---|
| 录制 | 总开关；关闭后 `CombatTelemetry.record()` 立即返回 |
| 写文件 | 同时写 `user://debug/combat_*.jsonl` |
| 暂停 | 暂停界面刷新（事件仍继续记录；点“继续”恢复） |
| 清空 | 清空事件缓冲和所有面板 |
| 导出 | 把当前缓冲导出为 JSONL，状态栏显示绝对路径 |
| 重要+详细 / 仅重要 / 仅详细 | 时间线过滤 |
| 本场 | 只显示当前 `run_id` 的事件；关闭后保留历史场次 |
| 跟随 | 打开时时间线/日志滚到最新；手动滚动或点选历史事件会自动关闭；再打开会跳回最新 |
| 搜索 | 按单位名、魂灵、效果、事件类型、detail 过滤 |

## 页签

### 总览

- 战斗时间、敌人数、玩家 HP、事件数/丢失数、FPS；
- 当前装备魂灵一行一颗：魂器名、冷却条、充能秒数、加速/减速/冻结、激活/触发/收充能；
- 最近 12 条重要事件。

### 时间线

- 列：时间、类别、事件、来源、目标、详情；
- 打开“跟随”时自动滚到最新；用滚轮向上翻或点选任意历史行会自动停止跟随，时间线不再追加/滚动；点回“跟随”恢复并跳回最新；
- 点击一行，下方显示完整字段和**因果链**；
- 因果链按同一 root trace 列出：一次施法 → 效果 → 周期 tick / 触发器 → 充能 → 再次施法；
- 颜色来自事件本身的 `color`，日志和结构化事件可以对照看。

### 魂灵

- 当前玩家装备的每颗魂灵：魂器、槽位、冷却、充能百分比、状态、激活/触发次数；
- 选中后显示运行期详情：冷却/充能、加速/减速/冻结、激活锁、本场贡献（伤害/治疗/护盾/灼烧/剧毒/生命再生）、统计、触发器列表。

### 单位

- 玩家 + 最近 100 个敌人：HP、护盾、灼烧、剧毒、生命再生、标签数、状态、距离；
- 选中单位后显示完整属性、标签、ActiveEffect（含来源/层数/剩余/Cue 标签）、能力（充能/激活）、魂灵；
- “关注选中单位”会把详细事件切到该单位；玩家默认被关注；
- 关注单位的行名字显示为绿色。

### 触发器

- 当前选中单位（没有选中时用玩家）的触发器绑定：
  - 来源魂灵、事件、范围、条件、是否已触发、触发充能；
- 选中后显示原始字段，包括 `event_tag`、触发器能力 `ability_tag`、`run_count`。

### GAS

- 玩家当前标签；
- 已注册 Cue 标签（`GameplayCueManager._cue_scenes`）；
- 最近激活失败（`ability_activation_failed`）；
- 最近的 GAS GameplayEvent（`Event.Movement.*` / `Event.Health.*` / `Event.Combat.*`）。

### 日志

- `CombatNarrator` 生成、经 `BattleManager.log_line` 发出的中文日志镜像，支持搜索（用工具栏搜索框过滤时间线，不改变日志文本；输入有 200ms 防抖）；
- 节流：敌方施法/步骤日志只在关注该怪或开“记录所有详细事件”时播报；玩家受击日志间隔 ≥150ms，场上敌人超过 16 只时不再逐只播报死亡；
- 与时间线共用“跟随”开关：关闭后日志不再追加/滚到最新，方便回看历史；重新打开会从缓冲重建最新日志。

### 设置

- 事件缓冲上限（100～50000）；
- “记录所有详细事件”：打开后敌人属性/周期 tick 也全部进缓冲，调试单场时用，长时间挂机不要开；
- “见闻全部解锁”：测试用，只影响显示、不写存档；已打开的见闻窗口需要切页签/重开才刷新；
- 当前关注单位、录制文件路径。

## 常见排查

1. **魂灵不放技能**
   - 魂灵页看冷却/充能是否满；
   - 看“冻结/激活锁/施法中”；
   - 单位页看该魂灵所在单位是否在攻击范围内（敌人只有进范围才充能）；
   - 时间线看 `被拒绝`（激活锁）或 `队列拒绝`（ASC 门卫）。
2. **触发器不触发**
   - 触发器页看 `fired`、条件（半血阈值/每场一次/相邻/标签）；
   - 时间线过滤“触发器”，看事件是否到达、目标数是多少；
   - `Event.Combat.SoulUsed` 排除来源自己；`Event.Combat.FreezeApplied` 按“每冻住一个目标”触发，`Event.Combat.SlowApplied` 由魂灵级减速触发，两者都受 `max_range` 限制。
3. **状态没显示/没伤害**
   - 单位页看 ActiveEffect 是否有对应效果、层数、剩余时间、来源；
   - 看 `周期结算` 事件里的 `health_delta / burn_delta`；
   - 灼烧/剧毒/生命再生是属性 + 周期效果，不是 Cue；Cue 只负责表现。
4. **Cue 没播**
   - GAS 页看标签是否在已注册 Cue 列表；
   - 单位页看效果是否挂了对应的 `persistent_cues / application_cues`；
   - 注意 `GameplayCueManager` 对未注册标签是静默返回。
5. **性能变差**
   - 关闭“记录所有详细事件”；
   - 只关注玩家或单只敌人；
   - 降低事件缓冲上限或关闭录制；
   - 关闭调试窗口后不轮询快照；
   - 战斗中打开战斗信息窗卡：正文是 `TerminalView`；如果仍卡，检查 `InfoWindow` 是否在每次追加时错误地重建全部日志，或终端是否需要脏行重绘。

## 导出

“导出”会写：

- 一行 meta：场次、事件数、丢失数、缓冲上限；
- 每行一个事件 JSON。

路径默认 `user://debug/combat_<时间>_run<场次>.jsonl`；Windows 下可用 `%APPDATA%\Godot\app_userdata\idle_around\debug\` 打开。

## 限制

- 触发器已走 GAS GameplayEvent；GAS 页为空时，先确认 ASC 上有没有对应 `trigger_event_tag` 的 `SoulTriggerAbility`，以及事件产生处有没有发送条件。
- 敌人只显示最近 100 个，避免无限刷怪把 Tree 撑爆；需要看更远的敌人时用搜索/关注/快照接口。
- 事件缓冲是内存环形缓冲；长时间挂机只保留最近 `max_events` 条。
