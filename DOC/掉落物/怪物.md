# 掉落

每个怪物都有自身的掉落池，可以在检查器里配置。
以蛇为例，`yao.tres`是可以掉落的，我可以设置掉落几率。
击败怪物可以掉落，掉落直接进仓库窗口。

```
需要确认的问题

  1. yao.tres 不能直接当掉落物

  yao.tres 是 SkillDefinition（蛇的“咬”技能数据），不是 ItemData。仓库系统只接受 ItemData 的子类，GBIS.add_item() 的参数类型就是 ItemData，所以现在的 yao.tres 放不进仓库。

  需要明确是哪种：

  - 掉一件普通物品：新建一个 ItemData 资源（比如“蛇牙”），配置图标、占格、名称；
  - 掉落的是“技能载体”：那就需要一个类似 SoulData 的物品类，持有 skill: SkillDefinition，装到魂灵格或使用后生效。

  2. 掉落池配在哪一层

  两种都符合“自身掉落池”：

  - 直接放在怪物场景根节点上：@export var drops: Array[DropEntry]（简单，推荐先用这个）；
  - 做成独立 DropTable 资源，场景里引用（多只怪共享同一张表时更方便）。

  3. 多条掉落的结算方式

  - 每条独立掷骰（可能同时掉多件）——按文档“每条设置几率”，我理解是这个；
  - 还是权重池里只抽一件？

  4. 仓库满了怎么办

  GBIS.add_item() 返回 false。掉落失败时：

  - 直接丢失 + 战斗日志提示（推荐先这样）；
  - 还是保留到下次、或掉在地上？

  5. 数量

  一条掉落是固定 1 个，还是需要 min_count ~ max_count？StackableData 已经支持自动堆叠，add_item 内部会 duplicate()，所以多次掉落同一资源不会共享实例。

  建议的 v1 实现

  1. 新建 game/content/drops/drop_entry.gd：

  gdscript
  class_name DropEntry extends Resource

  @export var item: ItemData
  @export_range(0.0, 1.0, 0.01) var chance: float = 0.1

  2. BattleUnit 加 @export var drops: Array[DropEntry] = []，在 snake.tscn 检查器里配；
  3. BattleManager._on_unit_died() 里对 ENEMY 单位掷骰：

  gdscript
  for entry in unit.drops:
	  if entry.item and rng.randf() <= entry.chance:
		  if GBIS.add_item("inventory_0", entry.item):
			  log_line("%s 掉落了【%s】" % [unit.unit_name, entry.item.item_name], "#ffd866")
		  else:
			  log_line("仓库已满，【%s】掉落丢失" % entry.item.item_name, "yellow")

  4. 掉落用 battle.rng，和选目标共用一个随机源。

  确认 1–4 之后我来实现；如果你先只想跑通，也可以直接采用“独立掷骰、固定 1 个、仓库满则日志丢失”这组默认值。
```
