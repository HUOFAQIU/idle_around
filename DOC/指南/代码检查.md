## 一键命令

在项目根目录用 Git Bash：

```bash
bash tools/check.sh --file Scripts/foo.gd   # 单文件文本规则，最快
bash tools/check.sh --staged                # 暂存文件 + 全量编译检查 + 情景测试
bash tools/check.sh --all                   # 单测 + 全量文本规则 + 编译检查 + 情景测试
bash tools/check.sh --scenario battle_run   # 只跑指定情景，调试用
```

若 Godot 不在默认路径，先 `export GODOT_BIN=".../Godot_v4.7.2-stable_win64_console.exe"`。

首次使用装一次 git hook：

```bash
bash tools/install.sh
```

它把 `core.hooksPath` 指到 `tools/git-hooks/`：提交跑 `--staged`，推送跑 `--all`。Claude Code 的 `PostToolUse` hook 在每次 Edit/Write 后跑单文件规则，把错误回传给模型；硬门仍是 pre-commit 和 CI。

## 规则

Python 规则（`tools/lint/rules.py`）：

| ID | 检查 | 级别 |
|---|---|---|
| `no-comments` | 首方 `.gd` 不写注释；`@export` 的 Inspector 文档、`@meta_*` 来源标注、生成文件例外 | error |
| `resource-name-cjk` | `.gd/.tscn/.tres` 中的中文 `resource_name` | error |
| `file-access-boundary` | `FileAccess`/`DirAccess` 出 `Scripts/save/`、`Scripts/mod/`、`Scripts/debug/`、`EngineTools/modkit/` | error |
| `mod-path-root` | 裸写 `res://base_mods`、`user://mods`、`res://mods` 根路径 | error |
| `inline-color` | 表达式里内联 `Color(...)` 字面量；命名常量/声明不受影响 | error |
| `dependency-boundary` | 跨层引用只走 `tools/lint/boundaries.toml` 声明的方向；边来自 `res://`、`class_name`、autoload 名 | error |

依赖边界（`tools/lint/boundaries.py` + `boundaries.toml`）：

- 层 = 路径前缀，按最长前缀匹配；同层永远放行，目标不属于任何层默认放行（`Assets/`、`mods/`、`user://`）。
- 三种边都算：`res://` 字面量、`class_name` 标识符、autoload 单例名。类名表由扫描全仓 `class_name` 自建，不读 `.godot` 缓存（缓存过期会静默放行）。
- autoload 到脚本的映射写在同一张表里；与 `project.godot` 的 `[autoload]` 键集合不一致直接报错。
- `game/content/`（content-def）只读 `game/inventory/`、`godot_gas/`、`addons/` 等数据面向的层，不得引用 `game/battle/`；`game/battle/` 读 `game/content/` 的定义，方向单一。
- GBIS 在 `game/inventory/` 下，属 `game/` 层，不再单开一层；`drag_presenter` 开 `ItemWindow` 的例外仍挂 allowlist。
- 改边界先改表：表是策略，检查器只负责执行；有意的反向依赖进表，不从表里删规则。

注释策略：

- 首方 `.gd` 不写注释；why、边界、坑写进 `DOC/`。
- 只保留三类：`@export` 及其变体正上方的 `##`（Godot Inspector 显示）、`## @meta_addon/@meta_author/@meta_license` 来源标注、`godot_gas/gameplay_tags.gd`（插件生成，改完会再生成）。
- `#region` / `#endregion` 不留；编辑器折叠交给代码结构。
- 清理用 `tools/lint/strip_comments.py`（`--dry-run` / `--check` / `--write`），完整流程见 `.claude/skills/delete-comment/SKILL.md`。

Godot 警告（`project.godot` 的 `[debug]`，值 `2` 表示提成 error）：

- 4.7 中除下面几类外的警告全部提成 error。
- 未启用：`unsafe_*`（5 条）、`missing_tool`、`inferred_declaration`、`untyped_declaration`、`return_value_discarded`。
- `return_value_discarded` 暂不启用：存量主要是 `connect()` 等故意忽略的返回值，开启会逼出无意义变量或大量 `@warning_ignore`。
- 外部类 emit 的信号用 `@warning_ignore("unused_signal")` 标注；故意开火即忘的协程用 `@warning_ignore("missing_await")`。
- `debug/gdscript/warnings/directory_rules` 默认排除 `res://addons`，第三方代码不跟项目警告配置走。

编译检查：

- `tools/compile_check/check_scene.tscn` 以场景方式启动，autoload 已注册；遍历首方 `*.gd`、`*.tscn`、`*.tres` 逐个 `load()`。
- 只认 `SCRIPT ERROR: Parse/Compile Error`、`Failed to load script`、`Failed to instantiate an autoload`；退出时的 RID/ObjectDB 泄漏警告不算失败。
- 漏跑也算失败：输出里没有 `CHECK_TOTAL`、或 Godot 退出码非 0，一律判红。
- 运行前把 `APPDATA` / `XDG_DATA_HOME` 指到临时目录，不碰真实存档。
- 无 `.godot` 缓存、或有 `.gd` 比类缓存新时先跑一次 `--import`（约 9 秒）；否则约 3 秒。新增 `class_name` 后必须重导，否则运行时会报「Could not find type」。

## 情景测试

`tools/scenarios/` 是领域行为的反馈环：驱动真实入口，断言可见状态，失败时给出实际值与期望值。

- 运行方式：`run.tscn` 是场景，autoload 已就绪；参数写在 `--` 之后，空表示全部。
- 输出契约：每例一行 `SCENARIO <名> PASS|FAIL (n 项断言)`，失败明细为两空格缩进的 `  - 消息`；结尾 `SCENARIO_TOTAL` / `SCENARIO_FAILED`。
- 缺 `SCENARIO_TOTAL`、未知用例名、`SCENARIO_FAILED` 非 0、退出码非 0，任一出现即判红。
- 用例必须产生至少一项断言，空用例判失败；用例结束前自行清理它改过的全局状态。
- 需要主场景的用例实现 `needs_main_scene()` 返回 `true`，运行器按需加载一次 `main.tscn`（约 0.3 秒）。
- 新增用例：在 `cases/` 建脚本，`extends ScenarioCase`，实现 `case_name()` 与 `run(ctx)`，再到 `run.gd` 的 `CASES` 注册；`ScenarioContext` 提供 `check` / `equal` / `near`。
- 手头驱动不了的异步结算（如死亡走 `call_deferred`）在用例里 `await (Engine.get_main_loop() as SceneTree).process_frame`。
- 领域行为变更（存档、战斗、地图放置、开局流程）必须新增或更新对应情景；没有情景覆盖的新行为不算做完。

现有用例：

| 名称 | 覆盖 | 依赖 |
|---|---|---|
| `save_roundtrip` | 存档管线写读、备份回退、版本只读、v1 迁移、槽位摘要 | 无场景，`TestAPI.check_save_pipeline()` |
| `map_place` | 地图板空槽入槽、满槽排队、重复提交被拒、腾位结算 | autoload `MapBoard` |
| `battle_run` | 开战、手动时钟步进、伤害致死、击杀计数、停战 | `main.tscn` |
| `battle_lightning_rod` | 避雷针 tooltip、冻结/减速触发伤害、`max_range` 射程过滤 | `main.tscn` |

## 例外

`tools/lint/allowlist.toml`：

```toml
[[allow]]
rule = "no-comments"
path = "Scripts/example.gd"
reason = "保留旧实现对照，2027 年前删除"
expires = "2027-01-01"
```

- 四个字段缺一不可；`expires` 过期、条目没命中都会让检查失败。未命中只在全量检查时判：`--staged` / `--file` 只看到部分文件。
- 例外是债务，不是消音器；到期就修，或续期并写清原因。
- `dependency-boundary` 的例外按「文件×目标」计：一个文件越界到两个目标就要两条。

## 新增规则

1. 在 `tools/lint/rules.py` 加规则类，错误信息里写一句原因；需要配置表的把策略放 `tools/lint/<名>.toml`，检查器只读表。
2. 在 `tools/lint/tests/test_rules.py` 加一正一反 fixture。
3. 先在项目上跑 `--all` 看基线：有存量就先清理或写 allowlist，再把级别提到 error。
4. 更新本页规则表和 `DOC/INDEX.md`（若改了路由）。

能改 API 让错误不可能发生的，优先改 API，不要为同一件事堆多条规则。规则预算先控制在 10 条以内。

## 边界

- 不检查 `addons/`、`EngineTools/kanban_tasks/`、`EngineTools/color_catalog/`、`.godot/`、`base_mods/`、`mods/`；`EngineTools/modkit/` 算首方代码，`file-access-boundary` 对它单独豁免。
- 暂不引入 gdtoolkit/gdformat；格式统一另开一次提交。
- 规则误报时先改规则或删规则，不要让人习惯 `--no-verify`。
- CI：`.github/workflows/check.yml` 在 `windows-latest` 下载 Godot 4.7.2 后跑 `--all`；分支保护建议开启。
