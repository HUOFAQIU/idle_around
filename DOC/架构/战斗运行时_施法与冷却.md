## 1. 战斗系统 `game/battle/`

### 1.1 运行时对象图

```
BattleWindow (BaseWindow，Control)
├─ Tile (tile.tscn)
│  ├─ GroundTileMapLayer        六边形 TileMapLayer（32×32）
│  └─ Units (Node2D)            ← BattleUnit 都挂在这里，和地图同坐标系
├─ UiOverlay/Control
│  ├─ GridContainer/InfoButton     ☰ → 开关 InfoWindow
│  ├─ GridContainer/StartButton    ▷ / 重开
│  ├─ PlayerHealthBar              左下角生命条，中间显示当前/最大生命
│  ├─ PlayerRegenBar               生命再生条，有生命再生时显示
│  ├─ PlayerShieldBar              护盾条，有护盾时显示
│  ├─ PlayerBurnBar                灼烧条，有灼烧时显示
│  └─ PlayerPoisonBar              剧毒条，有剧毒时显示
└─ BattleSession (Node，窗口 _ready 时创建)
   └─ BattleManager (每场 new 出来，add_child)

BattleUnit (CharacterBody2D，Player/Snake 场景根)
├─ AbilitySystemComponent (Node，名字必须精确叫这个)
│  └─ AutoCastAbility...           ← 运行时从魂灵生成后 grant 到 ASC
├─ BattleBrain (Node)
├─ CollisionShape2D                ← 形状由场景决定（玩家圆形半径 14，怪物胶囊），和其他单位互挡

```

框架约束：`AbilitySystemComponent` 的节点名必须精确为 `AbilitySystemComponent`，GAS 在解析“施法者 → ASC”时按这个名字查找。

### 1.2 脚本职责

`game/battle/` 下每个脚本一个类，类名与文件名一致，职责从公开方法与信号读取；入口按 §1.1 的对象图找。几条读代码看不出来的归属：

- `BattleManager` 只保留门面与调度：名册、空间索引、地图换算、掉落都委托给协作者，刷怪只保留 `spawn_one()`；移动按实例 ID 分片，带 `UnitMoved` / `FreezeApplied` 触发器的单位注册为广播监听者。
- `SoulLoadout` 是玩家/怪物共用的唯一装载器；怪物没有魂器，槽位由 `SoulSlot.virtual_slots()` 按列表顺序生成。
- `BattleBrain` 每物理帧按 1/120 刻度结算状态和自然充能；单位级/魂灵级冻结都“不充能、不释放”，怪物在攻击范围外时由 `BattleManager` 直接关掉物理帧。
- `AutoCastAbility` 发射投射物即返回，不占用 `is_active`；投射物任务挂在施法者身上，不绑技能生命周期。
- 伤害取整与护盾分流集中在 `DamageResolver`；各 `*_execution.gd` 只准备数值。

### 1.3 一帧的施法链路

```
BattleBrain._physics_process(_delta)
  if unit.is_dead or battle == null or not battle.is_running: return
  # 怪物兜底：不在角色攻击范围内就不跑（正常由 BattleManager 直接关物理帧）
  if unit.team == ENEMY and not unit.is_in_attack_range(battle.player): return
  frozen = unit.asc.has_tag(ChargedAbility.FROZEN_TAG)

  # 基础刻度：UNITS_PER_SECOND * BattleClock.tick_seconds
  # 60 Hz 时是 2 刻度/帧
  base_units = ChargedAbility.UNITS_PER_SECOND * battle.tick_seconds()

  # 第一段：所有魂灵先结算激活锁和自然充能，再扣状态剩余时间
  for ability in abilities:
      charged.advance_activation_lock(base_units)  # 20 刻激活锁倒计时
      if not frozen and not charged.is_frozen():
          charged.advance_charge(base_units)       # 吟唱等施法过程也继续充能（投射物已独立飞行）
      charged.advance_status(base_units)           # 加速/减速/冻结倒计时（必须在充能之后）
  if frozen: return

  # 第二段：按数组顺序释放 —— 数组已按魂灵栏从左到右排好
  for ability in abilities:
      if charged and (charged.is_frozen() or not charged.is_ready()
              or not charged.can_activate_now()): continue
      if unit.asc.can_activate_ability(ability):
          ability.try_activate()                # 开火即忘，技能内部自己 await

  # 第三段：本帧触发器充能满的魂灵同帧释放（保持入队顺序）
  flush_pending_activations()
```

`frozen` 是单位级冻结（`State.Frozen` 标签）；`charged.is_frozen()` 同时包含魂灵自身的 `freeze_units`。两者都不影响 `advance_status()`，所以冻结期间加速/减速/冻结计时照常减少；外部 `add_charge()` 也照常生效。

触发器充能（`Event.Combat.SoulUsed`、`Event.Combat.FreezeApplied` 等）由 `SoulTriggerAbility` 充能后调用 `BattleBrain.request_activation()` 入队；物理 tick 内触发的由 `BattleManager` 在 tick 末统一 flush（同一 tick 释放），渲染帧内触发的顺延到下一 tick；不再使用 `call_deferred`。队列释放前重走死亡/战斗结束/冻结/攻击范围门控。单帧待释放队列上限 64 只防异常递归，真正的主限制是 20 刻激活锁。

吟唱等待按物理 tick 数推进（`battle.ticks_for_seconds()` + `BattleClock.wait_ticks()`），不读渲染帧 `delta`，也不再用 GAS 的 `ability_task_wait_delay`。

每颗魂灵有 `ChargedAbility.ACTIVATION_LOCK_UNITS = 20`（1/6 秒，1 秒最多 6 次）的激活锁，由 `AutoCastAbility._activate_ability()` 在扣费/清空前检查并标记。自定义 `ChargedAbility` 子类必须先在 `_activate_ability()` 里 `can_activate_now()` 再 `mark_activated()`，否则会绕过 20 刻锁。它允许“你触发我、我触发你”，但防止同一颗魂灵在同一 tick 或极短时间内无限连发；正常冷却远大于 20 刻，只有充能/触发链会撞到它。

多重触发（`SkillDefinition.cast_times > 1`）复用同一把锁：一次激活内第 2 次起，每次释放前都要等锁走完再 `mark_activated()`，所以释放节奏仍是 1 秒最多 6 次，超出的顺延到后续秒继续。整段释放序列期间 `is_active` 保持 true；冻结、战斗结束或施法者倒下会停止后续释放。

### 1.4 冷却与扫描线

- 冷却不再使用 GAS 的 DURATION 效果，而是 `ChargedAbility.charge_units` 按 `1/120` 秒的整数刻度累加。
  - 60 Hz：每物理帧基础 +2；加速 +4；减速 +1；加速+减速 +2。
  - 基础刻度 = `ChargedAbility.UNITS_PER_SECOND * BattleClock.tick_seconds`（只随物理帧率变化）。
  - 输出给 UI 的秒数由 `haste_seconds()` / `slow_seconds()` 换算（单位 / 120）。
- 技能冷却时长来自 `SkillDefinition.cooldown_seconds`：
  - `AutoCastAbility.apply_definition()` 直接写 `cooldown`；`GameplayAbility.cooldown_effect` 保持为空，避免 GAS 门卫按标签再判一次冷却；
  - 移动不再走冷却：`BattleUnit.move_speed` 是持续速度（像素/秒，默认 11，约 3 秒走一格），由 `BattleManager` 驱动。
- `cooldown <= 0` 时 `is_ready()` 恒为 `true`、`charge_ratio()` 恒为 `1.0`。
- 扫描线：
  - `BattleWindow._physics_process()` 每物理帧调用 `SoulRuntime.refresh_from_ability()`；
  - `SoulRuntime.changed` 通知已绑定的 `ItemView` 直接更新材质参数，不再每帧 duplicate `shader_params` 触发全量重绘；
  - 开战 `_set_scanlines(true)`，关窗/结束 `_set_scanlines(false)`；
  - 扫描线材质来自 `Assets/Shader/soul_scanline.gdshader`，参数包括 `line_color`、`band_width`、`intensity`、`enable`、`progress`；
  - 所有魂灵的 `line_color` 统一为 `#8cd9ff`（`Color(0.54902, 0.85098, 1, 1)`），不再按魂灵单独配色。
- 同一颗主动魂灵装两份，会生成两个独立的 `AutoCastAbility`，各自充能，不去重。
- 被动魂灵没有 `AutoCastAbility`；`_set_scanlines(true)` 会跳过它，不显示扫描线。
- 加速/减速：
  - `haste_units` / `slow_units` 各自是单个剩余时间（刻度）；加速固定 2x、减速固定 0.5x；
  - 重复施加同一种状态只累加剩余时间（2 秒 + 2 秒 = 4 秒），不会提高倍率；
  - 加速和减速同时存在时，`_charged_units_for_tick()` 返回 1x 刻度；某一方到期后按另一方继续；
  - 只乘 `advance_charge()` 的自然充能，外部 `add_charge(秒)` 直接加的刻度不受影响；
  - 剩余时间归零时在战斗日志里写“状态【加速/减速】结束”；
  - 本 tick 施放产生的状态，下一 tick 才开始影响充能（两段式）。
  - 状态剩余时间在 `advance_charge()` 之后扣减：持续 N 刻的加速/减速/冻结正好影响 N 刻充能。顺序反过来会让每个状态少 1 刻；常驻加速这类临界配速下，误差会持续累积（例如长弓每 4 秒被松鼠、咖啡刷新加速，会逐次晚 1 刻释放）。
- 冻结：
  - 魂灵级：`freeze_units` 和加速/减速同一套刻度；`apply_freeze(秒)` 累加时间，`advance_status()` 归零时写“状态【冻结】结束”；
  - 单位级：`base_mods/core/effects/freeze_unit.tres` 是 `DURATION` 效果，`granted_tags = [State.Frozen]`，持续期间整个 `BattleBrain` 不充能、不释放；移动、魂灵技能一起停；
  - 两种冻结都只停自然 `advance_charge()`，外部 `add_charge()` 仍然有效；加速/减速/冻结计时照常减少；
  - 只停单颗魂灵时用魂灵级冻结（`SoulSkillStep.freeze_duration` + `SoulTargetRule.BOTH_SIDES`）；需要冻结全场时用单位级冻结（触发器把效果施加给全体敌人）。
- 充能：
  - `SoulSkillStep.charge_duration` 仍是秒；`AutoCastAbility` 调 `target.add_charge(秒)`，内部换算成刻度；
  - 不受加速/减速倍率影响；
  - `add_charge()` 最多加到技能冷却，溢出丢弃，释放时 `reset_charge()`；
  - 技能充能后如果目标已经满，会立刻在同一帧释放；触发器充能由 `BattleBrain.request_activation()` 入队，当帧末由本 Brain 的 `flush_pending_activations()` 释放；
  - 跨单位触发器由 `BattleManager` 在物理 tick 末统一 flush，不再用 `call_deferred`；flush 前重走死亡/战斗结束/冻结/攻击范围门控；
  - 每颗魂灵有 20 刻（1/6 秒）激活锁，同一颗魂灵 1 秒最多激活 6 次；正常冷却远大于 20 刻，只限制充能/触发链；多重触发的每次释放也各占一次锁，超出 6 次的部分顺延到后续秒；
  - 充能是瞬时的，不新增状态计时/徽章。
- 状态徽章：
  - `SoulRuntime` 保存 `haste_seconds` / `slow_seconds` / `freeze_seconds`（战斗显示用，按 0.1 秒取整）；
  - `BattleWindow._push_scanlines()` 每物理帧从 `ChargedAbility` 写入；
  - `ItemView` 用 `game/content/Kits/jiasu.tscn` / `jiansu.tscn` / `bingdong.tscn` 显示，加速在上、冻结在中、减速在下，一位小数；
  - 魂灵冻结时 `soul_scanline.gdshader` 的 `freeze` 参数同时打开冰霜覆盖；
  - 战斗结束/重开时由 `BattleSession.stop()` 清零。
- 顺序：
  - `BattleWindow._equipped_souls()` 先按魂器网格里魂器的占格从上到下、从左到右排魂器，再按每个魂器内部容器从左到右排魂灵；
  - `_soul_abilities` 与这个顺序一一对应，`BattleBrain` 第二段直接按数组顺序释放；
  - 因此同冷却的魂灵在同一 tick 按“魂器位置 → 魂器内列位置”触发；
  - 触发器充能满的魂灵不在主循环的左右位置释放，而是在当 tick 末按入队顺序补发（仍在同一 tick）。

### 1.5 时间模型与已知限制

- 固定 tick：`BattleBrain` 充能/释放、`BattleManager` 移动、`SoulProjectile` 飞行/命中、`BattleSession` 刷怪、吟唱等待、跨单位触发器 flush。它们都以 `BattleClock` 为唯一时钟。
- `BattleClock` 正常游玩时按物理帧推进；`TestAPI.pause_battle()` 后改由 `TestAPI.step_battle(n)` 手动推进，GAS 持续效果也一起步进（`AbilitySystemComponent.advance_time()`）。
- 手动时间模式下新入场单位也要设 `ASC.manual_time`，否则 ASC 会按渲染帧推进。
- 内部重开（玩家复活/地图完成）沿用当前手动时间模式；外部 `stop()` 退回正常速度。
- 表现层：Cue、飘字、血条、扫描线、Tween/粒子继续按渲染帧运行，只读逻辑状态。
- **已知限制**：正常游玩时 GAS 持续效果（灼烧/剧毒/生命再生每跳、DURATION 到期、单位级冻结时长）仍由 `AbilitySystemComponent._process(delta)` 按渲染帧推进；当前 `max_fps=60` 与物理 60Hz 重合，差异不明显。暂停/步进测试时这部分会随 `BattleClock` 走，但生产时序仍与固定 tick 不完全一致。
