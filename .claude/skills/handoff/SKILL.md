# 阶段交接

交接单是临时文件，不是文档：写进 `%TEMP%`，不提交，不占 `DOC/`。

## 1. 选位置

```bash
python -X utf8 -I -c "import tempfile; print(tempfile.gettempdir())"
```

文件名 `idle_around-handoff-YYYY-MM-DD-HHMM.md`，写完把完整路径告诉用户。

## 2. 内容（不超过 60 行）

先跑这三条，用真实输出填：

```bash
git status --short --branch
git log --oneline -5
```

然后写五节：

- 现在在哪：分支、HEAD、工作区有没有残留改动、最后一次验收命令和结果。
- 做完了什么：按 spec 编号或文档章节列，每条附验收命令。
- 下一步：有顺序的清单，每条指向 spec、`DOC/` 章节或 `file.gd::symbol`。
- 未决、等用户决定：单独列，写清选项。
- 指针：相关文档路径、探针是否已拆。

不复制代码，不复制文档正文，只给指针。改动还在 spec 里时，只写「读 `DOC/spec/NNNN-x.md`，状态已约定或已实现」，不重述行为清单。

## 3. 恢复

新会话按顺序：

1. 读交接单。
2. `git status` / `git log` 核对；与交接单不一致时以仓库为准。
3. 跑交接单里的验收命令，确认基线是绿的。
4. 从「下一步」第一条继续。

## 4. 收尾检查

- 探针已拆，工作区只剩本次真实改动。
- 需要长期保留的结论已经写进 `DOC/` 或 spec，而不是只留在交接单里。
- 交接单路径已告诉用户。
