## 1. 设计原则与分层

- **六槽独立 JSON**：`user://saves/slot_0.json` … `slot_5.json`，每槽独立 `.bak` / `.tmp`。不存 `Resource`，不存静态配置/场景尺寸，不存战斗运行期状态（HP、冷却、怪物、扫描线、地图进度）。
- **启动不自动读档**：`SaveManager._ready()` 仅扫描六槽摘要；必须由 `GameFlow` 选槽或建新档进入。无活动槽时不累计 `play_time_sec`、不心跳、关窗不写盘。
- **职责分层**：`SaveManager`（组合根 + 会话态）→ `SavePipeline`（版本/主备回退/participant 顺序）→ `SaveStorage` seam（生产 `DiskSaveStorage`，测试 `MemorySaveStorage`）；`SaveScheduler` 管去抖/心跳，`SaveDocument` 管顶层 schema/迁移，容器/见闻/地图板各自实现 `SaveParticipant`。

## 2. 文档 Schema（`version: 2`）

```json
{
  "version": 2, "saved_at_unix": 1793923200, "play_time_sec": 3721.5,
  "player": { "character_id": "small_coal_lamp", "display_name": "小煤灯" },
  "containers": {
    "inventory_0": [{ "kind": "soul", "id": "<id>", "name": "<排查名>", "at": [0, 0] }],
    "vessel_cells": [{ "kind": "vessel", "id": "<id>", "at": [0, 0], "contents": [] }]
  },
  "detached": [], "orphaned": [],
  "collection": { "monsters": [], "souls": [], "vessels": [] },
  "map_board": { "slots": [null], "pending": null, "orphaned": [] }
}
```

- 读档只认 `id`（`name` 仅排查用）；`at` 为左上角格，非法锚点 `SaveCodec.anchor_from_record()` 回退 `(-1,-1)` 落首个空位。
- 魂器带 `contents`（相对内部容器锚点），未入世界时原始 record 已含内部魂灵，不可重复拆写；`detached` 存保存瞬间鼠标上的物品，读档入仓库首个空位；空容器与空 `orphaned` 不写；商店/装备槽不存；写盘按锚点与字母排序便于 diff。

## 3. 保存时机

| 触发 | 行为 |
|---|---|
| 背包增删改 / `sig_inv_refresh` | 有活动槽时 `mark_dirty()`，去抖 2 秒写当前槽 |
| 见闻解锁 `entry_unlocked` | 有活动槽时 `mark_dirty(true)`，下一帧立即写盘 |
| 运行中 / 关窗或暂停 | 每 30 秒心跳写盘 / 同步写当前槽 |
| 切档 / 新游戏 / 手动 | `GameFlow` 先停战关面板再 `save_now()`；新档先写空文档成功再清内存 |

去抖与心跳全在 `SaveScheduler`（禁止在信号回调直接写盘）；写盘失败保留 `dirty` 重试。

## 4. 启动、读档、新建与扩展持久化域

- **启动就绪**：`SaveManager._ready()` 注册 participant → 扫六槽摘要 → `await process_frame` 等 `Warehouse`（`inventory_0..9`）与 `CharacterWindow`（`vessel_cells`）注册完毕。无主场景（`--script`）或缺少期望容器时切只读防覆盖（`TestAPI.get_save_status()` 可查）。
- **读已有槽**：`GameFlow.request_load_slot()` 停战关窗保存旧槽 → `SavePipeline.load()` 读主文件/回退 `.bak`（高版本只读、低版本 `SaveDocument.migrate()` 回写）→ 清空期望容器按 `(at.y, at.x)` 用 `try_add_to_grid()` 精确恢复（禁用 `GBIS.add_item()` 防破坏相邻关系），放不下走 `Warehouse.add_item()`，未注册容器/缺失 mod 进 `orphaned` → 恢复 `detached` / `collection` / `map_board` / `player`（旧档缺 `player` 回退小煤灯）→ 末尾仅重试磁盘带回的 `orphaned`，发一次 `sig_inv_refresh`；`CollectionDB` 首帧后补扫已拥有魂灵。
- **新建游戏**：`first_empty_slot()` 找首个空槽（解析失败的损坏槽视为空槽，覆写时轮换进 `.bak`），先写空文档成功再清空内存并切 `IN_GAME`；满 6 槽提示「角色已满」。
- **新增持久化域**：新建 `XxxSaveParticipant` 实现 `collect_into` / `apply_from` / `finish_load` → 顶层键加入 `SaveDocument`（必要时补 `migrate()`）→ 按依赖顺序注册到 `SaveManager._participants`；`player` 段由 `SaveManager` 直接维护。

## 5. 物品编码、版本与原子写

- **四种可持久化物品（`SaveCodec`）**：`soul`（`SoulData.content_id`）、`vessel`（`SoulVesselData` + `contents`，内部单颗魂灵缺失仅保留该魂灵进 `orphaned`）、`map`（`MapData.content_id`，`MapCatalog` 找回）、`stone`（数量石，`MapCatalog` 找回）。`content_id` 随 `make_instance()` 保留，不按 `name` 反查。
- **地图板与见闻**：`MapBoardSaveParticipant` 存 8 槽 + `pending` + `orphaned`，读档整体替换不逐项发 `item_removed`；`CollectionDB` 读档后发 `state_reloaded` 刷新见闻窗。
- **版本与原子写**：当前 `version: 2`（v1 迁移补 `player`）。写盘顺序：`slot_N.json.tmp` → 旧主文件轮换 `.bak` → `.tmp` 改名为主文件；从 `.bak` 恢复后的首次写盘置 `_keep_backup_next_save` 保留好备份。`delete_slot()` 删三文件，删活动槽会断开会话并回 01 面。

## 6. 边界、测试与排查

- 容器名常量集中在 `scripts/container_ids.gd`，改名视为不兼容（旧记录进 `orphaned`）。
- 直接调 `SaveManager.load_slot()` 不会停战，正常流程必须经 `GameFlow`。主窗口置顶走 `user://Settings.cfg`（`scripts/settings_file.gd`），面板/立方体位置与离线收益尚未持久化。
- 管线自检：`TestAPI.check_save_pipeline()`（走内存存储不碰真实 `user://`）；详细排障与无头隔离见 `指南/存档排查.md`。
