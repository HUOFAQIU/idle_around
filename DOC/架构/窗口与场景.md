## 1. 启动与窗口外壳

### 1.1 单窗口模型

主场景是 `Main/Cube/Scenes/main.tscn`（3D 立方体外壳）。`Main/control.tscn` 仍然是完整的游戏 UI，但作为主视口里的 `GameUI` CanvasLayer 覆盖层运行，不再塞进立方体面片：

```text
Main/Cube/Scenes/main.tscn (Node3D)
├─ CubeView (CanvasLayer, layer=1024)     → 压住 GameUI
│  ├─ ViewportContainer (SubViewportContainer, 全屏、stretch、IGNORE)
│  │  └─ CubeViewport (SubViewport, 透明、独立 World3D)
│  │     └─ Cube / Camera3D / 灯光
│  │        └─ CubeRig/OrientationPivot
│  │           ├─ Front（Face3D，face_index=0）→ SaveSlotsContent
│  │           ├─ Back（Face3D，face_index=1）→ PetPanelContent → Main/pet_panel.tscn
│  │           ├─ Left（Face3D，face_index=2）→ FaceUI
│  │           ├─ Right（Face3D，face_index=3）→ CharacterSelectContent
│  │           └─ Top/Bottom（Face3D）→ FaceUI
│  │              └─ 每个 Viewport 带 LockOverlay
│  └─ InputSurface (Control)              → 立方体轮廓内接管输入
├─ GameUI (CanvasLayer, layer=1)
│  └─ Main/control.tscn
│     Control (control.gd)               → 当前游戏 UI（主视口全屏覆盖层）
│     ├─ 9 个 BaseWindow 面板 + PanelManager
│     ├─ DragLayer (CanvasLayer, 1025) / ItemWindow
│     └─ TooltipLayer (CanvasLayer, 1026) / TooltipWindow
├─ HUD (CanvasLayer, layer=1024)         → 面识别/流程 Toast，树中在 CubeView 之后
└─ WindowPassthrough
```

- 游戏 UI 的设计基准是 1600×960；当前工作副本是全屏透明覆盖层，视口尺寸跟随窗口客户区，窗口位置/尺寸只用项目设置决定，不在运行期修改（原因见 §1.7 和 `立方体外壳.md` §4.1）。
- 立方体是屏幕空间的小浮件：01/02/04 面的投影约 300px，默认在屏幕中心，由 `CubePlacement` 按视口尺寸换算世界缩放和位置。启动正对 01 面，02/04 默认锁。
- 立方体渲染在 `CubeView`（layer=1024）的透明子视口里，压住 `GameUI`；HUD 也是 1024 但树中更靠后，所以 Toast 显示在立方体之上；`DragLayer`（1025）和 `TooltipLayer`（1026）仍在最上面。`CubeInputSurface` 只在立方体轮廓内接管鼠标，被盖住的面板收不到 hover/点击。`PanelManager._input` 会先问 `contains_screen_point()`，立方体输入区内不置顶/激活下层面板；战斗窗口的坐标 tooltip 也会在指针落入立方体输入区时让位。
- 主场景内立方体子树的 NodePath 集中在 `Main/Cube/Scripts/cube_scene_paths.gd`，改 main.tscn 里的子树只改这一份；cube.tscn 内部的拖动圆点路径仍由 `CubeRig` 维护。
- 项目设置：`window/size/mode=3`、`transparent=true`、`borderless=true`、`per_pixel_transparency/allowed=true`、`viewport/transparent_background=true`、`stretch/mode="disabled"`，渲染 Forward+ / D3D12。
- `window/subwindows/embed_subwindows` 不再参与面板布局：项目里没有 `Window` 面板，只有唯一的主 OS 窗口。
- 面板都是主视口里的 `Control`；面板背景强制不透明（见 §1.2），透明的是面板之间的空桌面区域，点击穿透见 §1.7。
- 01/02/04 面的内容（存档位/主菜单/角色选择）都在 SubViewport 里，鼠标事件由 `CubeInputSurface` 推进子视口，再由 `Face3D` / `CubeRig` 转发；这三个面 `ui_capture=true`，采用“控件优先”分流（见 `立方体外壳.md` §3）。

游戏 UI 的 Control 树（在主视口里铺满，全屏锚点）：

```
Control (control.gd)
├─ CharacterWindow / VesselWindow / InventoryWindow / BattleWindow /
│  ShopWindow / CollectionWindow / InfoWindow / DebugWindow / ModWindow /
│  TerminalWindow                            → BaseWindow 面板（Control）
├─ PanelManager (Node)                       → 置顶/激活/遮挡判断
├─ DragLayer (CanvasLayer, layer=1025)
│  └─ ItemWindow (Control)                   → 拖拽幽灵浮层
└─ TooltipLayer (CanvasLayer, layer=1026)
   └─ TooltipWindow (PanelContainer)         → 悬停提示浮层
```

- 所有面板都是主视口里的 `Control`，绘制顺序就是根节点的子节点顺序；`PanelManager.raise()` 把面板 `move_to_front()`，并记录 `_active`。
- Tooltip/Item 放在 1025/1026 的 CanvasLayer 里，保证永远盖在面板上面。
- 主菜单不再在 `control.tscn` 里：`PetPanel` 已抽成 `Main/pet_panel.tscn`，挂在立方体面 02 上，按钮请求由 `Main/Cube/Scripts/main.gd` 转给 `GameUI.open_panel()`；01/04 面的存档/角色请求转给 `GameFlow`。切档/新游戏前 `GameUI.close_all_panels()` 统一关闭旧面板。
- `control.gd::open_panel(panel_id)` 按 id 找到窗口并转发给 `popup_window()`；`popup_window()` 只做 `PanelManager.toggle(window)`。
- `BaseWindow.open_window()` 负责尺寸/位置/可见；真正显示时 `visibility_changed` 让 `PanelManager` 置顶并设为激活面板。
- 存档不再在启动时自动读档：`SaveManager` 只扫描槽位摘要，由 `GameFlow` 在 01 面选档或新游戏时调用 `load_slot()` / `create_new_game()`；mod 挂载时机不变。

### 1.2 BaseWindow

`Windows/base_window.gd`（`extends Control`；类名沿用 Window）：

- `@export var open_position: Vector2i`：**主视口内坐标**；任一坐标为负表示“居中”。
- `_ready()` 先建背景 `Panel`（`WindowBackground`，`MOUSE_FILTER_IGNORE`）和 `TitleUI`（`VBoxContainer`：28px 标题栏 + `ContentRoot`），并设 `clip_contents = true`，复现原来 Window 的裁剪行为。默认 `Panel` 主题的 `bg_color` 是半透明（alpha 0.6），这里强制改成 alpha 1，避免透明窗口下面板透出桌面。
- `open_window()`：
  - `_wrap_content()` 后按当前/场景尺寸夹到主视口大小；
  - 有 `open_position` 就 `_clamp_position()`，否则在主视口居中；
  - `visible = true`，`call_deferred("_grow_to_content")`：等一帧布局完成后按 `ContentRoot` 子节点的最小尺寸向上撑（只增不减，避免 RichTextLabel 在宽度为 0 时算出巨大高度）。
- `title` 是 BaseWindow 自己的属性 + `title_changed` 信号，子类继续用 `title = "..."`；不再依赖 `Window.title`。
- `_build_title_bar()`：`TitleUI/TitleBar` 是 `PanelContainer`，背景取 `GameColors.WINDOW_TITLE_BAR`（#facc15），content margin 为 0；内层 `TitleBarBox` 依次放 `TitleMargin/TitleLabel`、额外按钮（`add_title_bar_button()`）、`CloseButton`、右侧留白。标题文字用 `TEXT_OUTLINE` 保证黄底对比度，由 `_sync_title()` 同步。
- 拖动：`Scripts/ui/control_drag.gd` 绑定标题栏；按下后每帧轮询主视口鼠标 + `Input.is_mouse_button_pressed()`，更新 `position` 并 clamp 到主视口。鼠标快速拖出面板也不会断。
- `add_title_bar_button(button)`：子类在 `super()` 之后调用，按钮插到关闭按钮左侧，沿用统一字号/光标/按下高亮。
- `_wrap_content()`：把原内容挪进 `ContentRoot`，外层 `size.y` 加 28；`_grow_to_content()` 再按内容最小尺寸撑高。
- 不再有 `borderless`、`popup`、`close_requested`、`grab_focus`、`min_size`、每窗口置顶等 Window 专有逻辑；面板前台化由 `PanelManager` 统一处理。

### 1.4 两个浮层单例

后加载的脚本通过静态变量拿单例：

| 类 | 单例 | 关键接口 |
|---|---|---|
| `TooltipWindow` | `TooltipWindow.instance` | `show_tip(owner, layer, title, body := "")` / `hide_tip(owner)`；层级 `COORD < ITEM` |
| `ItemWindow` | `ItemWindow.instance` | `hold(view, offset, base_size)` / `clear()` |

- **TooltipWindow** 现在是 `PanelContainer`，挂在 `TooltipLayer`（layer 1026）下：
  - `_place_tip()` 用 `get_viewport().get_mouse_position()` 和 `get_viewport_rect().size`，默认在鼠标右下方，右边/下边放不下就翻边，再夹回主视口；不再有 OS 窗口的显示/隐藏闪烁。
  - `show_tip()` / `hide_tip()` 仍按 owner + 层级记账，低层级不能覆盖仍有效的高层级；同帧 hide+show 会合并。
  - 正文由 `SoulTooltip.build()` / `VesselTooltip.build()` 生成。标题和正文都由内嵌 `TerminalView`（终端字符网格，调试网格开启）绘制：标题是顶部 `TerminalSpan` 跨格大字（`TITLE_SPAN_ROWS = 2`，带下划线），正文从第 2 行开始，`TooltipWindow` 把纯文本转成 ANSI。标题和正文都为空时隐藏 `BodyTerminal`。`TooltipText` 统一产出 PLAIN / BBCode / ANSI。
  - 根节点 `mouse_filter = IGNORE`，不会挡住下面的面板。
- **ItemWindow** 现在是 `Control`，挂在 `DragLayer`（layer 1025）下：
  - `hold()` 把 `ItemView` 加进来，整棵子树递归设 `mouse_filter = IGNORE`，避免幽灵挡住放置/取消事件。
  - `_process` 每帧用 `get_viewport().get_mouse_position() - _grab_offset` 跟随鼠标；尺寸跟物品视图同步。
  - 不再需要屏幕外预热、跨窗口焦点监听、topmost 降级/恢复、`DisplayServer.window_set_flag`、`get_window_id()` 这些原生窗口补丁。
  - 幽灵只能在主窗口内跟随；拖到窗口边缘会被裁掉，这是单窗口模式的正常代价。
- **InfoWindow** 仍是普通 BaseWindow，正文是 `TerminalView`；窗口隐藏时日志写入自己的 500 行缓冲，打开时重建到终端，见 `窗口/终端.md` 和 `现状与注意.md`。

### 1.5 面内容与立方体拖动

- `PetPanel` 现在是立方体面 02 的 300×300 主菜单（`Main/pet_panel.tscn`）；01 面是存档位，04 面是角色选择，都是 300×300 子视口，面内容不自己拖动或持久化位置。
- 原 PetPanel 的浮层职责由立方体承接：
  - 01/02/04 面在主视口里的投影约 300px，默认停在主视口中心；
  - `Main/Cube/Scripts/cube_placement.gd` 按视口高度换算立方体缩放，并把它锚定在屏幕坐标上；

### 1.6 置顶

- 单窗口模式只有整个应用可以置顶：`Main/status_bar_container.gd` 的 T 按钮 + `WindowPinSettings.MAIN_WINDOW_ID`。
- 面板标题栏只有拖动、标题、关闭（以及见闻的“全解锁”按钮），没有每面板 T；`BaseWindow` 不再读写 `Settings.cfg` 的窗口条目。

- TestAPI 的 `set_window_pinned()` / `is_window_pinned()` / `get_window_pin_states()` 只支持 `MainWindow`；其他名字返回 false。

### 1.7 透明区域点击穿透

- 主窗口是全屏透明覆盖层；`Main/Cube/Scripts/window_passthrough.gd` 用 `get_window().mouse_passthrough_polygon` 设置**接受鼠标的区域**，区域外的点击落到桌面。
- 区域 = 立方体的屏幕投影凸包 + 可见游戏面板 + Tooltip + ItemWindow + HUD Toast + 拖动圆点；凸包由 `CubeProjection` 投影（相机在 `CubeViewport` 里），与 `CubeInputSurface` 的 GUI 命中共用；立方体凸包外扩 `REGION_PADDING`（28px），UI 矩形外扩 `UI_REGION_PADDING`（8px），由 `Scripts/ui/ui_region.gd` 用 2px 走廊合并成一个多边形。
- OS 穿透和应用内层级是两件事：立方体压住面板时，轮廓内事件先被 `CubeInputSurface` 吃掉；窗口区域仍取「凸包 + UI 矩形」的并集。
- 鼠标按下、拖拽、旋转/回正期间把区域临时扩成整个客户区，结束后恢复，避免拖动 UI 或旋转时丢事件。
- **主窗口必须是 borderless**（`display/window/size/borderless=true`）。Godot 的 Windows 后端对非 borderless 窗口会用可调边框的非客户区尺寸（`SM_CXSIZEFRAME + SM_CXPADDEDBORDER` 等）平移多边形，导致绘制和命中错位；本项目 `mode=3` + borderless，Godot 直接把多边形当客户区坐标用，才和绘制 1:1。
- **不要在运行期改主窗口的 `position` / `size`**。Windows 下透明窗口被重新定位/缩放后逐像素透明会失效，整块窗口变成不透明（实测：早期启动时贴合屏幕的 `_fit_window_to_screen()` 就是这个后果，已移除）。并且视口尺寸和客户区不一致时，绘制和窗口区域也会错位。
- 注意：Godot 的 `WINDOW_FLAG_MOUSE_PASSTHROUGH` 在 Windows 上只传给同一应用窗口（Godot issue #120881），不能替代 `mouse_passthrough_polygon`；代码里保持 `mouse_passthrough=false`。
- TestAPI：`set_cube_passthrough_enabled()` / `is_cube_passthrough_enabled()` / `get_cube_passthrough_state()`；状态含 `enabled` / `locked` / `rects`（UI + HUD + 拖动圆点矩形数量，不含立方体凸包）/ `polygon_points`。
- 已知边界：DPI 缩放/多屏需要实测；Toast 显示/隐藏、窗口开关/移动、Tooltip 跟随会触发区域重建（矩形数量很少）；立方体旋转结束后才会恢复精确区域。

## 2. 场景与配置

### 2.1 `Main/control.tscn`（游戏 UI 覆盖层）

- 通过 `Main/Cube/Scenes/main.tscn` 的 `GameUI` CanvasLayer 实例化为主视口覆盖层；不再是主场景；
- 根 `Control` 全屏锚点、`MOUSE_FILTER_IGNORE`，铺满主视口；
- 不再包含 `PetPanel`（主菜单在 `Main/pet_panel.tscn`，挂在立方体面 02；01/04 面是存档位和角色选择）；
- 8 个 BaseWindow 场景实例 + 内联 ModWindow（共 9 个面板，全部是 Control）；
- `PanelManager`（Node）：置顶、激活、按矩形判断最上层面板；切档/新游戏前 `hide_all()` 关闭旧会话窗口；
- `DragLayer`（1025）里是 `ItemWindow`，`TooltipLayer`（1026）里是 `TooltipWindow`；
- 各窗口的 `open_position` 是主视口局部坐标（设计基准 1600×960）：Character 在场景里配 `(20,20)`，Vessel `(20,320)`，Inventory `(735,20)`，Battle `(560,20)`，Debug `(200,80)`；Shop/Collection/Info/Mod 未配置 → 居中；
- 场景里不再有 `OverlayPassthrough` 节点；窗口穿透由立方体外壳的 `WindowPassthrough` 统一处理。

### 2.2 `BattleWindow`

- 场景尺寸 1000×1030（运行时加 28 = 1000×1058），默认位置 (560,20)；
- `Tile` 放在 `(484,440)`，`scale` 保持 1:1，不缩放：

## 3. 常见排查

1. **窗口跑到工作区外/被裁**
   - 所有 `open_position` 都是主视口局部坐标；负数才是居中；
   - `BaseWindow._popup_size()` 会把面板夹到主视口大小，`_clamp_position()` 会夹位置；打开后 `_grow_to_content()` 会在布局完成后再按内容最小尺寸向上撑（只增不减）；
   - 设计基准是 1600×960；全屏下主视口更大，面板会按实际视口夹取。

2. **标题栏拖不动 / 关不掉**
   - 标题栏拖动由 `Scripts/ui/control_drag.gd` 统一处理：`process_frame` 轮询主视口鼠标、`Input.is_mouse_button_pressed()` 判断按键，鼠标拖出面板边缘仍会继续；
   - 关闭按钮是 `TitleUI/TitleBar/CloseButton`，`pressed → hide()`；`BaseWindow` 已没有 `close_requested`，也没有系统标题栏/边框；
   - 如果拖不动，先确认标题栏空白区域没有被额外按钮/子 Control 用 `MOUSE_FILTER_STOP` 吃掉；01/02/04 面的 `ui_capture` 只影响立方体面内容，不影响游戏面板。

3. **Tooltip/拖拽幽灵被面板盖住**
   - 面板是根 Control 下的普通子节点，`TooltipLayer` 必须是 1026，`DragLayer` 必须是 1025；
   - Tooltip/Item 必须留在对应 CanvasLayer 下，不要塞回根 Control；面板改用 `move_to_front()` 置顶后，CanvasLayer 仍然优先。

4. **拖拽时点不到格子/放不下物品**
   - `ItemWindow` 根节点和它的整棵子树都必须是 `MOUSE_FILTER_IGNORE`；`hold()` 里已有递归处理；
   - 幽灵只在主窗口内跟随，拖出窗口边缘会被裁掉。

5. **战斗地图被裁/压住血条**
   - BattleWindow 的地图按 1:1 显示：928×896 地图 + 118px 状态条堆叠决定窗口内容区至少 1030 高；改地图范围、状态条数量/高度后要重新核对 Tile 的 `(484,440)`、窗口高度和血条顶部。1:1 布局在 1600×960 设计基准下会被夹到 960，状态条会压到地图上；实际全屏 2560×1438 不受影响；
   - 不要直接缩小 TileMap 的格数来适配窗口，那会改变战斗距离。

6. **调试/Mod 内容错位**
   - 这两个窗口的 UI 全是脚本构建；标题栏会占 28px，Root 在 ContentRoot 里；
   - DebugWindow 场景 1200×760、运行时含标题栏 1200×788；ModWindow 场景 760×520、运行时 760×548；两者都不支持窗口缩放。

7. **测试置顶状态**
   - 单窗口只有主窗口能置顶：`TestAPI.set_window_pinned("MainWindow", true/false)`；
   - 面板的置顶状态 API 已移除，不要再用 `CharacterWindow` 等名字。

8. **静止时 UI 边缘缺一条、按住鼠标又出现**
   - 症状：点击/按住面板或立方体主菜单时，UI 的边缘（典型是顶部/左侧几条像素）突然补上，松开又消失；
   - 检查点：主窗口是否 `borderless=true`（非 borderless 会被 Godot 按可调边框的非客户区尺寸平移 `mouse_passthrough_polygon`），以及窗口尺寸/位置是否和视口一致（见 §1.7）；
   - 结论：`project.godot` 必须保留 `window/size/borderless=true`，且不要用代码在运行期改窗口位置/尺寸（会让窗口变不透明，见 §1.7）。

9. **全屏透明覆盖层失效/点击穿透异常**
   - 检查 `project.godot` 是否误加了 `window/size/resizable=false`、`window/size/maximize_disabled=true`、`window/size/always_on_top=true`：Godot 4.7 下这些会让 `mode=3` 降级成接近屏幕大小的窗口；
   - 立方体/面片/拖动圆点的命中与穿透见 `立方体外壳.md` §4。
