## 3. 启动与窗口外壳

### 3.1 启动链

`Main/control.tscn` 的根节点是 `Control`，挂 `Main/control.gd`。

```
Control (control.gd)
├─ Setting (setting.gd)          → 启动时把主窗口贴到屏幕左下角
├─ StatusBarContainer            → 主窗口顶部状态栏（44px）
│  ├─ Button       "<"           → 主窗口移到左下角
│  ├─ Button2      "T"           → 切换置顶（always_on_top）
│  ├─ Button3/4/5  （空）        → 暂未接逻辑
│  └─ Button6      ">"           → 主窗口移到右下角
├─ GridContainer                 → 3×3 功能按钮
│  ├─ Button  人物  → CharacterWindow
│  ├─ Button2 魂灵  → EquipmentWindow
│  ├─ Button3 仓库  → InventoryWindow
│  ├─ Button4 商店  → ShopWindow
│  ├─ Button5 战！  → BattleWindow
│  ├─ Button6 见闻  → CollectionWindow
│  ├─ Button7 调试  → DebugWindow
│  ├─ Button8      （空）        → 暂未接逻辑
│  └─ Button9      → ModWindow
├─ CharacterWindow
├─ EquipmentWindow
├─ InventoryWindow
├─ BattleWindow
├─ ShopWindow
├─ CollectionWindow
├─ TooltipWindow
├─ InfoWindow
├─ DebugWindow
├─ ModWindow
└─ ItemWindow
```

`control.gd::popup_window()` 的规则：

- 窗口已经可见 → `hide()`（再点一次就是关）；
- 是 `BaseWindow` → 调 `open_window()`，按 `open_position` 摆放，没配就居中；
- 不是 `BaseWindow` → `popup_centered()`。

存档读档时机：`SaveManager` 是 autoload，排在 `Warehouse` 之后；启动时等一帧，让 `Warehouse` 预注册 `inventory_0..inventory_9`、各窗口在 `InventoryView._ready()` 里注册 `cell_0..3`，再执行 `load_game()`。`--script`/工具模式没有主场景，等完一帧直接返回，不读也不写。不要在 `Control._ready()` 之前读档，否则容器还不存在。详见 `架构/存档.md`。

mod 挂载时机：`ModLoader` 是第一个 autoload，在 `_init()` 里发现内置/第三方 mod、先挂载全部 PCK、再加载内容，早于 `CollectionDB` 建立内容目录；`GameplayCueManager` 直接使用 GodotGAS 管理器，先加载内置 registry（当前为空）；`ModCueRegistrar` 再把 core 和第三方 Cue 注册进去。详见 `架构/Mod系统.md`。

### 3.2 BaseWindow

`Windows/base_window.gd`：

- `@export var open_position: Vector2i`：任一坐标为负数表示“居中”；
- `open_window()`：有位置时 `popup(Rect2i(open_position, _popup_size()))`，尺寸取 `max(当前尺寸, 内容最小尺寸)`；置顶窗口先临时取消 `always_on_top` 再 popup，弹出后恢复；
- `_ready()`：禁止缩放、最小化、最大化；从 `user://Settings.cfg` 读取本窗口置顶状态；在顶部加 28px 置顶栏（右侧 T 按钮）；
- `_wrap_content()`：延迟到子类 `_ready()` 之后，把原内容挪到置顶栏下方，窗口高度 +28px，保证内容区尺寸不变；CanvasLayer 单独把顶层 Control 往下推；
- `set_pinned()` / `is_pinned()`：切换并持久化本窗口置顶；
- `close_requested` → `hide()`。

### 3.4 三个全局单例窗口

后加载的脚本通过静态变量拿单例，不依赖节点路径：

| 类 | 单例 | 关键接口 |
|---|---|---|
| `TooltipWindow` | `TooltipWindow.instance` | `show_tip(owner, layer, title, body := "")` / `hide_tip(owner)`；层级 `COORD < ITEM` |
| `InfoWindow` | `InfoWindow.instance` | `append_line()` / `clear_log()` / `toggle()` |
| `ItemWindow` | `ItemWindow.instance` | `hold(view, offset, base_size)` / `clear()` |

注意点：

- **TooltipWindow 的内容节点**：`Panel/Margin/VBox` 下是 `TitleLabel`（大字号标题行）和 `BodyLabel`（`RichTextLabel`，正文）。
  - 标题行显示魂灵名 / 物品名 / 战斗坐标；正文只有魂灵 tooltip 才有，由 `Windows/Tooltip/soul_tooltip.gd` 的 `SoulTooltip.build()` 生成，正文为空时隐藏 `BodyLabel`。
  - 正文开启 BBCode；`SoulTooltip.build(soul, true)` 按 `GameColors` 全局色板给灼烧 / 生命再生 / 剧毒 / 治疗 / 护盾 / 冻结 / 加速 / 减速 / 充能 / 伤害 / 暴击率上色，`[ 狼 ]` 这类方括号会转义成 `[lb]` / `[rb]`。
  - 窗口已改为 `borderless`，标题不再依赖原生标题栏，而是画在正文区的 `TitleLabel` 上，因此标题字号可以和正文分开调。
  - `show_tip(owner, layer, title, body := "")` / `hide_tip(owner)` 不是立即改 `visible`，而是记账到 `_process` 里统一结算，避免同一帧“先隐藏再显示”导致 OS 窗口闪烁；`body` 支持 BBCode。
  - `COORD` 是战斗窗口的格子坐标，`ITEM` 是物品/魂灵；低层级不能覆盖或隐藏仍然有效的高层级 owner。
  - `_place_near()` 默认在鼠标右下方，右边/下边放不下就翻边，再夹回屏幕内。
  - 标题、正文和位置只在值真的变化时才写。战斗窗口每个物理帧都会调 `show_tip`，鼠标停着时 `_place_tip` 也会每帧跑；文字没变就不改 Label、不 `reset_size()`，位置没变就不调 OS，避免布局重算和窗口管理器做无用功。
  - 当前用 `DisplayServer.screen_get_size()`，不是可用区域。
- **ItemWindow** 的 `_process` 每帧同步尺寸并跟随鼠标；`borderless` 让拖拽时的物品窗口没有标题栏。
- **InfoWindow** 的战斗日志来自 `BattleManager.log_sink`，由 `BattleWindow` 在开战时接上。

### 3.5 主窗口贴边

- `Scripts/setting.gd`：`_ready()` 根据 `DisplayServer.screen_get_usable_rect()` 把主窗口放到左下角。
- `Main/status_bar_container.gd`：`<` 左下角、`>` 右下角；`T` 切换主窗口 `always_on_top`，按下态在代码里覆盖成亮绿色；状态写入 `user://Settings.cfg` 的 `[window_pins]` 段，键 `main_window`（`WindowPinSettings.MAIN_WINDOW_ID`）。
- 偏移量都来自 `GameGlobal.WINDOWPOSOFFSET`（5px）。

### 3.6 窗口置顶

- 每个 `BaseWindow` 顶部单独一行 28px 放 T 按钮（`Windows/base_window.gd` 统一创建），原窗口内容整体挪到置顶栏下方；窗口高度增加 28px，内容区尺寸保持不变。
- BattleWindow 的 `CanvasLayer` 不参与 Control 布局：只把顶层 Control 的顶边向下推 28px，底部血条仍然贴窗口底部。
- 状态持久化到 `user://Settings.cfg`：

```ini
[window_pins]

character_window=true
main_window=true
```

- 键是 `BaseWindow.get_pin_key()`：默认取窗口脚本文件名（`character_window`、`equipment_window`、`inventory_window`、`battle_window`、`shop_window`、`collection_window`、`debug_window`、`info_window`、`mod_window`），主窗口用 `main_window`。节点改名不影响设置；脚本改名时在场景里显式填 `window_id`。
- 旧版节点名键（`CharacterWindow`、`MainWindow` 等）在首次读取时由 `WindowPinSettings.LEGACY_PIN_KEYS` 自动迁移到稳定 ID，并删除旧键。
- Windows 的硬限制：
  - 置顶窗口：`transient = false`、`always_on_top = true`，独立压住其他应用；
  - 未置顶窗口：`always_on_top = false`、`transient = true`，跟随主窗口，只在主窗口上方。
- `open_window()` 在弹出后重新应用置顶状态；窗口隐藏后再打开不会丢失。
- `TooltipWindow` / `ItemWindow` 没有 T 按钮，固定 `transient = true` 跟随主窗口，不再独立置顶。
- TestAPI 的 `set_window_pinned()` / `is_window_pinned()` / `get_window_pin_states()` 可以读写这些状态。

## 8. 场景与配置

### 8.1 `Main/control.tscn`

- 根节点 `Control`，挂 `control.gd`；
- `Setting` 节点挂 `setting.gd`，启动时贴左下角；
- `StatusBarContainer`：`<`、`T`、三个空按钮、`>`；
- `GridContainer`：人物、魂灵、仓库、商店、战！、见闻、调试、一个空按钮、Mod；
- 11 个窗口实例，初始都隐藏（部分在自身场景里设 `visible = false`，其余在 `control.tscn` 实例上隐藏）。

### 8.2 `BattleWindow`

- 窗口 1000×1100；场景默认位置 (0,36)，实际打开时由 `control.tscn` 的 `open_position` 覆盖为 (240,165)；
- `Tile` 位置 (490,475)，`GroundTileMapLayer` 是六边形图块，图块尺寸 32×32；
- 单位统一挂在 `Tile/Units` 下，和地图同一个坐标系；
- `CanvasLayer/Control` 里是顶部按钮栏和左下角生命/状态条：
  - `PlayerHealthBar`（220×18，距左 70、距底 12），中间显示当前/最大生命值，左侧有“生命”标签；
  - `PlayerRegenBar` / `PlayerShieldBar` / `PlayerBurnBar` / `PlayerPoisonBar`（220×18，从生命条上方依次向上排列），分别显示生命再生、护盾、灼烧、剧毒；
  - 四条状态条都是满条显示，中间显示当前数值，左侧分别有“再生”“护盾”“灼烧”“剧毒”标签；数值为 0 时隐藏；

## 9. 常见排查

1. **T 按钮置顶无效/窗口互相压不住**
   - Windows 不允许 transient 窗口置顶：置顶时必须 `transient = false` + `always_on_top = true`，取消时反向；
   - `TooltipWindow` / `ItemWindow` 固定 transient，不独立置顶；
   - 确认窗口走的是 `BaseWindow.open_window()`，它在弹出后会重新应用置顶状态。
2. **重启后置顶设置丢失**
   - 状态在 `user://Settings.cfg` 的 `[window_pins]`；键是 `get_pin_key()`，默认取窗口脚本文件名，主窗口固定 `main_window`；
   - 节点改名不影响键；脚本改名要在场景里显式填 `window_id`，否则会换键；
   - 旧版节点名键由 `WindowPinSettings.LEGACY_PIN_KEYS` 首次读取时迁移并删除旧键。
3. **窗口高度/内容错位**
   - 置顶栏会给每个 `BaseWindow` 增加 28px 高度，内容区整体下移；改窗口场景时保持内容区尺寸不变、窗口高度增加 28px；
   - BattleWindow 的 `CanvasLayer` 不参与 Control 布局，只把顶层 Control 的顶边向下推 28px。
4. **测试时读写置顶状态**
   - 用 `TestAPI.set_window_pinned()` / `is_window_pinned()` / `get_window_pin_states()`，不要直接改 `Settings.cfg`。
