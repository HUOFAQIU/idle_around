# AI 用量与成本优化（2026-11）

> 类型：指南 | 状态：有效
> 何时读：会话 token 消耗异常、准备跑长任务、要减少上下文/子代理开销
> 关键词：token 用量 上下文 缓存 工具表 子代理 effort 压缩 成本 转录
> 代码：—
> 相关：`指南/Claude Code 项目结构.md`（配置与加载）、`指南/代码检查.md`（提交前）；本页只记用量口径与优化动作
> 核对：2026-11-22

## 1. 口径

- 数据来源：`~/.claude/projects/<项目路径转写>/*.jsonl`；子代理在 `<会话目录>/subagents/*.jsonl`。
- 一条 `assistant` 记录的 `message.usage` 给出该次请求的 `input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`、`output_tokens`。`api-request-shape` 记录当次请求的系统提示与工具表。
- **按 `message.id` 去重**：同一请求按内容块会写成多条记录，不去重会多算 2～3 倍。分叉/恢复出的新 jsonl 共享同一批 `message.id`，去重后才是真实请求数。
- 加权有效 token：输入 1×、缓存读 0.1×、缓存写 2×、输出 5×。
- 固定开销：`shape.system` + `shape.tools` 字符数 ÷ 3.6，按每次请求 0.1× 计（它每轮都随上下文重读）。

## 2. 2026-11-22 实测（近 3 天）

| 指标 | 数值 |
|---|---|
| 唯一请求 / 子代理请求 | 1432 / 309 |
| 原始输入 / 输出 | 194M / 1.56M |
| 加权有效 | 34.5M |
| 缓存读占输入 | 98.7% |
| 平均上下文 | 135k |
| 固定开销 | 8.5M（25%） |

分组（占加权有效）：

| 组 | 占比 |
|---|---|
| 文件操作（Read/Edit/Grep 的结果与参数） | 22.8% |
| 模型输出（含思考） | 19.9% |
| 子代理 | 15.0% |
| 系统提示 + 内置工具 | 13.8% |
| Shell 命令 | 11.4% |
| MCP 连接器 | 11.2% |
| 对话输入 | 5.7% |

- 桌面端会话每次请求带 130 个工具定义（约 65k token）加系统提示，合计约 68–78k；CLI 会话只有 15 个内置工具，约 12k。
- 成本集中在少数对话：789 请求、约 5 小时的会话占 51%（含 12 个子代理）；平均上下文 263k 的会话占 18%；一条 243 请求的会话占 16%；三者合计 86%。

## 3. 优化动作

按杠杆排序；改动后用 §1 口径复测。

1. **长任务放 CLI 跑**：同样请求数，固定开销可从 8.5M 降到 2M 左右。桌面端留给看 diff、pane、浏览器这类交互。原因是桌面端 130 个工具定义每轮重发，CLI 只有 15 个。
2. **按需开 MCP 连接器**：MCP 合计 11.2%，单项最大是 `ccd_session_mgmt`（2.6%）；godot、terminal、scheduled-tasks、Browser 这类不用时关掉，godot 只在跑游戏时开。
3. **拆长会话**：按「调研 → 设计 → 实现 → 检查」分段，每段新开，只带当前需要的文件，不带整段历史。经验值：平均上下文每降 100k × 400 请求 ≈ 4M 有效 token。
4. **不重复整文件读**：先 Grep 定位再按段读；本会话已读过的文件不再重读。实测 3 天里 `DOC/INDEX.md` 被整读 18 次、`Scripts/test_api/battle.gd` 12 次、`DOC/指南/代码检查.md` 11 次。
5. **机械任务降 effort**：跑检查、批量改名、格式化用 low/medium；设计、排障再用 high/max。输出占 20%，其中思考是大头。独立于当前任务的机械活新开低 effort 会话跑（必要时换更便宜的模型），不必在本会话手动切档；与当前任务改同一批文件的仍留在本会话，避免两个会话同时写同一批文件。
6. **子代理只回结论**：要求返回「结论 + `file:line`」，不要长报告；一个 Explore 能覆盖的不拆多个。

## 4. 复查

- 临时分析脚本放仓库外（如系统临时目录），跑完删除，仓库内不留探针。
- 只看规模：统计各会话按 `message.id` 去重后的请求数，累加 `cache_read_input_tokens` 与 `output_tokens`。
- 看固定开销：取会话最后一条 `api-request-shape`，量 `shape.system[].text` 与 `shape.tools` 的字符数。
