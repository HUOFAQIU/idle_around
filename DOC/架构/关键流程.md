## 9. 关键流程串讲

### 9.1 敌人移动 → 触发型被动 → 持续伤害

```
敌方单位 MoveAbility 走一格
  → BattleUnit.move_to_cell()：cell 更新 + 发 moved
  → BattleManager._on_unit_moved() → unit_moved
  → 玩家 BattleUnit._on_battle_unit_moved()
      → 只处理 team = ENEMY 的单位
      → 遍历玩家的触发型被动（PassiveTrigger）
          → 对移动的怪物施加触发器配置的即时效果
          → 施加周期效果（例如灼烧）；数值由 trigger.magnitude 传入
  → 之后按周期效果的 period 结算：
      → execution 计算本跳的伤害/层数变化
      → periodic_effect_ticked 里按效果类型识别，写日志/飘字
      → 周期效果不会逐跳发 effect_received
```

### 9.2 Tooltip 与拖拽

```
鼠标进入物品格
  → InventoryView.grid_hover → ItemFocusService.focus_item
  → sig_item_focused → InventoryWindow 用 ITEM 层显示 TooltipWindow

鼠标离开
  → item_lose_focus → 本帧末确认 → sig_item_focus_lost → TooltipWindow.hide_tip(self)

拖拽
  → 左键拿起：物品从容器移除，ItemWindow（无边框、跟随鼠标）显示 ItemView
  → 左键放下：ContainerData.try_add_to_grid → sig_inv_item_added
```

- `ItemFocusService` 会把“失去焦点”延迟到本帧末再确认，避免物品跨多个格子时 tooltip 闪烁；拖拽中不切换焦点。
- 战斗窗口也会用同一个 TooltipWindow 显示格子坐标，但它只有在自己拥有焦点、且没有被更高层 owner 占住时才显示（`_update_coord_tooltip()`）。
- 魂灵窗口盖在战斗窗口上时，物品 tooltip 是 `ITEM` 层，战斗坐标是 `COORD` 层，战斗窗口的每帧调用不能覆盖或隐藏物品 tooltip。
- 战斗窗口判断鼠标是否在自己里面，用的是系统鼠标坐标 + 窗口 `Rect2i(position, size)`，因为每个 `Window` 是独立 OS 窗口。
