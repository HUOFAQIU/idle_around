# ADR 0002：文档采用单一权威节加指针

> 类型：记录 | 状态：有效 | 核对：2026-11-21
> 何时读：写或改文档、发现同一概念在多处重复时
> 关键词：ADR 文档 指针 单一权威 去重 INDEX 元数据 核对日期
> 代码：`tools/lint/index_meta.py`
> 相关：`INDEX.md`、`指南/代码检查.md`、`adr/0003-trigger-event-registry.md`

**决策状态**：已接受 · 2026-11-21

## 背景

同一份触发器事件清单曾散落在八篇文档里，每次新增事件都要逐篇同步，漏一处就产生矛盾；`INDEX.md` 清单也出现过指向已删除文档和日期漂移。文档越长、复制越多，维护成本越高。

## 决策

每个概念只保留一个完整定义处，其他文档只写自己的流程、排查示例和指针：

- 权威节负责事件、字段、派发规则等完整信息；引用方写「见 `某文档.md` §某节」，不复述清单。
- `INDEX.md` 只做需求路由和文档清单，不复制正文；清单行与文档头的类型、状态、核对日期保持一致。
- 文档头的核对日期随内容改动更新；跨文件一致性交给 `tools/lint/index_meta.py`，在 `check.sh --staged` 与 `--all` 中执行。
- 过期内容直接删除，需要追溯时用 git 历史。

## 后果

- 好处：改概念只改一处；引用方更短；日期和类型由脚本兜底，漏同步会变红。
- 代价：查完整信息可能多跳一次；权威节必须保持完整，否则引用方没有退路。
- 约束：新增文档要进 INDEX 清单；只有 `spec/README.md` 和 `adr/README.md` 这类目录入口进清单，单份 spec / ADR 不进。

## 替代方案

- 各文档自包含：读者少跳一次，但重复内容会漂移，已经被触发器清单验证过。
- 自动生成文档：当前文档量和结构不值得引入生成器，且会削弱手写「为什么」的部分。
