## 1. 测试

`TestAPI` 已暴露：`save_now()`、`load_save_slot(slot)`、`load_save_slot_raw(slot)`、`new_game(character_id)`、`delete_save_slot(slot)`、`click_cube_delete_save_slot(slot)`、`has_save()`、`get_save_slots()`、`get_active_slot()`、`get_game_flow_state()`、`get_save_path(slot)`、`get_save_status()`、`dump_save()`。

最小回归：

1. 用隔离的用户目录跑无头探针（Windows 可把 `APPDATA` 指到临时目录），避免写到真实 `user://`；
2. `TestAPI.new_game()` 创建第一个槽；断言 `get_game_flow_state().state == "IN_GAME"`、`get_active_slot() == 0`、`get_save_slots()[0].character_name == "小煤灯"`；
3. 游戏内再 `new_game()`，确认占下一个空槽，不覆盖槽 0；
4. 填满 6 槽后再点新游戏，确认状态不离开 `IN_GAME` 且 HUD 提示「角色已满」；
5. `load_save_slot(0)` 切回旧槽，确认活动槽和角色名正确；
6. 放魂灵/魂器 → `save_now()` → 清空容器 → `load_save_slot_raw(0)`，断言 ID 和左上角格一致；
7. 把主文件写坏，`load_save_slot_raw(0)` 应从 `.bak` 恢复；
8. 旧 v1 档放到 `slot_0.json`，启动后摘要显示小煤灯，读档后文件版本变 2；
9. 01 面删除：`click_cube_delete_save_slot(1)` 第一次只进入「确认」，第二次才删；活动槽的删除按钮应隐藏，直接调用返回 false。

无头探针的写法见 `.claude/skills/verify-godot/SKILL.md`：用临时场景加载 `Main/Cube/Scenes/main.tscn`，不要在 `--headless --script` 模式里引用 autoload 全局名。

## 2. 常见排查

按「症状 → 先看 → 常见原因」顺序查，先确认不是数据/容器问题，再怀疑代码。

1. **启动后没有进度/没有自动读档**
   - 这是新流程的预期：启动停在 01 面，选已有存档或点新游戏才会进 02。先看 `TestAPI.get_game_flow_state()` 和 `get_save_slots()`。
   - 如果 01 面显示全空但 `user://saves/` 有文件，检查槽文件名是否为 `slot_0.json`…`slot_5.json`，以及版本号是否可解析。
2. **读档后物品少了/位置变了**
   - 先看日志里的 `orphaned` 与容器 warning：ID 不在 `CollectionDB`、容器名对不上、格子被占都会走到这里；
   - 核对场景 `container_name` 与 `Scripts/container_ids.gd` 是否一致；
   - 读档前容器必须已注册（启动等一帧），手动读档不要在战斗/拖拽中调用。
3. **进度回退到旧存档**
   - 主文件解析失败时会读 `.bak`；先看对应槽的 `slot_N.json` 与 `slot_N.json.bak` 时间戳；
   - 从备份恢复后的第一次写盘会保留好备份（`_keep_backup_next_save`），排查时不要手动删 `.bak`。
4. **主文件和备份都读不出**
   - JSON 整体损坏或存档版本高于当前游戏时不会覆盖原文件；用 `TestAPI.get_save_path(slot)` / `dump_save()` 定位，必要时 `delete_save_slot(slot)` 后重开；
   - 主文件和备份都无法解析的槽在摘要里按空槽处理；点新游戏会覆盖它，旧主文件在写盘时轮换成 `.bak`，不会静默删除；
   - 版本高于当前游戏的槽可正常读取，但切档/新游戏会跳过保存并提示「当前存档只读，进度不会保存」；
   - `--script`/工具模式没有主场景，`SaveManager` 不读也不写，别在工具模式里判断存档坏了。
5. **新增物品类型读不回来**
   - `SaveCodec` 目前编码 `kind = "soul"` 和 `kind = "vessel"`；新类型要补 kind 分支和反序列化，没有该段按空处理。
6. **日志提示“容器未注册”/自动写档被禁用**
   - 启动后看 `TestAPI.get_save_status()` 的 `missing_containers`；正常主场景应为空数组；
   - 常见原因是主场景没有加载立方体外壳（`Main/Cube/Scenes/main.tscn`）、`Main/control.tscn` 没有作为 GameUI 覆盖层实例化、角色窗口未实例化（`vessel_cells` 未注册），或场景 `container_name` 被改名；
   - 此时 `read_only=true`，不读档也不写档；补齐容器后重启。
7. **01/04 面锁状态不对**
   - 看 `GameFlow.get_face_lock_state(1/3)` 和 `TestAPI.get_cube_layering_state().input_ready`；
   - 锁状态只由 `GameFlow` 状态决定，`main.gd` 在 `state_changed` 时统一写给六个 `Face3D`；不要单独在面内容里改 `ui_capture`。
8. **切档后旧数据还显示**
   - `GameFlow` 在切档前先取消拖拽并发 `session_will_change`；`main.gd` 关闭所有面板并停战斗。若仍有旧数据，检查是否有面板没登记到 `PanelManager`，或直接调了 `SaveManager.load_slot()` 绕过流程。
9. **删档后状态不对**
   - 正常 UI 只能删非活动槽：删除按钮是两段式，第一次点变「确认」，第二次才发 `delete_requested`；活动槽显示 ACCENT 绿底、不显示删除按钮，`GameFlow.request_delete_slot()` 也会拒绝。
   - 删活动槽只能走 `TestAPI.delete_save_slot(slot)`；此时 `GameFlow` 监听 `SaveManager.active_slot_changed(-1)` 回到 `NO_SESSION`/01 面。如果还停在 02 面，检查 `GameFlow._ready()` 是否连接了该信号。
   - 删档后 01 面没刷新，检查 `SaveManager.delete_slot()` 是否调了 `refresh_slot_summaries()`，以及 `slot_list_changed` 是否接到 `GameFlow.slots_changed`。
