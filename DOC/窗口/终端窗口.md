终端目前是“字符网格渲染 + 固定屏幕缓冲”的显示层，主界面「终端」按钮打开 `TerminalWindow`，内容区铺满 `TerminalView`；底部输入行接 `CommandRegistry`，ANSI SGR、单行调试命令和 Tab 补全已接入。

## 1. 分层

数据层在 `Scripts/terminal/`（调色板、单格样式、近似 wcwidth 的宽度、ANSI 流式解析、字符缓冲与行环历史、跨格大字描述），渲染在 `Windows/Terminal/terminal_view.gd`；窗口壳与补全浮层同在 `Windows/Terminal/`，`terminal_preview.tscn` 是独立 demo。各文件职责以文件头为准。

写入路径：外部 → `TerminalView.write_line()` / `write_ansi()` → `TerminalBuffer` → `queue_redraw()`。ANSI 解析在独立 Parser 里，Buffer 和 View 都不认识转义文本；输入也应该做成独立中间层。

## 2. 已实现

能力清单以 `Scripts/terminal/` 的公开 API 为准：`TerminalBuffer`（网格、行环形缓冲、CJK 双宽、历史）、`TerminalAnsiParser`（SGR）、`TerminalHistory`、`TerminalView`（渲染、光标、跨格大字、调试网格）。主终端窗口、Tooltip 正文、内嵌信息窗共用这一套，`TerminalWindow` 只做窗口壳与输入转发。

- 调色板是 16 色 ANSI，颜色值与参考网页 how-terminals-work 一致，登记在 `GameColors`；工具提示正文由 `SoulTooltip` / `VesselTooltip` 的 PLAIN 文本经 `TooltipWindow` 转 ANSI。
- 跨格大字（`TerminalSpan`）是 View 级装饰：不进 Buffer/历史、不参与光标与选中，多格大字只能走 `TerminalView.set_spans()`。
- 调试命令与补全统一走 `CommandRegistry`，命令表与候选来源见 `指南/命令控制台.md`。
- 独立预览场景用于看网格与跨格大字，和主终端共用 `TerminalView`。

实现约束：

- Packed 数组按引用传递；`resize()` 前必须 `duplicate()` 旧数组，否则旧数组会被一起改掉。
- `_allocate()` 内部的 `clear()` 会把光标归零；resize 后要恢复原光标并按新尺寸夹紧。
- 1 列终端放不下双宽字符时退化为单宽；双宽字符只剩最后一格时先换行，不能把续格拆到下一行。
- Buffer 写入时复制颜色和属性，不保存 `Style` 引用；调用方可以复用同一个 `Style` 对象逐行改色。
- `TerminalHistory` 的哨兵值与 Buffer 数值一致，但单独定义，避免两个类互相引用。
- 光标下的字符要反色再画一遍，否则会被背景色块盖住。
- 调试网格最外圈向内收 1px，避免被 `clip_contents` 裁掉；跨格大字内部的分隔线跳过。
- 跨格大字按一行处理，换行替换成空格，避免测量和绘制错位。
- 历史/程序化改文本时不要自动弹补全。
- 点输入框会移动光标，旧候选的 token 区间失效，接受前要校验。
- 调试命令：底部 `LineEdit` 提交后调 `CommandRegistry.run()`，回显 `> 命令`，成功输出 `OK`/JSON，失败输出红色 `ERR` + usage；上下键翻历史。终端和 AI 探针共用同一套命令，命令表与扩展步骤见 `指南/命令控制台.md`。
- 命令补全：输入时自动调 `CommandRegistry.complete()`，命令名和参数候选来自 `command_catalog.gd`；当前 token 是唯一完整匹配时自动收起，空输入按 Tab 列全部命令。`CompletionPanel` 显示在输入框上方，顶部一行显示当前命令的 usage + summary；上下键选择、Tab/鼠标接受、Enter 执行输入、Esc 关闭。列表打开时上下键不再翻历史；带引号的 token 不补全。

## 3. 已知限制

- 组合字符（宽度 0）目前直接跳过，带重音的拉丁文字、阿拉伯文组合等会丢失附加符号。
- emoji ZWJ 序列、区域旗帜等复合字形没有组合渲染；每个码点仍按独立字符处理。
- 中文字体依赖系统：当前自动找 Microsoft YaHei UI 等，换机器或系统没有这些字体时中文仍会缺字；还没有打包可分发字体。
- ANSI 只支持 SGR；CSI 光标移动/擦除/备用屏目前整段忽略，冒号子参数和 dim/italic/blink/strikethrough 未实现。
- 回看历史默认 1000 行，超过后丢最旧行；`scrollback_lines = 0` 可以关闭历史。
- 终端按列硬换行，不做英文单词级 word wrap；长单词会被拆开。
- 滚到历史时光标隐藏；上翻后新内容不会自动拉回底部（`auto_scroll = false`）。
- 命令输入只有单行，没有多行编辑和粘贴处理；没有选区复制；`TerminalWindow` 和 `InfoWindow` 也没有滚动条，回看历史只能用滚轮。
- 补全只覆盖已登记的参数位置；容器名、当前战斗单位名等运行时候选还没接入；带引号的 token 不补全；输入框没有 MC 那种命令文本着色。
- 终端正文使用统一 cell 字号；Tooltip 的冷却行用粗体代替 20 号字。标题用 `TerminalSpan` 按 2 行高临时放大，字号不是固定 24 号。
- `TerminalSpan` 只是 View 级装饰：不进入 Buffer/历史，不参与选中复制；ANSI 也没有纵向跨格标准，所以多格大字只能走 `TerminalView.set_spans()` 专用 API，`TooltipText.ANSI` 仍然只负责正文。
- 每次写入/光标闪烁仍整屏重绘；当前没有脏行裁剪。
- 没有备用屏幕、鼠标上报、能力探测，也没有 PTY；这些只有做“真终端模拟器”才需要。

## 4. 功能路线

### 定位（2026-11-14 调整）

终端定位为**游戏内内容的显示载体 + 调试命令前端**：显示层类似 `TooltipWindow` / `InfoWindow`；底部单行输入接 `CommandRegistry`，命令实现不在窗口里。raw 模式、备用屏、多行 TUI 暂缓。

首用方向确定为**通用显示 API**（滚动回看、自动滚底、set/append 内容）；Tooltip 的 ANSI 输出和战斗日志（`InfoWindow`）已接入，其他内容来源待定。

已完成（2026-11-14）：CJK 双宽 + 系统中文字体 fallback、ANSI SGR、回看历史 + 自动滚底、显示 API、Tooltip ANSI 适配、战斗日志 InfoWindow 终端化。

### P0：显示载体

1. **内容适配层**
   - Tooltip（已完成）：`TooltipText` 增加 ANSI 序列化，终端不解析 BBCode；`TooltipWindow` 正文已换成内嵌 `TerminalView`，仓库/见闻悬停直接按字符网格显示，标题用顶部跨格大字；`TestAPI.terminal_show_soul_tooltip()` / `terminal_show_vessel_tooltip()` / `terminal_show_equipped_vessel_tooltip()` 可把同样内容写进终端窗口。
   - 战斗日志（已完成）：`BattleLogAdapter` 仍把 `(text, color)` 交给 `InfoWindow.append_line()`；`InfoWindow` 正文是 `TerminalView`，保留原窗口、☰ 开关和 600×428 尺寸。日志在窗口隐藏时写入 500 行缓冲，打开时重建到终端，可见时直接追加；颜色用 `Color.from_string()` 转 `TerminalStyle.fg`，终端底黑、光标和调试网格关闭。
   - 纯文本/ANSI：`set_content` / `set_ansi_content` / `append_line` 直接可用。
2. **排版约定**
   - 终端按列硬换行；长英文单词、宽字符由内容适配层处理，不做自动 word wrap。
   - 标题/分隔线/缩进由内容适配层拼，不塞进 Buffer。

### P1：体验

3. **选中复制**
   - 鼠标拖选记录起止 cell，渲染器画半透明选区，`DisplayServer.clipboard_set` 复制；宽字符按两格处理。

## 5. 性能路线

行环形缓冲和历史行环已完成。历史 push 每行 O(cols)，和清空新底行同量级；默认 1000 行在 90 列下约 3.3 MB（每格 4 + 16 + 16 + 1 字节）。历史实测（本机 GTX 1060 / GL Compatibility 时期 / 关闭 vsync；现已切 Forward+，数值需重测）：

| 场景 | 结果 |
|---|---|
| Buffer 120×42 连写 2000 行 | 168 ms，84 µs/行（行环前 1195 ms，598 µs/行） |
| Buffer 192×56 连写 2000 行 | 205 ms，102 µs/行 |
| 1200×800 整屏重绘 | 约 2.3 ms |
| 1920×1080 整屏重绘 | 约 3.6 ms |
| 900×600 游戏内终端（约 90×29） | 约 1.5 ms/帧 |

结论：900×600 面板 60fps 够用；1080p 满屏约 3.6 ms 还能接受；4K 全屏约 13 ms，需要继续优化。

剩余优化按收益排序：

| 优先级 | 优化 | 预计收益 | 何时做 |
|---|---|---|---|
| 1 | 按样式 run 画字：同色/同样式连续 cell 合并成 `draw_string`/`TextLine` | 1080p 3.6 → 1.5–2 ms；4K 13 → 5–6 ms | 全屏/4K |
| 2 | 脏行重绘：每行一个绘制层或行缓存 | 单行追加 3.6 → 0.1–0.2 ms | 高频日志/滚动 |
| 3 | ASCII 快速写入：`to_ascii_buffer()` + 内联写格 | 84 → 25–40 µs/行 | 每秒几百行以上 |
| 4 | 紧凑 cell 存储：样式表 + 每格样式索引 | 内存减半，缓存更好 | 4K/大 scrollback |
| 5 | 光标独立层 | 每 0.5 秒省 2–3.6 ms | 锦上添花 |
| 6 | MultiMesh / 字形图集 | 4K 60fps 轻松 | 只做真终端模拟器时 |

## 6. 测试

- 预览：F6 运行 `Windows/Terminal/terminal_preview.tscn`；可看 16 色、粗体/下划线/反显、ANSI 颜色、打字、滚动、resize、网格线/悬停。样例里有“中文双宽：终端字符网格”“混合 mixed 中文 123 ABC”和一行 ANSI SGR 示例。点「滚动测试」写 40 行，再用滚轮往上翻历史，点「回到底部」恢复。
- 游戏 UI：`Main/control.tscn`（主视口覆盖层）里 `TerminalWindow` 默认隐藏，主界面「终端」按钮打开（900×628，内容区为 `TerminalView` + 30px 输入行，约 90×29，行列随窗口尺寸和字体变化）；欢迎语本身是中文，可直接检查双宽对齐。外部可调 `TerminalWindow.set_content()` / `append_line()`，窗口还没布局时会先缓存。
- Tooltip 正文：仓库/见闻悬停魂灵或魂器时，`TooltipWindow` 的 `BodyTerminal` 会按内容自动计算行列并显示调试网格；标题是同一个终端顶部的 2 行高 `TerminalSpan`（下划线画在块底部），正文从第 2 行开始。`tooltip_snapshot()` 的 `spans` 可检查标题实际占的格子矩形。
- 战斗信息窗：战斗窗口左上角 ☰ 打开 `InfoWindow`（600×428），正文是 `TerminalView`（60×21，光标/调试网格关闭）。窗口隐藏时日志写入 500 行缓冲，打开时重建；`TestAPI.get_battle_log()` 读同一份缓冲，不是终端上当前可见的几行。
- TestAPI：`terminal_write_line(text)`、`terminal_write_ansi(text)`、`terminal_set_content(text)`、`terminal_set_ansi_content(text)`、`terminal_scroll(lines)`、`terminal_scroll_to_bottom()`、`terminal_clear()`、`terminal_set_grid(enabled)`、`terminal_snapshot()`、`complete_command(line, caret := -1)`、`tooltip_snapshot()`；终端快照返回 `{cols, rows, cell, cursor, history, view_offset, auto_scroll, spans}`，Tooltip 快照返回 `{grid, debug_grid, body_visible, tooltip_size, spans}`。
- 补全：`TestAPI.complete_command(line, caret)` / `CommandRegistry.complete()` 返回 `{start, end, prefix, token_index, candidates, common_prefix, usage, summary}`；终端里输入 `ba` 会自动出现命令候选，输入 `soul.add ` 会自动出现参数候选和语法抬头。
- Tooltip 显示：`terminal_show_soul_tooltip(id, equipped := false, grid := true)`、`terminal_show_vessel_tooltip(id, grid := true)`、`terminal_show_equipped_vessel_tooltip(slot := 0, grid := true)` 会把标题 + ANSI 正文写进终端并打开窗口，`grid` 默认打开调试网格；对应纯 ANSI 文本由 `get_soul_tooltip_ansi()` / `get_equipped_soul_tooltip_ansi()` / `get_vessel_tooltip_ansi()` / `get_equipped_vessel_tooltip_ansi()` 返回。
- 无头探针注意：headless 主视口可能只有 64×64，`BaseWindow` 会把终端窗口夹小；验证真实尺寸时把 `Main/control.tscn` 放进 1600×960 的 `SubViewport`（或在探针里设置主窗口尺寸）。
- 直接运行预览场景会触发 `SaveManager` 的只读警告（不是主场景，`vessel_cells` 未注册），不写存档，忽略即可。

## 7. 常见排查

| 现象 | 检查点 |
|---|---|
| 中文不显示/错位 | 先看 `TerminalView.cjk_font` 是否找到系统字体（Microsoft YaHei UI / Noto Sans CJK SC 等）；再检查 `TerminalWidth.columns()` 是否返回 2，以及续格是否在写入/覆盖/resize 时被清掉 |
| ANSI 颜色不生效/原样显示 | 确认用 `write_ansi()` / `write_ansi_line()` / `TestAPI.terminal_write_ansi()`，而不是 `write_text()`；目前只解析 SGR，其他 CSI 会被整段吞掉 |
| 终端窗口很小/网格只有几列 | 视口是否异常小；`BaseWindow` 会用 1600×960 兜底，但 headless dummy 视口可能是 64×64 |
| 写入后不刷新 | 确认走 `TerminalView.write_line()`/`write_text()`/`write_ansi()`，不要直接改 Buffer 数组 |
| 滚动后内容错位 | 读逻辑行必须用 `TerminalBuffer.get_row_base(row)`，不能再用 `row * cols` |
| 滚轮没反应 | `TerminalView.mouse_filter` 不能是 `IGNORE`；预览里的 DebugOverlay 用 `PASS` 把滚轮让给父级；history 为 0 时也没有历史可翻 |
| Tab 没反应/候选为空 | 命令名是否已补全；参数位置是否在 `command_catalog.gd` 的 `complete` 数组登记；当前 token 是否带引号；内容（mod/存档）是否已加载 |
| 上翻后新内容把视图拉回/停不住 | 检查 `auto_scroll`；`write_*` 在 `auto_scroll=false` 时会按新增行数抬高 `view_offset`，回底部用 `scroll_to_bottom()` |
| 历史行丢失 | 默认上限 1000 行，超过丢最旧行；改 `TerminalView.scrollback_lines` 或设 0 关闭历史 |
| 滚到历史后看不到光标 | 设计如此：`view_offset > 0` 时隐藏光标 |
| Tooltip 文本行首被覆盖/冷却行没加粗 | 文本里是否带 `\r`；`TooltipText` 会统一 CRLF → LF，绕过它自己拼 ANSI 时要先处理换行 |
