## 1. 一套入口

`CommandRegistry.run(line) -> {ok, value, error}` 是唯一入口。游戏内终端和 AI 探针都调它，命令实现只写一份。

- 终端：只负责输入行、回显和格式化显示。
- AI：直接读 `value` / `error`，不解析终端渲染文本。
- 实现：`scripts/commands/actions/` 调 `scripts/test_api/` 的域模块，不复制业务逻辑。
- 补全：`CommandRegistry.complete(line, caret)` 读同一份命令表，终端和 AI 共用。

## 2. 游戏内使用

主界面「终端」按钮打开 `TerminalWindow`，底部输入行回车执行。

```text
> help
> help battle.start
> soul.list
> battle.start forest_map
> battle.state
```

- `help [command]` 列出全部命令或查看单条 usage。
- 输入时自动弹出候选和语法抬头；Tab 补全，Enter 执行输入框里的命令。
- 上下键翻命令历史（候选列表打开时改为选候选）；`clear` 清屏。
- 成功：`OK` + 标量/JSON；字符串类命令（`help` / `echo`）直接输出文本。
- 失败：`ERR` + 原因，并附 `usage:` 提示。

## 3. 补全与预览

输入行按 MC 的方式工作：输入时自动列出下一步能填的内容，候选浮层显示在输入框上方。

| 操作 | 行为 |
|---|---|
| 继续输入 | 自动刷新候选；当前 token 已是唯一完整匹配时自动收起 |
| 空输入 | 不自动弹；按 Tab 列出全部命令 |
| Tab（列表已打开） | 接受当前候选 |
| Tab（列表关闭） | 唯一候选直接补全；多候选先补公共前缀再列出 |
| Enter | 始终执行输入框里的命令，不会接受候选 |
| 上下键（列表已打开） | 在候选中移动；列表关闭时仍是历史 |
| Esc | 关闭候选，不改输入 |
| 鼠标单击 / 滚轮 | 接受候选 / 翻候选 |

候选上方会显示当前命令的 `usage` 和 `summary`，例如 `battle.spawn <monster_id> — 立刻刷一只怪`；命令名阶段不显示。

命令名补全取命令表 `command_catalog.gd::command_names()`；参数按 token 位置读命令表里的 `complete` 数组。带引号的 token 不补全。

候选来源在 `scripts/commands/command_completers.gd`；哪条命令的哪个参数有候选，看 `command_catalog.gd` 里该命令的 `complete` 数组。容器名候选来自 `TestAPI.get_container_names()`，内容 ID 来自 `TestAPI` 的域模块。

## 4. AI / 探针

```gdscript
var result := CommandRegistry.run("battle.start forest_map")
if not result.ok:
    push_error(result.error)
var state: Dictionary = CommandRegistry.run("battle.state").value
var soul_ids: Array = CommandRegistry.run("soul.list").value
```

`run()` 返回 `{ok: bool, value: Variant, error: String}`；`value` 是原生 Variant，不需要再解析终端的 ANSI/换行。

补全用 `CommandRegistry.complete(line, caret = -1)`，返回 `{ok, start, end, prefix, token_index, candidates, common_prefix, usage, summary, error}`；`caret` 为负时按行尾处理，`usage`/`summary` 只在参数阶段有值。AI 探针也可用 `TestAPI.complete_command()`。

```gdscript
var suggestion: Dictionary = CommandRegistry.complete("soul.add ch", 11)
var candidates: PackedStringArray = suggestion.candidates
```

## 5. 参数规则

- 空格分隔，命令名用 `domain.action`。
- 带空格的文本用单/双引号：`echo "hello world"`。
- 反斜杠转义引号。
- P0 只支持位置参数；复杂数组/字典参数在 P1 加 JSON 字面量（如 `mod.order ["core","example_souls"]`）。

## 6. P0 命令

命令名、参数和 usage 以 `scripts/commands/command_catalog.gd` 为准；`help` 与补全抬头直接读这份元数据，本文不再抄表。当前覆盖 `help` / `clear` / `echo`，以及 `battle.*`、`soul.*`、`vessel.*`、`map.*`、`save.*`、`cube.state`、`debug.state`。

## 7. 扩展命令

1. 在 `scripts/commands/actions/<domain>_actions.gd` 写 handler，参数用 `PackedStringArray`，返回 `CommandResult.ok(value)` / `CommandResult.fail(error)`；业务逻辑调 `scripts/test_api/` 对应域模块。
2. 在 `scripts/commands/command_catalog.gd` 登记 `usage`、`summary` 和 `handler`；`help` 和补全抬头直接读这份元数据。
3. 需要参数补全时，在 `scripts/commands/command_completers.gd` 加候选方法，再在命令的 `complete` 数组里按参数位置登记 `Callable(COMPLETERS, "方法名")`；没登记的位置不补。
4. 只有新增域或命令入口语义变化时才更新本文；命令清单由 `help` 直接反映。
5. 跑 `tools/check.sh --all`；需要的话用临时探针调 `CommandRegistry.run()` / `complete()` 验证。
6. 只在终端显示用的格式化逻辑放 `terminal_window.gd` / `command_formatter.gd`，不要塞进 handler。

## 8. 常见排查

- **未知命令**：确认命令在 `command_catalog.gd` 注册，`help` 能看到；第三方内容 id 用 `soul.list` / `vessel.list` / `map.list` 查。
- **Tab 没反应**：当前 token 没有候选；确认命令名已补全、参数位置在 `complete` 数组里登记，且当前 token 不带引号。
- **候选列表为空**：对应内容没加载（mod/存档）；先跑 `soul.list` / `map.list` 确认数据存在。
- **参数不足 / 不是整数**：错误里带 `usage:`，按提示补参数；P0 不支持 JSON 数组。
- **`battle.start` 失败**：先确认地图资源存在、`BattleWindow` 已创建；终端窗口打开不影响开战。
- **`save.new` 失败**：流程状态不对；先从主菜单新游戏，或用 `save.load` 读已有槽。
- **headless 看不到终端**：直接调 `CommandRegistry.run()`；终端 UI 只负责显示，命令逻辑不依赖它。
- **写档**：headless/自动化测试把 `APPDATA` 指到临时目录，避免写真实 `user://`；完整流程见 `指南/AI测试接口.md`。
