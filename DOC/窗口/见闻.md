# 见闻 CollectionWindow

> 类型：实现 | 状态：已实现 | 核对：2026-11-04
> 何时读：改见闻窗口、解锁规则、怪物/魂灵图鉴
> 关键词：见闻 图鉴 解锁 CollectionDB registry soul monster tooltip 放入仓库 筛选
> 代码：`Scripts/collection_db.gd`、`Windows/Collection/`、`game/content/Collection/`
> 不覆盖：掉落规则（见 `怪物/怪物.md`）

这个窗口用来展示已遇见的怪物和魂灵；条目网格是窗口主体，右侧预留筛选区。

## 数据来源

| 层 | 位置 | 说明 |
|---|---|---|
| 清单 | `game/content/Collection/soul_registry.tres` | YARD registry；扫 `game/content/Souls/` 下 `*_soul.tres` |
| 清单 | `game/content/Collection/monster_registry.tres` | YARD registry；扫 `game/content/Monster/` 下 `*_data.tres` |
| 数据 | `SoulData` / `MonsterData` | 魂灵 tooltip 正文在 `SoulData.tooltip_blocks`；怪物数据在 `game/content/monster_data.gd` |
| 索引与状态 | `Scripts/collection_db.gd`（Autoload `CollectionDB`） | 运行时加载 registry、记录已遇见、写存档 |

## 解锁规则

- 怪物：战斗里**首次刷出**即记录（`BattleWindow._spawn_enemy()`）；
- 魂灵：**首次进入背包**即记录（监听 `GBIS.sig_inv_item_added`）；
- 状态存 `user://collection.cfg`，键是 registry 字符串 ID（文件名去后缀，如 `snake_data`、`xiao_lu_soul`）；
- `CollectionDB.unlock_all_for_testing` 默认 `false`：按真实进度显示；调试窗口“设置”页或 `TestAPI.set_unlock_all()` 可临时切换成全解锁。该开关只影响显示、不写存档；已打开的见闻窗口需要切页签/重开才会刷新。

## 界面

- “怪物 / 魂灵”两页；未遇见条目占位显示 `？？？`，不暴露名字和图标；
- 条目只有图标和名字，窗口不再有详情面板；
- 魂灵页的已遇见条目：悬停显示与仓库窗口一致的 tooltip（标题 + `SoulTooltip.build()` 正文，层级 `TooltipWindow.Layer.ITEM`）；未遇见条目不显示；
- 魂灵页的已遇见条目：右键放入 `inventory_0`（仓库窗口），每次一颗；放入后走正常入包流程；成功时从条目图标播放一个向右的抛物线动画（纯视觉反馈，失败不播）；窗口底部固定提示「右键已遇见魂灵：放入仓库」；
- 怪物页不显示 tooltip，也不响应右键；
- `Root/VBox/Body/FilterPanel`（240 宽、空容器）预留给后续筛选功能。

## 注意

- registry 的 `.tres` 要提交到 git；新增/删除资源后由编辑器里的 YARD 扫描自动同步；
- registry `.tres` 自身必须带合法 `uid`（YARD 用 UID 作为编辑器打开状态的键），手工生成资源时容易漏；
- `GBIS.add_item()` 会 `duplicate()` 物品，副本没有 `resource_path`，所以魂灵解锁按 `item_name` 反查 registry ID；
- 怪物数据抽成 `MonsterData` 后，战斗场景只负责战斗表现，刷怪时由 `_spawn_enemy()` 把数据注入 `BattleUnit`。
