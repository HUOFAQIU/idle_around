## 1. 关键流程串讲

本节只串流程；事件定义、payload 和派发规则见 `架构/战斗数据与魂灵.md` §魂灵触发器。

### 1.1 敌人移动 → 魂灵触发器 → 持续伤害

> 实时制下，怪物在角色攻击范围外不会跑 `BattleBrain`，魂灵不开始冷却；进入范围后才会施放（见 `战斗运行时_施法与冷却.md`）。

```
BattleManager._physics_process() 驱动敌方单位朝角色直线移动（按实例 ID 分片，每物理帧约 200 个移动体；≤200 只时逐物理帧移动）
  → 跨入新地图格时更新 BattleUnit.cell 并发 moved（from_cell/to_cell）
  → BattleManager._on_unit_moved() 只派发给注册了 UnitMoved 触发器的单位
  → BattleUnit.on_enemy_moved()
      → 只处理与自身不同阵营的移动单位
      → ASC.send_gameplay_event(Event.Movement.UnitMoved, {target, trace})
          → ASC 找到 trigger_event_tag 匹配的 SoulTriggerAbility 并 try_activate()
              → 按 target_scope 选事件目标/自己/全体敌人
              → 施加触发器配置的即时效果
              → 施加周期效果（例如灼烧）；数值由 trigger.magnitude 传入
              → charge_source_seconds > 0 时给来源魂灵充能
                  → 充满则 BattleBrain.request_activation() 入队，当帧末统一释放
  → 之后按周期效果的 period 结算：
      → execution 计算本跳的伤害/层数变化
      → periodic_effect_ticked 里按效果类型识别，写日志/飘字
      → 周期效果不会逐跳发 effect_received
```

### 1.1b 生命值低于阈值 → 冻结 → 逐只充能

```
伤害/治疗改变单位 health
  → ASC.attribute_changed
  → BattleUnit._on_attribute_changed()
      → health <= 0：排队死亡
      → 否则 _check_health_triggers(old, new)
          → ASC.send_gameplay_event(Event.Health.BelowPercent, {ratio, trace})
              → SoulTriggerAbility 检查 ratio < threshold_ratio；once_per_battle 只触发一次
              → target_scope = ALL_ENEMIES：对每个存活敌人施加 freeze_unit.tres
                  → 获得 State.Frozen + Cue.Status.Freeze，默认持续 1 秒
                  → 向所有与目标敌对、且带 FreezeApplied 触发器的单位发送 Event.Combat.FreezeApplied
                      → 带该触发器的魂灵按 charge_source_seconds 逐只充能
                          → 充满则入待释放队列，当帧末同帧释放（受 20 刻激活锁限制）
  → 冻结期间 BattleBrain 不充能、不释放；解冻后按当前加速/减速速率继续
```

减速走同一套监听者注册表：`ChargedAbility.apply_slow()` 发 `status_applied` → 所属单位 `BattleUnit.notify_slow_applied()` → 向与该单位敌对、且带 `Event.Combat.SlowApplied` 触发器的单位派发，payload 的 `target` / `source` 都是被减速单位。

### 1.2 Tooltip 与拖拽

```
鼠标进入物品格
  → InventoryView.grid_hover → ItemFocusService.focus_item
  → sig_item_focused → TooltipWindow 用 ITEM 层显示提示
      → 魂灵：SoulTooltip.build() 生成正文，标题用 TerminalSpan 大字 + 正文一起显示
      → 魂器：VesselTooltip.build() 生成正文，标题同样走 TerminalSpan
      → 其他物品：只显示标题（标题也由 BodyTerminal 的 span 绘制）

鼠标离开
  → item_lose_focus → 本帧末确认 → sig_item_focus_lost → TooltipWindow.hide_tip(self)

拖拽
  → 左键拿起：物品从容器移除，ItemWindow（无边框、跟随鼠标）显示 ItemView
  → 左键放下：ContainerData.try_add_to_grid → sig_inv_item_added
```

- `ItemFocusService` 会把“失去焦点”延迟到本帧末再确认，避免物品跨多个格子时 tooltip 闪烁；拖拽中不切换焦点。
- 魂灵 tooltip 的正文由 `windows/Tooltip/soul_tooltip.gd` 统一格式化：尺寸/类型行 → 暴击率 / 攻击距离 → 技能段 → 每条触发段，段间固定 `===================================`；没有文案的魂灵显示头部 + `无`。魂器 tooltip 由 `windows/Tooltip/vessel_tooltip.gd` 生成，效果文案后接内部魂灵文字网格；两者共用 `TooltipText` 的着色/转义。状态词（灼烧、生命再生等）按 `GameColors` 全局色板着色；正文控件是 `TooltipWindow` 内嵌的 `TerminalView`，`TooltipWindow` 把纯文本转成 ANSI，冷却行用粗体代替大字号。
- 战斗窗口也会用同一个 TooltipWindow 显示格子坐标，但它只有在战斗面板是激活面板、且鼠标下最上层是它时才显示（`PanelManager.is_active()` + `get_top_panel_at()`，见 `_update_coord_tooltip()`）。
- 仓库 / 见闻窗口盖在战斗窗口上时，物品 / 魂灵 tooltip 是 `ITEM` 层，战斗坐标是 `COORD` 层，战斗窗口的每帧调用不能覆盖或隐藏上层 tooltip。
- 战斗面板判断鼠标是否在自己里面，用 `get_global_rect().has_point(get_global_mouse_position())`；面板都在主视口的游戏 UI 覆盖层里，这两个接口使用主视口坐标。
