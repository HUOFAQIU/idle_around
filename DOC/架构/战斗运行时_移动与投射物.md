## 1. 移动与投射物

### 1.1 实时移动与攻击范围门控

战斗已从格子制改为即时制：

- `BattleUnit` 是 `CharacterBody2D`，碰撞体形状由场景决定（玩家圆形半径 14，怪物胶囊），怪物之间/怪物与角色之间会互相阻挡。
- 移动不再走 `MoveAbility` / `HexStep`：`BattleManager._physics_process()` 统一驱动敌对单位朝角色直线移动。
  - 按 `get_instance_id() % slices` 分片：`slices = max(1, ceil(怪物数 / 200))`，每帧最多驱动约 200 个移动体。怪物 ≤200 时逐物理帧移动（60Hz），200～400 时 30Hz，依此类推；速度设为 `move_speed × slices` 补偿。
  - 距离 ≤ `attack_range`（默认 30px，约一格）就停下，并开启该单位的 `BattleBrain`；
  - 离开范围（理论上角色不动，只有被挤出时）再关掉。
- **门控**：怪物的魂灵冷却只在角色进入其攻击范围后才开始。范围外的怪大脑物理帧被关闭，`charge_units` 保持 0；进范围后从 0 开始按正常速率充能。
- **冻结**：单位级冻结（`State.Frozen`）时，`BattleManager` 也会把速度清零、停止移动；魂灵级冻结只停那一颗魂灵的充能和释放，不影响移动。
- 移动跨入新地图格时才发 `moved`（`BattleManager` 用 `map.local_to_map(position)` 判断），所以 `Event.Movement.UnitMoved` 触发器保持“走一格触发一次”的节奏，而不是每帧触发。
- 刷怪距离按怪配置：`MonsterData.spawn_distances` 是这只怪允许的距离数组；`BattleSession._rebuild_spawn_cells()` 开战时按玩家所在格缓存「距离 → 格子」表，每次刷怪把请求距离对应的环格子合并后随机取一格；请求的距离都没有格子时退到最近的有格环。同格刷出的怪加 0～12px 随机偏移，避免完全重叠。
- 刷哪只怪由 `BattleSession` 决定：常规池只含 `MonsterData.spawn_weight > 0` 且 `is_rare = false` 的怪（按权重抽）；每击杀 10 只常规怪，`CollectionDB.pick_rare_monster()` 从 `is_rare = true` 的条目里挑一只，在下一拍替换常规刷怪。
- 选目标与投射物命中都走 `BattleManager.units_near()` 的均匀网格索引（64px 一格），不再遍历全场；`TargetRule.max_range` 仍按“格”配，内部用 `cell_size_px` 换算成像素。

魂灵触发器由 `SoulLoadout` 构建时为每条配置生成 `SoulTriggerAbility`，grant 到 ASC，**不进入 BattleBrain 主循环**：
- `Event.Movement.UnitMoved`：带该触发器的单位在 `BattleManager` 注册为监听者，只有注册者收到跨格派发；
- `Event.Health.BelowPercent`：`attribute_changed` 生命下降时发送，阈值由触发器自己判断，每场只触发一次可配；
- `Event.Combat.SoulUsed` / `Event.Combat.FreezeApplied`：分别由魂灵成功激活、单位被冻结时发送；
- 触发时按 `target_scope` 对事件目标/自己/全体敌人施加 `effects`，再按 `charge_source_seconds` 给来源魂灵充能；被动魂灵没有来源技能，只施加效果。

`AutoCastAbility._activate_ability()`：

1. `commit_cost()` + `reset_charge()` —— 充满就放，不等任何东西；扫描线从头重扫；
2. `self_effects` 对自己结算一次（例如自身的生命再生），steps 空放也照常生效；
3. `cast_time > 0` → `await task_wait_delay()`；醒来后先检查 `is_active` 和施法者，避免对着尸体放大；
4. 创建 `SkillCastContext`，按 `steps` 顺序执行；
5. `UnitSkillStep`：`TargetRule.resolve(owner_asc, battle)` 选战斗单位；选不到就是本步空放；`AutoCastAbility._record_cast()` 记录链路，`CombatNarrator` 负责战斗日志报幕；有 `projectile_scene` 时每目标发一支箭、落地逐支结算，否则逐目标直接结算；
6. `SoulSkillStep`：`SoulTargetRule.resolve()` 选魂灵，施加加速/减速/冻结/充能；空放也照常消耗冷却；
7. 每个 step 返回 `SkillStepResult`；任一步命中即算本次释放命中，全部空放才记一次空放。

`SoulSkillStep` 的日志格式与状态日志保持一致：
`角色 施放【魂灵A】→ 魂灵B`、`魂灵B 获得状态【加速】（2.0 秒）`、
状态到期时 `魂灵B 的状态【加速】结束`；减速/冻结同理；
充能是 `魂灵B 获得充能（2.0 秒）`，没有到期日志。

`BattleBrain` 与 `BattleManager` 的分工：

- `BattleBrain` 管“每个单位自己能做什么”，用 `_physics_process`；怪物只有在攻击范围内才会跑；
- `BattleManager` 管“场上发生什么”：移动和范围门控用 `_physics_process`；单位名册、空间索引、地图换算、刷怪、掉落分别委托 `UnitRegistry` / `UnitSpatialIndex` / `BattleGrid` / `EnemySpawner` / `LootRoller`；`EnemySpawner` 每 `DEFAULT_INTERVAL` 秒通知 `BattleSession` 刷一只，选怪和按 `spawn_distances` 选格都在 session 里；
- 两者都按各自的 `_process` / `_physics_process` 运行，不再提供全局倍速。

### 1.2 投射物与命中

- `AbilityTask_Projectile.execute()` 对每个目标实例化一支箭，瞄准的是**施法那一刻**目标的坐标。
- `SoulProjectile`：
  - 默认速度 `DEFAULT_SPEED = 420` 像素/秒；技能可通过 `UnitSkillStep.projectile_speed` 覆盖；
  - 每帧把移动距离拆成小步，逐步检测碰撞，避免高速穿过单位；
  - 命中半径 `HIT_RADIUS = 20`，大于 32×32 贴图的半径；
  - 只打不同阵营、还活着的单位；碰到谁算谁，不一定是原来瞄的那只；
  - 命中检测走 `BattleManager.units_near()` 的空间索引，不遍历全场；
  - 3 秒内没命中就飞空消失；空箭是设计的一部分。
- `AbilityTask_Projectile` 只把“命中支数”交回技能，不交单位名单 —— 因为先落地的箭可能已经把目标打死并释放，名单里会留下已释放对象。
- 每支箭落地都会立刻发 `projectile_landed`，`AutoCastAbility` 就地结算，不等其他箭飞完。
- **发射即返回**：`AutoCastAbility.launch_projectiles()` 不再 `await` 任务，技能在发完箭后立刻结束，`is_active` 不再被投射物飞行占用。任务挂在施法者节点上，不绑定技能生命周期；技能之后可以正常再次释放，箭继续独立结算。`_on_step_projectile_landed()` 只检查战斗是否还在进行、目标是否有效，不再检查 `is_active`。
- 战斗结束/重开时 `BattleSession.stop()` 会释放 `Units` 下所有子节点（包含残留的 `SoulProjectile`）；`SoulProjectile` 自己也检查 `BattleManager` 是否还有效/运行中。

### 1.3 性能边界

- 正常节奏积累到约 1400 只时，FPS 仍稳定在 59–60；靠 `units_near()` 空间索引和每帧最多约 200 个移动体的分片移动撑住。
- 一帧内强刷 2000–3000 只会卡死，属于已知极端情况；不要用它评估正常性能。
