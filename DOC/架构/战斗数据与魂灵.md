## 5. 战斗数据 `base_mods/core/`

### 5.1 `SkillDefinition` 与步骤

一份 `SkillDefinition` = 共享配置 + 有序的 `steps` 数组。每一步自己决定目标域、选目标规则和结算方式；一个技能可以同时有单位步骤、魂灵步骤，或两者混合。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | GAS 标签后缀（PascalCase），用于 `ability_tag = "Skill." + id`；留空时 `ModLoader` 按魂灵 content_id 自动派生。core 为 `<PascalName>`（如 `XiaoLu`），第三方为 `Mod.<PascalModId>.<PascalName>`（如 `Mod.ExampleSouls.FireWolf`） |
| `self_effects` | `Array[GameplayEffect]` | 只对施法者自己结算的效果；每次释放先结算，steps 空放也生效 |
| `cooldown_seconds` | `float` | 魂灵充能模型的冷却时长（秒）；不是 GAS 冷却效果 |
| `cast_times` | `int` | 多重触发：一次激活连续释放几次，默认 1 |
| `crit_chance` | `float` | `UnitSkillStep` 用的暴击率 0~1，默认 0 |
| `crit_multiplier` | `float` | 暴击倍率，默认 1.5 |
| `steps` | `Array[SkillStep]` | 按数组顺序执行；空数组时只有 `self_effects` |
| `cast_time` | `float` | 吟唱时间，0 = 瞬发；吟唱结束才执行 steps |
| `cast_require_all_tags` | `Array[StringName]` | 必须全部持有才能施放，翻译成 `require_all_tags` |
| `cast_block_tags` | `Array[StringName]` | 持有任意一个就拒绝，翻译成 `ignore_tags` |

步骤类型：

| 类型 | 字段 | 说明 |
|---|---|---|
| `UnitSkillStep` | `target_rule: TargetRule`、`effects`、`status_magnitude`、`hit_cue_tag`、`projectile_scene`、`projectile_speed` | 选战斗单位；effects 施加到每个目标；`status_magnitude >= 0` 时覆盖状态数值；有投射物时等落地再结算 |
| `SoulSkillStep` | `target_rule: SoulTargetRule`、`haste/slow/freeze/charge_duration` | 选魂灵；施加加速/减速/冻结/充能 |

执行约定：

- `AutoCastAbility._release_once()` 创建 `SkillCastContext`，按 `steps` 顺序调用 `step.execute(ctx)`；
- 每步返回 `SkillStepResult(hit, empty_reason)`；只要有一个 step 命中，本次释放就算命中；
- 全部步骤都空放才记一次空放；
- `SkillCastContext.blackboard` 用于步骤间传数据（例如前一步选中的目标）；运行时状态不能写进共享的 `SkillStep` 资源；
- 投射物落地回调绑定发起它的 step，每支箭结算自己的 effects/cue。

技能显示名不在这份数据里：`AutoCastAbility.ability_name` 来自魂灵的 `ItemData.item_name`，没传时退回 `SkillDefinition.id`。

`ModLoader` 校验每个 step：`UnitSkillStep` 的 `target_rule` 必须是 `TargetRule` 且至少有 `effects` 或 `projectile_scene`；`SoulSkillStep` 的 `target_rule` 必须是 `SoulTargetRule` 且至少有一个状态时长；`steps` 为空且 `self_effects` 为空会报错。

所有 `*_duration` 和 `cooldown_seconds` 在资源里仍然是秒；`ChargedAbility` 内部按 1 秒 = 120 刻度换算。

`cast_times > 1` 时，`AutoCastAbility` 按多重触发循环释放：每次释放按 `steps` 重新选目标、独立判定暴击、先结算 `self_effects` 再执行 steps。一次激活只扣一次充能、只广播一次 `SoulUsed`；第 2 次起每次释放各占一个 20 刻激活锁，所以 1 秒最多释放 6 次，超出的顺延到后续秒继续，不丢弃。冻结、战斗结束或施法者倒下时停止后续释放；所有释放都没选中目标才记一次空放。

`UnitSkillStep` 配了 `hit_cue_tag` 时，每次结算到目标身上都会在目标身上播一次命中特效；方向按这个 step 自己的命中次数交替（第 1 次右→左，第 2 次左→右），打空不消耗次数。这一击打死目标时改挂到战场单位层、按目标最后的位置播放，避免 Cue 跟着当场销毁的单位一起没。

### 5.2 `TargetRule`（`target_rule.gd`）

`TargetRule` 和 `SoulTargetRule` 都继承 `TargetRuleBase`；消费端按 `TargetRuleBase.domain()` 分派，不再按具体类型判断。两个子类各自实现：

- `domain()`：`TargetRule` 返回 `Domain.UNIT`，`SoulTargetRule` 返回 `Domain.SOUL`；基类未实现时 `push_error` 并返回 `UNIT`，避免静默走错分支。
- `max_range_cells()`：工具提示用的格数；`TargetRule` 返回 `max_range`，魂灵规则默认 0。

`ModLoader` 在加载时校验规则类型与技能字段一致：单位目标技能不能配魂灵状态时长；魂灵目标技能不能配 `effects` / `projectile_scene` / `hit_cue_tag`，且至少要有一个状态时长。自定义 `TargetRuleBase` 子类目前必须落在 `TargetRule` / `SoulTargetRule` 体系内，否则加载时报错。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.RANDOM` | 随机 `count` 个，不重复 |
| `Mode.REPEAT` | 随机 `count` 次，可重复；每次独立结算 |
| `Mode.LOWEST_HP_PERCENT` | 血量百分比最低的 `count` 个 |
| `Mode.NEAREST` | 离自己最近的 `count` 个 |
| `Mode.ALL` | 全部 |
| `Camp.ENEMY` | 敌方 |
| `Camp.ALLY` | 友方 |
| `Camp.SELF` | 自己 |
| `count` | 选几个 / 重复几次 |
| `max_range` | 只挑 `max_range` 格内的目标；0 = 不限 |
| `include_self` | `ALLY` 时是否允许选中自己 |

`resolve()` 返回“批次数组” `Array[Array[BattleUnit]]`：

- `RANDOM / LOWEST_HP_PERCENT / ALL / NEAREST` → 只产生 1 个批次（一次打多个目标）；
- `REPEAT` → 产生 `count` 个批次，每批 1 个目标，保证每次独立结算。

### 5.3 `SoulTargetRule`（`soul_target_rule.gd`）

给“以魂灵为目标”的技能用；和 `TargetRule` 一样继承 `TargetRuleBase`（`domain()` 返回 `SOUL`），但选的是魂灵能力，返回类型也不同。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.LEFT` | 同一部位行内，紧挨在左侧的魂灵；中间空一格就不算相邻 |
| `Mode.RIGHT` | 同一部位行内，紧挨在右侧的魂灵；中间空一格就不算相邻 |
| `Mode.BOTH_SIDES` | 同一部位行内，左右两侧紧邻的魂灵；各最多一个 |
| `Mode.RANDOM` | 从有冷却的魂灵里随机 `count` 个 |
| `Mode.SELF` | 自己 |
| `Mode.ALL` | 全部有冷却的魂灵 |
| `include_self` | `RANDOM / ALL` 时是否包含自己 |
| `count` | `RANDOM` 时选几个 |

`resolve(caster, rng)` 返回 `Array[ChargedAbility]`；选中魂灵后由 `SkillDefinition` 的 `haste_duration` / `slow_duration` / `freeze_duration` / `charge_duration` 决定施加什么：

- 候选只来自 `caster.unit_soul_abilities`，且 `cooldown > 0`；
- 玩家和怪物都适用：玩家魂灵栏来自装备容器，怪物魂灵栏由 `MonsterData.soul_entries` 生成；
- 无冷却魂灵当前没有设计，先直接排除，等以后补规则；
- `LEFT / RIGHT / BOTH_SIDES` 只比较同一 `soul_container`，不跨部位；
- `BOTH_SIDES` 同时检查左右两侧；空位、无冷却魂灵跳过，两边都没有才空放；
- 相邻判定用 `SoulSlot` 的 `column / width`：
  - 右侧：目标最左列 = 施法者最左列 + 施法者列宽；
  - 左侧：目标最左列 + 目标列宽 = 施法者最左列；
- 相邻判定统一走 `SoulTargetRule.is_adjacent(a, b)`，`PassiveTrigger` 的“使用相邻魂灵”筛选复用它；
- 没有目标就返回空数组，技能空放并照常消耗冷却。

### 5.4 怪物魂灵与掉落（`MonsterSoulEntry` / `DropEntry`）

`MonsterSoulEntry`（`game/content/monster_soul_entry.gd`）是怪物携带魂灵的唯一配置源：

| 字段 | 说明 |
|---|---|
| `soul: SoulData` | 携带的魂灵；部位取魂灵自身的 `equip_part` |
| `drop_chance: float` | 0~1，默认 0.2；每颗魂灵独立配置 |

`MonsterData.soul_entries` 同时决定两件事：

- `soul_list()`：按配置顺序取出魂灵，交给 `SoulLoadout` 生成技能和虚拟魂灵栏；
- `drop_entries()`：把每颗魂灵转成运行时 `DropEntry`（`item = soul`，`chance = drop_chance`）。

`DropEntry`（`game/content/drops/drop_entry.gd`）只负责运行时掷骰：

| 字段 | 说明 |
|---|---|
| `item: ItemData` | 掉什么；魂灵就是 `SoulData` |
| `chance: float` | 0~1，默认 0.2；每条独立掷骰 |

怪死亡时 `LootRoller.roll()` 对每条掉落各判定一次，成功就调用注入的 `Warehouse.add_item(item)`（从仓库第 1 页开始找空位），10 页全满才写日志丢失。因为掉落由携带魂灵自动生成，“怪物能掉落它所有的魂灵”不需要再手配一份掉落表。

### 5.5 魂灵与技能实现经验

路径：`base_mods/core/souls/<名字>/`

- 主动魂灵：`SoulData.skill` 指向 `SkillDefinition`，由 `SoulLoadout` 生成 `AutoCastAbility`；显示名取 `item_name`。冷却由 `ChargedAbility` 的充能模型管理，时长读 `SkillDefinition.cooldown_seconds`。投射物速度由 `SkillDefinition.projectile_speed` 控制，默认 420。
- 被动魂灵：使用 `PassiveSoulData`，没有冷却、不进入自动施法队列、不显示扫描线；`passive_effects` 在血条绑定和 `_connect_asc()` 之前挂到玩家 ASC，因此不会产生开场状态日志。
  - 被动属性效果使用 `PassiveEffect` 类型（`GameplayEffect` 子类）标记，`BattleUnit` 用类型判断是否写日志。
  - 被动魂灵占格，会阻断左右相邻；`SoulTargetRule` 只从 `cooldown > 0` 的主动魂灵里选，因此不会被加速/减速/冻结/充能选中。
- 魂灵类型与标签：`SoulData.types` 是语义类型（`Array[StringName]`，如 `Soul.types.Wolf`、`Soul.types.Animal`），用于让特定触发效果/伤害加成只识别特定魂灵；`SoulData.tags` 是见闻筛选标签（`Array[StringName]`，尺寸 `Soul.tags.Small/Medium/Large` 与 `Soul.tags.Damage`、`Soul.tags.Burn` 等效果标签）。两者都不做更深层级分类，与 GAS 自动生成的 `GameplayTags` 是两套东西；前缀和 PascalCase 后缀由 `ModLoader` 校验。`equip_part` 按魂灵配置：恐狼是 `ARMSSOUL`，其余现有魂灵仍为 `ANY`。tooltip 的类型行按 `SoulData.types` 显示，中文名由 `SoulText.type_name()` 统一提供（`Scripts/soul_text.gd`）。
- 魂灵触发器：`SoulData.triggers` 配 `PassiveTrigger`，主动/被动魂灵通用。`SoulLoadout` 构建时为每条触发器生成一个 `SoulTriggerAbility`（`GameplayAbility` 子类），grant 到 ASC 并把 `PassiveTrigger.event_tag` 写进 `trigger_event_tag`。它**不进入** `BattleBrain.abilities`，不会被主循环自动施放，只由 `ASC.send_gameplay_event()` 按标签唤醒；payload 里带 `target`、`used_ability`、`used_soul`、`ratio`、`trace`。
  - `Event.Movement.UnitMoved`：`BattleUnit._on_battle_unit_moved()` 只对敌方移动发送；蹈火术用。
  - `Event.Health.BelowPercent`：`attribute_changed` 里生命下降时发送，payload 带旧值/新值/比例；`SoulTriggerAbility` 按 `threshold_ratio` 严格小于判断，`once_per_battle` 控制只触发一次。
  - `Event.Combat.SoulUsed`：另一个魂灵技能成功激活（含空放）时由 `AutoCastAbility._notify_soul_used()` 发送；`SoulTriggerAbility` 排除来源自己，`required_soul_types` 要求被使用魂灵带齐类型，`require_adjacent` 要求同一部位行内紧邻。命中后按 `charge_source_seconds` 给来源魂灵充能；充满时由 `BattleBrain.request_activation()` 入队、当帧末统一释放，受 20 刻激活锁限制（同一颗魂灵 1 秒最多 6 次）。当前没有魂灵配置该事件。
  - `Event.Combat.FreezeApplied`：任何单位被冻结时，向所有以它为敌、且确实带该触发器事件的单位发送；每冻住一个目标触发一次，重复冻结同一目标也算，不区分冻结来源。当前没有魂灵使用；配置后可用 `charge_source_seconds` 在冻结时给来源魂灵充能。
  - `target_scope` 支持事件目标 / 自己 / 全体敌人；触发效果通过 spec 的 SetByCaller `Data.TriggerMagnitude` 传数值，不在效果资源里写死。
  - `charge_source_seconds` 在触发后给来源主动魂灵充能；被动魂灵没有来源技能，忽略该字段。
  - `trigger_name` 非空时写一行“触发【名字】”日志；留空保持原有静默行为。
  - 只有 ASC 上确实存在对应 `trigger_event_tag` 的触发器时才发送事件，避免无监听者的事件刷屏。
- 直接伤害：挂 `SoulDamageExecution`，吃施法者 `damage_bonus`，暴击在加成后计算；可选 `bonus_per_matching_soul` + `matching_soul_types`，按 `BattleUnit.loadout` 里带匹配类型的魂灵数量加伤害（恐狼每有一颗 `Soul.types.Wolf` +10）。伤害+剧毒挂 `PoisonDamageExecution`，剧毒值 = 最终伤害 × `poison_ratio`（默认 1，最少 1 点，整数）；治疗、灼烧、剧毒、生命再生周期本身不要挂。
- 护盾获得挂 `ShieldExecution`，不吃 `damage_bonus`。
- 单独施加灼烧/剧毒/生命再生挂 `StatusApplyExecution`，数值向下取整；`UnitSkillStep.status_magnitude` 写入 `Data.SkillMagnitude`，取值优先级为 `Data.SkillMagnitude` > `Data.TriggerMagnitude` > 效果资源 `base_amount`，再乘暴击倍率。治疗挂 `HealExecution`，治疗量的 5%（向下取整）从治疗目标的灼烧/剧毒中扣除。再生不是治疗，不触发净化。剧毒与再生同时存在时属性原值各自保留，只在每跳结算时相减。
- 伤害分流：`DamageResolver.split_damage()` 统一先扣护盾；普通伤害 1 护盾抵 1 伤害；灼烧对护盾伤害 `floor(伤害 × 0.5)`，破盾后剩余按“1 护盾抵 2 灼烧”进生命；剧毒无视护盾。
- 异常状态的暴击：只在释放/施加时判定，把暴击后的数值写进状态；之后灼烧/剧毒/生命再生每跳不再暴击。
- 暴击倍率读取与暴击标签注入统一走 `game/content/crit_resolution.gd`；`SoulDamageExecution` / `HealExecution` / `ShieldExecution` 不再各自复制这段逻辑。`StatusApplyExecution` 只读取倍率，不注入暴击标签。
- 持续伤害/再生：周期效果用 `BurnTickExecution` / `PoisonTickExecution` / `RegenTickExecution`，它们都继承 `PeriodicStatusTickExecution`；灼烧单独实现衰减/护盾分流，剧毒/再生共用 `NetStatusTickExecution` 的“净值 × 每点数值”结算。每跳叙事与飘字分别由 `CombatNarrator` / `UnitPresenter` 订阅 `periodic_effect_ticked` 处理，execution 自己提供 `status_attribute` / `status_display_name` / `remove_when_zero` / `log_color` / `popup_style` / `is_heal`；新增周期状态只需继承基类，不改 `BattleUnit` / `UnitPresenter` / `CombatNarrator` / `CombatNames`。`attribute_changed` 只负责血条/死亡。
- 扫描线：只有主动魂灵显示；每颗魂灵资源仍带 `ShaderMaterial`（`soul_scanline.gdshader`，`enable = 0`），被动魂灵不打开。
- 装备栏徽章：加速/减速剩余秒数显示在已装备的魂灵实例上；充能是瞬时的，不显示徽章。
- 状态颜色：tooltip / 战斗日志 / 头顶飘字 / 状态条统一读 `Scripts/game_colors.gd` 的 `GameColors`；显示名到颜色的映射在 `STATUS`，tooltip 关键词正则用 `STATUS_PATTERN`。
- tooltip 文案：`SoulData.tooltip_blocks`（`Array[String]`）存正文段落，格式化器用 `===================================` 连接并替换 `{cooldown}`；`SoulData.types` 决定类型行（中文名由 `SoulText.type_name()` 提供），`equip_part != ANY` 时追加部位行；技能和触发器资源不再带展示文案。
- 调试入口：新魂灵用 `TestAPI.add_soul()`（指定容器）或 `TestAPI.add_soul_to_warehouse()`（自动找空页）放进仓库，`TestAPI.set_warehouse_page()` 可切到指定页查看；正式入口由掉落/商店决定，不应写死在魂灵资源里。

### 5.6 冷却与持续效果资源

- 技能冷却不再有 `GameplayEffect` 资源：`SkillDefinition.cooldown_seconds` 是唯一时长来源，`ChargedAbility` 按充能模型管理；`GameplayAbility.cooldown_effect` 保持为空。
- 怪物移动已改为即时制；名字、血量、攻击范围、移速、贴图都配在 `MonsterData`，由 `BattleSession._spawn_enemy()` 注入 `BattleUnit`，场景只保留碰撞体/节点结构。

持续效果资源：

- `base_mods/core/effects/burn_apply.tres`：`INSTANT`，挂 `StatusApplyExecution`，写 `burn`；有 `Data.TriggerMagnitude` 时用触发器数值，否则用 base，结果向下取整。
- `base_mods/core/effects/poison_apply.tres`：同上，写 `poison`。
- `base_mods/core/effects/regen_apply.tres`：同上，写 `regen`，基础数值 5。
- `base_mods/core/effects/burn_tick.tres`：`INFINITE`、`period = 0.5`、`max_stacks = 1`、`granted_tags = [State.Burning]`，挂 `BurnTickExecution`；每跳按当前整数层数结算并衰减。
- `base_mods/core/effects/poison_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`、`granted_tags = [State.Poisoned]`，挂 `PoisonTickExecution`；每跳先与再生相减，剧毒更多时按差值直接扣生命，无视护盾且不衰减。
- `base_mods/core/effects/regen_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`，挂 `RegenTickExecution`；每跳先与剧毒相减，再生更多时按差值恢复生命，不衰减、不净化、溢出丢弃。当前没有为再生注册 `State.Regen` 标签。
- `base_mods/core/effects/freeze_unit.tres`：`DURATION`、3 秒、`REFRESH_DURATION`、`max_stacks = 1`，`granted_tags = [State.Frozen]`、`persistent_cue_tags = [Cue.Status.Freeze]`；没有 execution，只负责挂标签和持续 Cue。
- `base_mods/core/effects/freeze_unit_short.tres`：同上，`duration = 1.0`，通用的短时单位冻结效果；文件名不写数值。
- `RegenFromBurnExecution`（`game/content/regen_from_burn_execution.gd`）是可选扩展：让再生读取某个灼烧效果里 `StatusApplyExecution(burn)` 的结算值，灼烧数值被调整后再生自动跟随；周期部分仍复用 `regen_tick.tres`。冻结再生类触发可直接复用 `regen_apply.tres` + `regen_tick.tres`，用触发器 `magnitude` 覆盖基础数值。
- 这些资源不填 `resource_name`，编辑器按原文件名显示；战斗日志里灼烧/剧毒/生命再生周期效果由 `BattleUnit._effect_display_name()` 统一显示为“灼烧”/“剧毒”/“生命再生”，冻结按 `State.Frozen` 显示为“冻结”。

### 5.7 怪物数据与见闻清单

见闻窗口的“全部条目”来自 ModLoader 的内置 core manifest 和第三方 mod 条目：

| 位置 | 作用 |
|---|---|
| `base_mods/core/mod.json` | `SoulData` / `MonsterData` 全量清单；`content.souls` / `content.monsters` |
| `Scripts/collection_db.gd` | 从 ModLoader 条目构建运行时索引、已遇见状态；旧 `user://collection.cfg` 只读迁移，统一存档见 `架构/存档.md` |

- ID 由 manifest 的 `id` 字段决定（core 如 `xiao_lu_soul`、`snake_monster`），同时是“已遇见”存档的键；文件改名/移动不再影响 ID；旧怪物 ID `snake_data` / `fu_data` 由 `CollectionDB.LEGACY_MONSTER_ID_ALIASES` 迁移；
- 新增魂灵/怪物时，在 `base_mods/core/mod.json` 加条目，不再依赖编辑器扫描；
- 解锁时机：怪物首次刷出即记录；魂灵首次进背包即记录。`GBIS.add_item()` 会 `duplicate()` 物品，副本没有 `resource_path`，但 `content_id` 随副本保留，`CollectionDB` 直接读取；
- 未遇见条目仍占位显示，但不暴露名字和图标。
