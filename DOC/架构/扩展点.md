## 10. 扩展点

### 10.1 新增一颗魂灵

1. 主动魂灵：在 `base_mods/core/souls/<名字>/` 下新建技能资源（`*_skill.tres`）：
   - `SkillDefinition` 的 `id`（GAS 标签后缀：core 与魂灵 ID 对应，如 `XiaoLu`；留空时 `ModLoader` 自动派生）；
   - 共享配置：`cooldown_seconds`、`cast_times`（多重触发次数，默认 1）、`crit_chance`、`crit_multiplier`、`cast_time`、`cast_require_all_tags`、`cast_block_tags`；
   - `self_effects`：只对施法者自己结算的 `GameplayEffect`；steps 空放也生效；
   - `steps`：按顺序执行的步骤数组，常用两种：
     - `UnitSkillStep`：`target_rule` 选 `TargetRule`（UNIT），配 `effects`，可选 `status_magnitude`（覆盖 `StatusApplyExecution` 的数值，< 0 = 用效果资源默认值）/ `hit_cue_tag` / `projectile_scene` / `projectile_speed`；
     - `SoulSkillStep`：`target_rule` 选 `SoulTargetRule`（SOUL），配 `haste_duration` / `slow_duration` / `freeze_duration` / `charge_duration`；
   - 一个技能可以混合多个步骤，例如「先打怪，再给右侧魂灵加速」；每步独立选目标、独立结算；
   - `UnitSkillStep.effects` 里的伤害效果挂 `SoulDamageExecution`（`game/content/soul_damage_execution.gd`），填 `base_damage`；需要“每有一颗某类型魂灵 +X 伤害”时再填 `bonus_per_matching_soul` 与 `matching_soul_types`（数量取自 `BattleUnit.loadout`，包含魂灵自己）；治疗、灼烧、剧毒、生命再生不要挂；
   - 护盾效果挂 `ShieldExecution`（`game/content/shield_execution.gd`），填 `base_shield`；
   - 需要从一个效果派生数值时参考 `RegenFromBurnExecution`（`game/content/regen_from_burn_execution.gd`，让再生读取某个灼烧效果本次的结算值）；
   - `UnitSkillStep` 的 `hit_cue_tag`：命中特效标签，每次结算到目标身上时播一次；必须已注册，启动时会检查；接线见 `特效/effects.md`；
   - `ModLoader` 校验每个 step：`UnitSkillStep` 的规则必须是 `TargetRule` 且至少有 `effects` 或 `projectile_scene`；`SoulSkillStep` 的规则必须是 `SoulTargetRule` 且至少有一个状态时长；未知 step 类型会报错。
   - 同一个效果资源想在不同技能里用不同状态层数时，给步骤设 `status_magnitude`，不必复制效果资源；同一步骤内多个状态共用这个数值，需要不同数值就拆成多个步骤。
2. 新建魂灵资源（`*_soul.tres`）：
   - 主动魂灵用 `SoulData`，`skill` 指向上面的技能；
   - 被动魂灵用 `PassiveSoulData`（`game/content/passive_soul_data.gd`），`passive_effects` 填 `PassiveEffect`（`game/content/passive_effect.gd`，继承 `GameplayEffect` 的标记类），不填 `skill`；`PassiveEffect` 类型不写状态日志；
   - `types` 填语义类型（如 `Soul.types.Wolf`、`Soul.types.Animal`，供触发规则和按类型数量加伤筛选）；`tags` 填见闻筛选标签（尺寸 `Soul.tags.Small/Medium/Large` 与效果标签 `Soul.tags.Damage` 等）；两者前缀和 PascalCase 后缀由 `ModLoader` 校验；
   - 类型中文名统一在 `Scripts/soul_text.gd` 的 `SoulText.TYPE_NAMES` 里补，不在魂灵资源里重复填；未知类型会回退到 ID 最后一段；
   - 触发规则 `SoulData.triggers` 主动/被动魂灵通用，填 `PassiveTrigger`（`game/content/passive_trigger.gd`）：
     - `event_tag` 选 GAS GameplayEvent：`Event.Movement.UnitMoved`、`Event.Health.BelowPercent`、`Event.Combat.SoulUsed`、`Event.Combat.FreezeApplied`；必须以 `Event.` 开头（`ModLoader` 校验）；
     - `target_scope` 选事件目标 / 自己 / 全体敌人；
     - `threshold_ratio` 只对 `Event.Health.BelowPercent` 生效；`once_per_battle` 控制一次性；
     - `required_soul_types` / `require_adjacent` 只对 `Event.Combat.SoulUsed` 生效；
     - `charge_source_seconds` 给来源主动魂灵充能；被动魂灵没有来源技能，忽略；
     - 新增事件：在 `godot_gas/tag_registry.tres` 注册 `Event.*`，在事件产生处 `asc.send_gameplay_event()`，不需要改 `SoulTriggerAbility`；
   - `equip_part` 选部位；
   - 可选 `tooltip_blocks`（tooltip 正文段落；格式化器用 `===================================` 连接，`{cooldown}` 替换成技能冷却；`equip_part != ANY` 时自动追加 `{ 部位 }` 行）；
   - `item_name`、`category = "SOUL"`、`icon`（按尺寸用 `Assets/soul_small.png` / `soul_medium.png` / `soul_large.png`）、`columns/rows`；
   - 扫描线材质（`soul_scanline.gdshader`，`enable = 0`；被动魂灵不会打开它）。
3. 放进游戏：
   - 调试用：在见闻窗口右键魂灵条目放入仓库，或调用 `TestAPI.add_soul(id)` / `TestAPI.add_soul_to_warehouse(id)`；
   - 正式用：配置到某个怪物的 `soul_entries`，并给这颗魂灵单独配 `drop_chance`。
4. 在 `base_mods/core/mod.json` 的 `content.souls` 加一条 `{ "id": "<名字>_soul", "path": "souls/<名字>/<文件名>.tres" }`；ID 沿用旧值，不加前缀，新内容统一用 `_soul` 后缀。
5. 战斗内不需要改代码：主动魂灵由 `BattleUnit.add_soul_abilities()` 自动生成技能，显示名取 `item_name`；属性型被动由 `BattleWindow._spawn_player()` 收集 `passive_effects` 并在 `setup_from_scene()` 时挂到玩家 ASC；魂灵触发器由 `add_soul_abilities()` 统一登记，主动/被动魂灵走同一套绑定。

### 10.2 新增一种怪物

1. 在 `base_mods/core/monsters/<名字>/` 下复制 `snake.tscn` 作为战斗场景，根节点保持 `team = ENEMY`；
2. 新建 `<名字>_monster.tres`（`MonsterData`，`game/content/monster_data.gd`；旧版 `_data` 后缀仅兼容），配置：
   - `display_name`、`icon`（图鉴图标 + 战斗贴图）、`max_health`、`attack_range`、`move_speed`、`spawn_weight`（可选，0 = 不参与常规随机刷怪）、`is_rare`（可选，每击杀 10 只常规怪后替换刷出的稀有怪；设为 true 时同时把 `spawn_weight` 设为 0，`ModLoader` 会校验）；
   - `soul_entries`（携带的魂灵 + 各自的掉落几率；战斗时会生成对应技能，部位由魂灵自身 `equip_part` 决定，没配的部位就不存在）；
   - `battle_scene` 指向第 1 步的场景；
3. 配场景里的 ASC `attribute_sets`（可用 `MonsterStatsAttributeSet` 或新建）；根节点用 `CharacterBody2D` 并挂圆形 `CollisionShape2D`，场景不再写 `move_speed` / `attack_range` / 名字 / 贴图，全部从 `MonsterData` 注入，移动由 `BattleManager` 统一驱动。注意 `MonsterData.attack_range`（像素）要小于等于它攻击技能 `TargetRule.max_range` 换算后的像素值（格数 × `BattleManager.cell_size_px`），否则怪会停在技能够不着的距离空放；
4. 在 `base_mods/core/mod.json` 的 `content.monsters` 加一条 `{ "id": "<名字>_monster", "path": "monsters/<名字>/<文件名>.tres" }`；`spawn_weight > 0` 且 `is_rare = false` 的怪会进入常规随机池，`BattleWindow._spawn_enemy()` 从 `CollectionDB.pick_random_monster()` 按权重取用。

### 10.3 新增技能（不改代码）

- 用现有 `TargetRule` / `SoulTargetRule` + `GameplayEffect` + `projectile_scene`，按 `steps` 组合即可做出大部分主动技能；
- 新的战斗单位目标模式 → 扩展 `TargetRule.Mode` 和 `resolve()`；
- 新的魂灵目标模式 → 扩展 `SoulTargetRule.Mode` 和 `resolve()`；
- 新的目标域或新的结算方式 → 继承 `SkillStep` 实现 `execute()`，放进 `steps`；`AutoCastAbility` 不需要改，只需在 `ModLoader` 校验里补该步骤类型的检查；
- 新的效果类型（中毒等）→ 先用 GAS 的 `GameplayEffect`（周期效果、modifier）实现，再补标签和 Cue；护盾参考 `ShieldExecution`；
- 单位冻结 → 参考 `freeze_unit.tres`：`DURATION` + `State.Frozen` + 持久 Cue；魂灵级冻结 → 参考 `SoulSkillStep.freeze_duration` + `ChargedAbility.apply_freeze()`；
- 新增持续伤害/再生 → 参考 `burn_tick.tres` + `BurnTickExecution` 或 `regen_tick.tres` + `RegenTickExecution`：周期效果只负责计时，每次 tick 用 execution 读取目标状态并返回属性变化；`effect_received` 在周期效果上只表示“已施加”，每跳叙事监听 `periodic_effect_ticked`；
- 新的“状态” → 先加到 `godot_gas/tag_registry.tres`，再用插件重新生成 `gameplay_tags.gd`。

### 10.4 新增窗口

1. 新建场景，根节点用 `Window`，挂一个 `extends BaseWindow` 的脚本；
2. 在场景里设 `open_position`（或在 `control.tscn` 实例上覆盖）；
3. 把场景实例加到 `Main/control.tscn`；
4. 在 `Main/control.gd` 里加按钮/信号并调用 `popup_window()`。

### 10.5 新增特效

按 `特效/effects.md` 的三步走：写 `GameplayCueNotify` 场景 → 官方内容登记到 `base_mods/core/mod.json` 的 `content.cues`（第三方 mod 登记到自己的 `mod.json`）→ 挂到 `GameplayEffect` 的 `application/persistent/periodic/removal_cue_tags`。

UI 物品（例如魂灵格子）没有战场节点，不能直接挂 Cue；参考 `ItemView._apply_freeze_shader()`，用 `SoulData` 的状态字段驱动材质参数和 Kits 徽章。

### 10.6 通过 mod 扩展

官方内容和第三方 mod 都走 `ModLoader`：`CollectionDB` 从 ModLoader 条目构建目录，`ModCueRegistrar` 把 core 和第三方 Cue 注册进 `GameplayCueManager`。官方内容改 `base_mods/core/mod.json`，第三方改自己的 `mod.json`；ID、路径和加载顺序见 `指南/Mod制作.md`，架构见 `架构/Mod系统.md`。
