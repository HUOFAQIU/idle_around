## 1. 单窗口模型与层级

主场景是 `main/Cube/Scenes/main.tscn`，`main/control.tscn` 作为主视口内 `GameUI`（CanvasLayer 1）覆盖层运行，不再塞进立方体面片。层级顺序与输入优先级：`GameUI(1)` < `CubeView(1024)` < `HUD(1024, 树中更靠后)` < `DragLayer(1025)/ItemWindow` < `TooltipLayer(1026)/TooltipWindow`。

- **无 OS 子窗口**：所有游戏面板都是 `main/control.tscn` 根 `Control`（全屏锚点、`MOUSE_FILTER_IGNORE`）的直接子节点，绘制顺序即子节点顺序；`PanelManager.raise()` 调 `move_to_front()` 并记录 `_active`。人物/背包/魂器/Info 常驻场景，战斗/商店/收藏/调试/终端/Mod 由 `GameUI.ensure_panel(id)` 首次打开时按需实例化（`LAZY_SCENE_PANELS` 表，Mod 走纯脚本构建），`preload_panel()` 只发线程加载请求、不实例化。
- **立方体让位**：`PanelManager._input` 先查 `CubeInputSurface.contains_screen_point()`，指针在立方体轮廓内时不置顶下层面板；战斗窗口坐标 tooltip 同样让位。立方体锚定、拖动圆点与透明区域点击穿透机制见 `架构/立方体外壳.md` §2、§4。
- **入口分派**：主菜单 `PetPanel` 挂在立方体 02 面，经 `main.gd` 调 `GameUI.open_panel(id)` → `PanelManager.toggle(window)`（外壳仅保留 `open()` / `toggle()` 两个动词）；01/04 面请求转给 `GameFlow`。切档/新游戏前 `GameUI.close_all_panels()` 统一关窗。
- **全应用置顶**：单窗口模式仅主窗口可置顶，由 `main/status_bar_container.gd` 的 `T` 按钮读写 `WindowPinSettings.MAIN_WINDOW_ID`（`user://Settings.cfg`）；面板标题栏不再有独立置顶按钮，`TestAPI.*_window_pinned()` 仅接受 `"MainWindow"`。

## 2. BaseWindow 与面板约定

`windows/base_window.gd`（`extends Control`）：

- **结构**：`_ready()` 构建不透明背景 `WindowBackground`（强制 alpha=1 防透出桌面）和 `TitleUI`（28px 黄底标题栏 `GameColors.WINDOW_TITLE_BAR` + `ContentRoot`），开启 `clip_contents`。`TitleBarBox` 必须 `MOUSE_FILTER_IGNORE`，确保空白处落给 `scripts/ui/control_drag.gd` 拖动（按住后每帧轮询主视口鼠标并 clamp，拖出边缘不断）。
- **收纳与撑高**：`_ready()` 用 `call_deferred("_wrap_content")` 收纳初始子节点并给外层高度 +28；动态新增的 `Control` 需直接挂到 `TitleUI/ContentRoot`。`_open_window()`（仅由 `PanelManager` 与子类调用）夹取尺寸与 `open_position`（主视口局部坐标，设计基准 1600×960，负值居中），再 `call_deferred("_grow_to_content")` 只增不减。
- **扩展按钮**：子类在 `super()` 后调用 `add_title_bar_button(btn)` 插到关闭按钮左侧。
- **场景规范**：面板放 `windows/<Name>/<name>_window.tscn`（`ModWindow` 是唯一无场景、由 `GameUI.ensure_panel` 纯脚本构建的面板）；`windows/Info/`、`Item/`、`Shop/` 同属面板或浮层目录。

## 3. 浮层单例与核心窗口

| 类 / 窗口 | 单例 / 挂载层 | 关键约束 |
|---|---|---|
| `TooltipWindow` | `TooltipWindow.instance`（Layer 1026） | 根节点 `MOUSE_FILTER_IGNORE`；按 owner + 层级（`COORD < ITEM`）记账，同帧 hide+show 合并；先摆位再显示防闪烁；内嵌 `TerminalView`（顶部 2 行高 `TerminalSpan` 标题 + ANSI 正文，由 `TooltipText` 生成）。 |
| `ItemWindow` | `ItemWindow.instance`（Layer 1025） | `hold()` 递归设整棵子树 `MOUSE_FILTER_IGNORE`；每帧按 `mouse_pos - _grab_offset` 跟随（以格坐标记录抓取点），拖出主窗口边缘会被裁剪。 |
| `InfoWindow` | 普通 BaseWindow | 正文为 `TerminalView`，隐藏时写入 500 行缓冲，打开时重建（见 `架构/终端窗口.md`）。 |
| `BattleWindow` | 1920×1080（含标题栏 1108），默认居中 | 内容区纯 3D `BattleArena`（见 §3.1），标题栏自带「日志」按钮打开 `InfoWindow`；旧 2D 六边形 `Tile` 与 `UiOverlay` 已移除。 |
| `CharacterWindow` / `SoulVesselWindow` | 360×240 / 按魂器内容自适应 | 人物窗口含 9×3 `vessel_cells`，`open_position` 只能配在场景；魂器窗口由 `_fit_to_contents()` 算尺寸，右键打开、关闭不清空（见 `设计/魂器.md`）。 |

**关键场景资源**：`assets/tokens.png`（单位与投射物）、`assets/Shader/soul_scanline.gdshader`（扫描线）、`game/content/Kits/{jiasu,jiansu,bingdong}.tscn`（状态徽章）。

### 3.1 BattleWindow 内嵌 3D 战斗场景 BattleArena

`windows/Battle/scenes/battle_arena.tscn` 由 `BattleWindow._ensure_arena()` 懒加载实例化（首次开战或窗口可见时），以 `Control` 根挂进 `ContentRoot` 铺满窗口内容区；`battle_window.gd` 只发线程预加载请求，不提前实例化：

- **纯 3D 舞台解耦**：3D 渲染管线（`SubViewport`、相机、AO/Mist/DoF/PostProcess、草坪、天气）已独立为 `windows/Battle/view_3d/battle_view_3d.gd`（`BattleView3D`）；天气预设 `WeatherPreset` 归位 `game/content/weather_preset.gd` 并挂到 `MapData.weather_preset`。
- **尺寸自洽与纯按钮交互**：`BattleView3D` 用自身 `size` 与 `resized` 算分辨率与相机；`BattleHud` 是 `Control` 全屏锚点 + `MOUSE_FILTER_IGNORE`，已移除全部键盘快捷键并将 `+100`、`PERF`、`RST` 纳入右上角按钮栏。
- **HUD 每帧只读轻量快照**：`BattleHud.update_ui` 的波次标签走 `BattleSim.get_progress_label()` → `BattleSession.get_map_progress()`，只累加 `TIME_INTERVAL` 条目的已刷/总数；不要改回 `get_state()`（会逐只序列化全部敌人，1000 只时约 11ms/帧）。
- **隐藏即停机**：窗口不可见时 `BattleView3D.sync_active(false)` 将 `SubViewport` 切到 `UPDATE_DISABLED` 并跳过模拟，重新可见立即恢复。
- **GAS 逻辑与 3D 表现统一**：地图开战由 `BattleSim` 托管真实 `BattleSession`（`game/battle/` 纯逻辑 GAS 核心，含怪物 ASC 懒激活），每帧同步到 `BattleUnitBatchRenderer`（MultiMesh 合批），`Battle3DBridge` 监听 `BattleEventBus` 播放 3D 爪痕/火花/碎块/音效，彩色叙事经 `CombatNarrator` + `BattleLogAdapter` 写入 `InfoWindow`；旧 2D `Maps/tile.tscn`、`player.tscn`、`unit_presenter.gd`、`unit_health_bar.gd` 已删除。

## 4. 常见排查

1. **窗口出界或被裁**：检查 `open_position` 是否误用屏幕坐标（应为主视口局部坐标，负值才居中）；`BattleWindow` 需 1108 高，主视口不足时会被夹到视口高度（如 1600×960 基准下内容区只剩 932，BattleArena 按 932 重算 HUD），2560×1438 全屏不受影响。
2. **标题栏拖不动**：确认额外按钮/子 `Control` 未用 `MOUSE_FILTER_STOP` 吃掉 `TitleBar` 空白区；关闭按钮走 `TitleUI/TitleBar/CloseButton -> hide()`。
3. **Tooltip / 拖拽幽灵被盖住或挡点击**：确认 `DragLayer=1025`、`TooltipLayer=1026` 未移回根 `Control`；确认 `ItemWindow` 子树全为 `MOUSE_FILTER_IGNORE`。
4. **调试 / Mod 窗口内容错位**：两者纯脚本构建且不支持缩放，尺寸固定（Debug 1200×788、Mod 760×548，含 28px 标题栏），根节点必须挂在 `ContentRoot`。
5. **静止时 UI 边缘缺几像素 / 透明覆盖层失效**：确认 `project.godot` 保留 `borderless=true` 且运行期未改主窗口 `position`/`size`，且未同时加 `resizable=false`/`maximize_disabled=true`/`always_on_top=true`（详见 `架构/立方体外壳.md` §4）。
