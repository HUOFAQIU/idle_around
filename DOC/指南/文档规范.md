# 文档规范与检索协议

> 类型：指南 | 状态：有效 | 核对：2026-11-27
> 何时读：新增或修改文档、检查文档头格式、规范 AI 检索与排障回写流程
> 关键词：文档头 写作约定 检索协议 index_meta 单一权威 指针
> 代码：`tools/lint/index_meta.py`、`tools/lint/tests/test_index_meta.py`
> 相关：`INDEX.md`、`adr/0002-pointer-docs.md`、`指南/代码检查.md`

## 1. 文档头规范

除 `DOC/INDEX.md` 外，每篇文档标题下紧跟一段引用块（必须落在文件前 15 行内，由 `tools/lint/index_meta.py` 自动扫描校验）：

```markdown
> 类型：设计 / 实现 / 指南 / 规范 / 记录 | 状态：设计 / 部分实现 / 已实现 / 有效 / 占位 / 废弃 | 核对：YYYY-MM-DD
> 何时读：一句话说明什么任务该打开它
> 关键词：6～12 个核心同义词、类名或文件名，空格分隔，供 grep 命中
> 代码：相关入口文件；没有就写 —
> 相关：其他文档；可加「不覆盖」说明
```

- 实现/指南/规范/记录类用 `核对：YYYY-MM-DD`，设计类可用 `整理：YYYY-MM-DD`。
- 不在 `INDEX.md` 维护手工文档清单；`index_meta.py` 会自动扫描 `DOC/**/*.md` 校验文档头齐全性，并验证 `INDEX.md` 路由表中的每个 `.md` 路径与「代码入口」列中的每个路径存在。代码入口只认含 `/` 或带扩展名的引用（反引号内的符号名等不校验），且两条路由列都必须是仓库相对路径，绝对路径、盘符与 `..` 一律报错。

## 2. 写作约定

1. 一篇文档一个主题；目标压在 120 行内，超过 200 行或体积超过 10 KB、包含 3 个以上主题时拆分。
2. 只写代码里看不出来的：为什么、边界、数据流、扩展步骤、坑；不抄函数清单和资源枚举。
3. 内容清单以 `base_mods/core/mod.json` 为准；第三方 mod 以各自的 `mod.json` 为准。
4. 引用代码用符号（`file.gd::function`），不用行号。
5. 设计文档写「应该怎样」，架构文档写「现在怎样」；冲突时以代码为准并标注差异。
6. 过期内容直接删除，不留在正文；需要追溯时用 git 历史。
7. 改代码时同步更新受影响文档的核对日期；新增或移动文档时同步更新 `DOC/INDEX.md` 路由表（`check.sh --staged` 与 `--all` 会自动跑 `index_meta.py` 兜底）。
8. 新增功能/内容时，在 `Scripts/test_api/` 对应域模块实现测试方法，在 `Scripts/test_api.gd` 补转发；只有新增域或入口语义变化时才更新 `指南/AI测试接口.md`。
9. 一个概念只在一个权威节维护：事件清单、流程图、规则表选一处作为权威，其他文档只写指针和本地流程（决策见 `adr/0002-pointer-docs.md`）。

## 3. 检索协议（配合 CLAUDE.md）

1. 先查 `DOC/INDEX.md` 路由表，不猜文件名。
2. 命中目标文档后分级读取：≤80 行直接一次读完（省去多余 grep 轮次）；80～120 行按需整读或分段读；>120 行先 `grep '^##'` 看标题，再按 `offset/limit` 只读命中节。
3. 禁止整篇读超过 200 行的文档；标记为「记录」的文档只在明确查历史时读。
4. 文档没覆盖时先 grep 代码符号，改完后把缺口补进对应文档。
5. 排障先查症状路由：症状 → `INDEX.md` 路由表 → 目标文档「常见排查」→ 再 grep 代码，不从头读实现文档。
6. 修复后把「症状 → 检查点 → 结论」回写对应文档的「常见排查」节；跨主题的坑写进 `架构/现状与注意.md`。
