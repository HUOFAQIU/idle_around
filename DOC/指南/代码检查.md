# 代码检查

> 类型：指南 | 状态：有效 | 核对：2026-11-27

> 关键词：lint check.sh pre-commit allowlist boundaries index_meta 注释策略 情景测试 git护栏
> 代码：`tools/check.sh`、`tools/lint/`、`tools/git-hooks/`、`tools/compile_check/`、`tools/scenarios/`、`tools/git_guard.py`
> 相关：`INDEX.md`、`指南/文档规范.md`

## 原则

- 每纠正 AI 一次，优先写成 lint 等自动检查，而不是往说明文档里加话。
- 容易用错的东西直接禁掉；首方 `.gd` 禁普通注释，仅放行四类例外（见「注释策略」）。

## 一键命令

```bash
bash tools/check.sh --file Scripts/foo.gd    # 单文件文本规则，最快
bash tools/check.sh --staged                 # 暂存文件 + 文档元数据 + 编译 + 情景测试
bash tools/check.sh --all                    # 单测 + 全量文本规则 + 文档元数据 + 编译 + 情景测试
bash tools/check.sh --scenario save_roundtrip    # 只跑指定情景，调试用
```

若 Godot 不在默认路径，先 `export GODOT_BIN=".../Godot_v4.7.2-stable_win64_console.exe"`。首次使用跑 `bash tools/install.sh` 将 `core.hooksPath` 指到 `tools/git-hooks/`（提交跑 `--staged`，推送跑 `--all`）。Claude Code 的 `PostToolUse` hook 仅对 `.gd/.tscn/.tres` 跑单文件 lint；`PreToolUse` hook 跑 `tools/git_guard.py` 拦截破坏性 git 命令（`push --force/-f`、`reset --hard`、`clean -f`、`branch -D`、`checkout --/.`、非 `--staged` 的 `restore`）。

## 规则

Python 规则（`tools/lint/rules.py`）：

| ID | 检查 | 级别 |
|---|---|---|
| `no-comments` | 首方 `.gd` 禁普通注释；仅放行 `@export` 文档、`@meta_*` 来源、单行 `# why:`/`# invariant:`（≤120 字）与生成文件 | error |
| `resource-name-cjk` | `.gd/.tscn/.tres` 中的中文 `resource_name` | error |
| `file-access-boundary` | `FileAccess`/`DirAccess` 出 `Scripts/save/`、`Scripts/mod/`、`Scripts/debug/`、`EngineTools/modkit/` | error |
| `mod-path-root` | 裸写 `res://base_mods`、`user://mods`、`res://mods` 根路径 | error |
| `inline-color` | 表达式里内联 `Color(...)` 字面量；命名常量/声明不受影响 | error |
| `dependency-boundary` | 跨层引用只走 `tools/lint/boundaries.toml` 声明的方向；并校验 `[autoload]` 与 `project.godot` 零漂移 | error |

**文档元数据与路由校验（`tools/lint/index_meta.py`）**：
- `--staged` 与 `--all` 自动扫描 `DOC/**/*.md` 校验文档头（`类型`/`状态`/`核对|整理` 与 `YYYY-MM-DD` 日期格式），并校验 `DOC/INDEX.md` 路由表中每条 `.md` 路径真实存在；加 `--strict-budget` 额外校验单篇 ≤200 行且 ≤12 KB。

**依赖边界（`tools/lint/boundaries.py` + `boundaries.toml`）**：
- 按最长路径前缀匹配层，同层与未纳管目录（`Assets/`、`mods/`、`user://`）放行；检测 `res://` 字面量、全仓扫描的 `class_name` 与 autoload 单例名。`game/content/` 仅读数据面向层，不得引用 `game/battle/`；改边界先改表。

**注释策略（`tools/lint/comment_policy.py`）**：
- 首方 `.gd` 禁普通注释与 `#region`/`#endregion`，长篇设计、数据流与多模块坑写进 `DOC/`。
- 仅放行四类：
  1. `@export` 及其变体正上方或行尾的 `##`（Godot Inspector 显示）；
  2. `## @meta_addon` / `## @meta_author` / `## @meta_license` 来源标注；
  3. 单行 `# why:` / `# invariant:` 契约标注（非空且总长 ≤120 字符，就近说明不可直观读出的顺序/边界不变量）；
  4. `godot_gas/gameplay_tags.gd`（插件生成文件）。
- 批量清理用 `tools/lint/strip_comments.py`（`--dry-run` / `--check` / `--write`），流程见 `.claude/skills/delete-comment/SKILL.md`。

**Godot 警告与编译检查**：
- `project.godot` 除 `unsafe_*`、`missing_tool`、`inferred_declaration`、`untyped_declaration`、`return_value_discarded` 外全部提为 error（排除 `res://addons`）。
- `tools/compile_check/check_scene.tscn` 在隔离临时 `user://` 中逐个 `load()` 首方脚本/场景/资源，缺 `CHECK_TOTAL` 或编译错即判红；新增 `class_name` 时脚本自动先跑 `--import`。

## 情景测试

`tools/scenarios/` 驱动真实入口断言可见状态（每例输出 `SCENARIO <名> PASS|FAIL`，结尾 `SCENARIO_TOTAL` / `SCENARIO_FAILED`；空用例判失败；用例自清全局状态）。新增用例在 `cases/` 继承 `ScenarioCase` 并注册到 `run.gd::CASES`；领域行为变更必须同步情景覆盖。现有用例：`save_roundtrip`、`map_place`、`soul_emotion_roll`。

## 例外、新增规则与边界

- **例外（`tools/lint/allowlist.toml`）**：`rule`、`path`、`reason`、`expires` 四字段缺一不可，过期或全量检查未命中均判红。
- **新增规则**：在 `tools/lint/rules.py` 加类 + `tools/lint/tests/test_rules.py` 补正反单测 + 跑 `--all` 建基线 + 更新本页规则表（预算 ≤10 条）。
- **边界**：不检查 `addons/`、`EngineTools/{kanban_tasks,color_catalog}/`、`.godot/`、`base_mods/`、`mods/`；CI 见 `.github/workflows/check.yml`。
