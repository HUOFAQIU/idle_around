## 1. 启动与窗口外壳

### 1.1 单窗口模型

`project.godot` 的 `[display]`：

- `window/size/viewport_width=1600`、`viewport_height=960`；
- `window/size/initial_position_type=1`（居中主屏）；
- `window/subwindows/embed_subwindows=true`：所有 `Window` 都是主视口里的嵌入子窗口，只有一个 OS 窗口；
- 不可缩放、不可最大化。

主场景 `Main/control.tscn` 根节点是 `Control`，全屏锚点：

```
Control (control.gd)
├─ WorkspaceBackground (ColorRect)          → 深色工作区底
├─ PetPanel (300×300，默认左下角)           → 主界面浮层
│  ├─ Background (Panel)
│  ├─ StatusBarContainer                    → < T > 状态栏
│  └─ GridContainer                         → 3×3 功能按钮
├─ CharacterWindow / VesselWindow / InventoryWindow / BattleWindow /
│  ShopWindow / CollectionWindow / InfoWindow / DebugWindow / ModWindow
│                                            → 嵌入 Window，layer 1024
├─ DragLayer (CanvasLayer, layer=1025)
│  └─ ItemWindow (Control)                   → 拖拽幽灵浮层
└─ TooltipLayer (CanvasLayer, layer=1026)
   └─ TooltipWindow (Control)                → 悬停提示浮层
```

- 嵌入 Window 固定在 layer 1024；`CanvasItem` 在 1025 及以上才会盖在它们上面（Godot `CanvasLayer` 文档）。所以 Tooltip/Item 必须放在 1025+ 的 CanvasLayer 里。
- `PetPanel` 在 layer 0，会被嵌入面板盖住；面板可拖动/关闭，关掉后主界面重新可见。
- `control.gd::popup_window()`：
  - 已可见 → `hide()`；
  - `BaseWindow` → `open_window()`；打开位置是主视口内的 `open_position`，没配就 `popup_centered()`（在主视口内居中）。
- 存档读档时机、mod 挂载时机与旧版一致；`SaveManager` 仍等一帧再读档。

### 1.2 BaseWindow

`Windows/base_window.gd`（`extends Window`，但只作为嵌入子窗口使用）：

- `@export var open_position: Vector2i`：**主视口内坐标**；任一坐标为负表示“居中”。
- `open_window()`：
  - `_wrap_content()` 后计算 `_popup_size()`（当前/场景尺寸，夹到主视口大小）；
  - 有位置时先 `_clamp_position()` 再 `popup(Rect2i(...))`，没位置时 `popup_centered()`；
  - 最后同步标题并 `grab_focus()`，再 `call_deferred("_grow_to_content")`：等一帧内容布局完成后按内容最小尺寸向上撑（只增不减，避免 RichTextLabel 在宽度为 0 时算出巨大高度）。
- `_ready()`：先设 `borderless = true`（嵌入子窗口默认还会画一层 Godot 自绘的窗口装饰：居中标题 + 关闭按钮，会和自绘标题栏叠成两层），再创建 28px 标题栏（左侧标题、右侧关闭按钮），连接 `close_requested → hide()`；不再设置 `unresizable/minimize/maximize` 等原生装饰开关，也不再读写每窗口置顶状态。
- `_build_title_bar()`：`TitleUI/TitleBar` 下依次是 `TitleMargin/TitleLabel`、额外按钮（`add_title_bar_button()`）、`CloseButton`、右侧留白。标题读 `Window.title`，脚本后续改 title 时由 `title_changed` 同步。
- 拖动：标题栏空白区域的 `gui_input` 只负责按下/抬起；拖动期间通过 `SceneTree.process_frame` + `Input.is_mouse_button_pressed()` 每帧读主视口鼠标并更新 `position`，累加后 clamp 到 `[0, 主视口尺寸 - 窗口尺寸]`。这样鼠标快速拖出嵌入窗口边缘也不会断。嵌入窗口没有原生标题栏可拖，必须走这套。
- `add_title_bar_button(button)`：子类在 `super()` 之后调用，按钮插到关闭按钮左侧，沿用统一字号/光标/按下高亮。
- `_wrap_content()`：把原内容挪进 `ContentRoot`，窗口高度和 `min_size.y` 各加 28；`CanvasLayer` 不移动，只把顶边锚定的 Control 下推 28px（BattleWindow 血条依赖）。
- `suspend_topmost()/resume_topmost()/set_pinned()/is_pinned()/get_pin_key()` 已删除：单窗口里没有子窗口系统置顶。

### 1.4 两个浮层单例

后加载的脚本通过静态变量拿单例：

| 类 | 单例 | 关键接口 |
|---|---|---|
| `TooltipWindow` | `TooltipWindow.instance` | `show_tip(owner, layer, title, body := "")` / `hide_tip(owner)`；层级 `COORD < ITEM` |
| `ItemWindow` | `ItemWindow.instance` | `hold(view, offset, base_size)` / `clear()` |

- **TooltipWindow** 现在是 `PanelContainer`，挂在 `TooltipLayer`（layer 1026）下：
  - `_place_tip()` 用 `get_viewport().get_mouse_position()` 和 `get_viewport_rect().size`，默认在鼠标右下方，右边/下边放不下就翻边，再夹回主视口；不再有 OS 窗口的显示/隐藏闪烁。
  - `show_tip()` / `hide_tip()` 仍按 owner + 层级记账，低层级不能覆盖仍有效的高层级；同帧 hide+show 会合并。
  - 正文由 `SoulTooltip.build()` / `VesselTooltip.build()` 生成；正文为空时隐藏 `BodyLabel`。`TooltipText` 的颜色和 BBCode 转义逻辑不变。
  - 根节点 `mouse_filter = IGNORE`，不会挡住下面的面板。
- **ItemWindow** 现在是 `Control`，挂在 `DragLayer`（layer 1025）下：
  - `hold()` 把 `ItemView` 加进来，整棵子树递归设 `mouse_filter = IGNORE`，避免幽灵挡住放置/取消事件。
  - `_process` 每帧用 `get_viewport().get_mouse_position() - _grab_offset` 跟随鼠标；尺寸跟物品视图同步。
  - 不再需要屏幕外预热、跨窗口焦点监听、topmost 降级/恢复、`DisplayServer.window_set_flag`、`get_window_id()` 这些原生窗口补丁。
  - 幽灵只能在主窗口内跟随；拖到窗口边缘会被裁掉，这是单窗口模式的正常代价。
- **InfoWindow** 仍是普通 BaseWindow，战斗日志的裁剪逻辑不变（见 `现状与注意.md` 第 55 条）。

### 1.5 主界面与贴边

- `PetPanel` 是 300×300 的主界面浮层，默认左下角；`Scripts/setting.gd` 已删除，主窗口由项目设置居中。
- `Main/status_bar_container.gd`：
  - `<` → `_move_pet_panel(false)` 把 `PetPanel` 摆到工作区左下角；
  - `>` → `_move_pet_panel(true)` 摆到右下角；
  - `T` → 切换**整个主窗口**的 `always_on_top`，状态写入 `user://Settings.cfg` 的 `[window_pins]`，键 `main_window`。
- 偏移量都来自 `GameGlobal.WINDOWPOSOFFSET`（5px）。

### 1.6 置顶

- 单窗口模式只有整个应用可以置顶：`Main/status_bar_container.gd` 的 T 按钮 + `WindowPinSettings.MAIN_WINDOW_ID`。
- 面板标题栏只有拖动、标题、关闭（以及见闻的“全解锁”按钮），没有每面板 T；`BaseWindow` 不再读写 `Settings.cfg` 的窗口条目。
- `TooltipWindow`/`ItemWindow` 不再有 `transient`/`always_on_top`/`unfocusable`/`mouse_passthrough` 等原生标志。
- TestAPI 的 `set_window_pinned()` / `is_window_pinned()` / `get_window_pin_states()` 只支持 `MainWindow`；其他名字返回 false。

## 2. 场景与配置

### 2.1 `Main/control.tscn`

- 根 `Control` 全屏锚点；
- `WorkspaceBackground` 深色底；
- `PetPanel` 300×300，默认 `(5, 655)`；
- 9 个 BaseWindow + 内联 ModWindow；
- `DragLayer`（1025）里是 `ItemWindow`，`TooltipLayer`（1026）里是 `TooltipWindow`；
- 各窗口的 `open_position` 是工作区局部坐标：Character 在场景里配 `(20,20)`，Vessel `(20,320)`，Inventory `(735,20)`，Battle `(560,20)`，Debug `(200,80)`；Shop/Collection/Info/Mod 未配置 → 居中。

### 2.2 `BattleWindow`

- 场景尺寸 1000×892（运行时加 28 = 1000×920），默认位置 (560,20)；
- `Tile` 从原 `(490,475)` 改到 `(500,409)`，并设 `scale = (0.8, 0.8)`：
  - 地图本地范围约 896×864；缩放后约 717×691；
  - 实测窗口内范围 x 154.4～871.2、y 104.2～795.4，血条顶部在 802，互不重叠；
  - 战斗逻辑用 Tile 局部坐标和 `BattleGrid.cell_size_px`，缩放只影响视觉，不影响格距/距离判定。
- 顶部按钮栏和 FPS 在 `CanvasLayer/Control` 里，仍由 `_shift_canvas_layer_top()` 下推 28px；
- 5 条生命/状态条底边锚定，保持贴窗口底部；
- `_is_mouse_inside()` 用 `Rect2(Vector2.ZERO, size).has_point(get_viewport().get_mouse_position())`，不再和屏幕坐标比较；
- `has_focus()` 仍用于坐标 tooltip 的优先级；嵌入窗口失去焦点时不再显示坐标提示。

### 2.3 人物窗口与魂器窗口

**人物窗口**（`character_window.tscn`）：

- `InfoLabel`（RichTextLabel）+ 9×3 魂器网格 `vessel_cells`；
- 窗口尺寸 360×240，运行时 360×268。

**魂器窗口**（`vessel_window.tscn`）：

- 单例 `SoulVesselWindow.instance`；
- `_fit_to_contents()` 按容器行列计算尺寸，使用 `TITLE_BAR_HEIGHT`，并把结果 clamp 到主视口；
- 右键魂器 → `GBIS.sig_item_activated` → `open_for(vessel)`；关闭窗口不清空魂器内容；
- 悬停由 `TooltipWindow` 统一显示 `VesselTooltip`。

## 3. 常见排查

1. **窗口跑到工作区外/被裁**
   - 所有 `open_position` 都是主视口局部坐标；负数才是居中；
   - `BaseWindow._popup_size()` 会把窗口夹到主视口大小，`_clamp_position()` 会夹位置；打开后 `_grow_to_content()` 会在布局完成后再按内容最小尺寸向上撑（只增不减）；
   - 主窗口固定 1600×960，面板超过这个尺寸会被裁；大容器（魂器）会按视口上限截断。

2. **标题栏拖不动 / 关不掉**
   - 标题栏空白区域的 `gui_input` 只处理按下/抬起；真正移动由 `SceneTree.process_frame` 轮询、`Input.is_mouse_button_pressed()` 判断按键，鼠标拖出嵌入窗口边缘仍会继续；
   - 关闭按钮是 `TitleUI/TitleBar/CloseButton`，`pressed → hide()`；`close_requested` 只作为 Alt+F4 等系统关闭的兜底；
   - 嵌入窗口没有系统标题栏，不要指望系统 X 或系统拖动；`_ready()` 的 `borderless = true` 必须保留，否则会多出一层 Godot 自绘标题栏。

3. **Tooltip/拖拽幽灵被面板盖住**
   - 嵌入 Window 固定在 layer 1024；`TooltipLayer` 必须是 1026，`DragLayer` 必须是 1025；
   - Tooltip/Item 必须留在对应 CanvasLayer 下，不要塞回根 Control 或嵌入 Window。

4. **拖拽时点不到格子/放不下物品**
   - `ItemWindow` 根节点和它的整棵子树都必须是 `MOUSE_FILTER_IGNORE`；`hold()` 里已有递归处理；
   - 幽灵只在主视口内，鼠标拖出主窗口不会继续跟随。

5. **战斗地图被裁/压住血条**
   - BattleWindow 的 Tile 位置和 0.8 缩放是按 1600×960 工作区算的；改主窗口尺寸或血条高度后要重新核对 Tile 的 `(500,409)`、`scale` 和血条顶部；
   - 不要直接缩小 TileMap 的格数来适配窗口，那会改变战斗距离。

6. **调试/Mod 内容错位**
   - 这两个窗口的 UI 全是脚本构建；标题栏会占 28px，Root 在 ContentRoot 里；
   - DebugWindow 固定 1200×760，不再支持窗口缩放；ModWindow 固定 760×520。

7. **测试置顶状态**
   - 单窗口只有主窗口能置顶：`TestAPI.set_window_pinned("MainWindow", true/false)`；
   - 面板的置顶状态 API 已移除，不要再用 `CharacterWindow` 等名字。
