## 1. 运行时对象图与脚本归属

```text
BattleWindow (Control) ── BattleArena ── BattleSim ── BattleSession ── BattleManager (每场新建)
                                           ├─ BattleUnitBatchRenderer (3D MultiMesh 合批)
                                           └─ Battle3DBridge / CombatNarrator / CombatTelemetryAdapter

BattleUnit (轻量纯逻辑 Node，无 2D 物理/贴图，射程外 ASC 自动休眠)
├─ AbilitySystemComponent (节点名必须精确为此值，GAS 按名查找) ─ AutoCastAbility...
└─ BattleBrain (射程外关物理帧)
```

- `BattleManager` 只作门面与调度（名册/空间索引/地图换算/掉落全委托协作者），按实例 ID 分片移动，维护 `UnitMoved`/`FreezeApplied`/`SlowApplied` 监听者表；怪物在攻击范围外时由 `BattleManager` 直接关掉物理帧。
- `SoulLoadout` 是玩家/怪物唯一装载器（怪物走 `SoulSlot.virtual_slots()`）；`AutoCastAbility` 发射投射物即返回（投射物挂施法者不占 `is_active`）；取整与护盾分流集中在 `DamageResolver`。

## 2. 一帧施法链路与激活锁

`BattleBrain._physics_process()` 在未死、战斗运行中且（敌人）处于攻击范围内时，以 `base_units = 120 * BattleClock.tick_seconds`（60Hz 为 2 刻/帧）分三段执行：

1. **推进与状态扣减**：所有魂灵先 `advance_activation_lock(base_units)`；未遭单位/魂灵冻结时 `advance_charge(base_units)`（吟唱期间继续充能）；最后 `advance_status(base_units)` 扣减加速/减速/冻结时长。**状态扣减必须在充能之后**，确保持续 N 刻的状态精确影响 N 刻充能（反序会导致常驻加速临界配速逐次晚 1 刻）。
2. **主循环释放**：未遭单位冻结时，按已排好序的 `abilities` 数组（魂器网格从上到下、从左到右 → 魂器内部从左到右）依次释放就绪且未锁的魂灵（`try_activate()` 开火即忘）。
3. **帧末补发队列**：`flush_pending_activations()` 按入队顺序释放本帧由触发器充能满的魂灵（跨单位触发器由 `BattleManager` 在物理 tick 末统一 flush，不再用 `call_deferred`，释放前重走死亡/冻结/范围门控，单帧队列上限 64）。

- **敌人轮询早退**：`ChargedAbility.units_until_work()` 给出该魂灵距下次需要处理的刻数：吟唱中、冷却为 0、单位级冻结或魂灵冻结时返回 0（冻结期间不攒刻）；否则取充能剩余刻（加速减半、减速翻倍）、激活锁剩余刻与加速/减速剩余刻的最小值，状态到期或速度变化时提前醒来重算。补投按全额充能，保证冻结前攒下的刻不被冻结吞掉。`BattleBrain` 为每个单位缓存全部魂灵的最小值 `_units_until_work`：敌人本帧 `base_units` 小于它时只做减法并累积 `_deferred_units`，跳过上面三段流程；等需要处理、离开射程、遇单位级冻结（`State.Frozen` 标签不发信号，在冻结分支入口补投）或状态被标脏（`add_ability` / `begin_charge` / `request_activation` / `charge_added` / `status_applied`）时，用 `_flush_deferred_units()` 把攒下的刻一次性补投，充能总量与逐帧推进一致。玩家 brain 不做早退，冷却与 UI 保持逐帧精度；敌人中途的 `charge_units` / `charge_ratio` 读数是惰性的（延后未补投），调试遥测只在补投刻跳变。1000 只射程内敌人时轮询从约 19ms/物理帧降到约 1ms。
- **20 刻激活锁**：`ChargedAbility.ACTIVATION_LOCK_UNITS = 20`（1/6 秒，1 秒最多 6 次），自定义子类必须在 `_activate_ability()` 先 `can_activate_now()` 再 `mark_activated()`。多重触发（`cast_times > 1`）复用同一把锁，超出顺延，期间 `is_active` 保持 true，遇冻结/停战/倒下停止。吟唱等待走 `BattleClock.wait_ticks()`，不用 GAS 渲染帧延迟。

## 3. 冷却刻度、扫描线与状态徽章

- **1/120 秒刻度**：冷却唯一来源为 `SkillDefinition.cooldown_seconds`（`GameplayAbility.cooldown_effect` 留空）。60Hz 下基础 +2/帧，加速 +4（2×），减速 +1（0.5×），同时存在 +2（1×）；重复施加同状态累加时长不叠倍率。本 tick 施加的状态下 tick 生效；外部 `add_charge(秒)` 不受加减速与冻结倍率影响，溢出丢弃。同魂灵装两份生成两个独立能力不去重。
- **扫描线与徽章**：`BattleWindow._physics_process()` 调 `SoulRuntime.refresh_from_ability()` 直接改材质参数（统一 `line_color = #8cd9ff`，被动魂灵跳过）。`ItemView` 按 0.1 秒精度显示加速（上）/冻结（中）/减速（下）徽章，魂灵冻结同步开启 `soul_scanline.gdshader` 冰霜参数；`BattleSession.stop()` 统一清零。冻结语义详参 `战斗运行时_伤害与流程.md` §2。

## 4. 时间模型与已知限制

- 固定 tick（`BattleClock` 唯一时钟）：`BattleBrain`、`BattleManager` 移动、`SoulProjectile`、`BattleSession` 刷怪、吟唱等待、跨单位触发器 flush。`TestAPI.pause_battle()` + `step_battle(n)` 手动步进时同步推进 `ASC.advance_time()`（新入场单位须同步设 `ASC.manual_time`；内部重开沿用手动模式，外部 `stop()` 恢复正常）。
- **已知限制**：正常游玩时 GAS 持续/周期效果仍由 `ASC._process(delta)` 按渲染帧推进；当前 `max_fps=60` 与物理 60Hz 重合，改帧率或掉帧时会与固定 tick 产生轻微偏差。
