# 颜色与主题

> 类型：实现 | 状态：有效 | 核对：2026-11-21
> 何时读：改任何颜色、新增 UI/特效、调整色板
> 关键词：颜色 色板 GameColors 色值 主题 Theme 战斗状态 UI 场景 特效 爪痕 CLAW_SLASH 编辑器 主屏幕
> 代码：`Scripts/game_colors.gd`、`Scripts/game_color_catalog.gd`、`EngineTools/color_catalog/`
> 相关：`魂灵/魂灵.md`、`架构/窗口与场景.md`

项目里的**单色**统一放在 `Scripts/game_colors.gd` 的 `GameColors`。颜色用 HTML 十六进制字符串保存；需要 `Color` 时调用 `GameColors.to_color()`。多段粒子渐变属于特效资源，留在各自场景里。

## 分区

| 区 | 常量 | 用途 |
|---|---|---|
| 战斗状态 | `DAMAGE`、`BURN`、`POISON`、`HASTE`、`SLOW`、`CHARGE`、`REGEN`、`HEAL`、`CRIT`、`FREEZE`、`SHIELD` | tooltip / 战斗日志 / 飘字 / 状态条 |
| UI 文字 | `TEXT_PRIMARY`、`TEXT_SECONDARY`、`TEXT_DISABLED`、`TEXT_OUTLINE`、`TEXT_OUTLINE_SOFT`、`LOCKED_MODULATE` | Label、提示、未遇见条目 |
| 面板 | `TOOLTIP_BG`、`TOOLTIP_BORDER`、`PANEL_SEPARATOR`、`WINDOW_TITLE_BAR` | tooltip 面板、面板分隔线、窗口标题栏背景 |
| 语义 | `ACCENT`、`ACCENT_TEXT`、`SUCCESS`、`WARNING`、`DANGER`、`INFO` | 置顶按钮、FPS、调试状态 |
| 血条 | `BAR_BORDER`、`BAR_BG`、`STATUS_BAR_BG`、`HEALTH_FILL`、`HEALTH_FILL_ENEMY` | 玩家/单位血条、状态条 |
| 背包网格 | `GRID_BORDER`、`GRID_EMPTY`、`GRID_TAKEN`、`GRID_CONFLICT`、`GRID_AVAILABLE`、`GRID_AVAILABLE_SLOT`、`GRID_UNAVAILABLE_SLOT`、`SOUL_NAME`、`SOUL_NAME_OUTLINE`、`STACK_NUM` | 背包、装备槽、魂灵卡面 |
| 魂灵/场景 | `SOUL_LINE`、`SOUL_FREEZE`、`PLAYER_MODULATE`、`ENEMY_MODULATE`、`PROJECTILE`、`CLAW_SLASH`、`POISON_SPLASH`、`FREEZE_BADGE_BG`、`FREEZE_BADGE_BORDER` | 扫描线、阵营染色、投射物、命中爪痕、剧毒飞溅、冻结徽章 |
| 调试 | `DEBUG_TEXT`、`DEBUG_HINT`、`DEBUG_COUNTER`、`DEBUG_NAME`、`DEBUG_STATUS`、`DEBUG_HIGHLIGHT` | 调试窗口 |

`STATUS` 是显示名 → 颜色映射，`STATUS_PATTERN` 是 tooltip 关键词正则，两者和状态色一起维护。正则里长词放前面，避免「生命再生」「暴击率」被拆成短词。

## 分类数据

`GameColors.GROUPS` 是机器可读的分类（组名 → 常量名数组），与上面分区表一一对应。

`GameColorCatalog`（`Scripts/game_color_catalog.gd`）负责派生和校验，编辑器色板与 TestAPI 共用：

- `groups()`：按 `GROUPS` 分组的色卡数据
- `aliases()`：同色别名（`DAMAGE` / `CRIT` 等）
- `ungrouped()`：漏归类的颜色常量
- `status_entries()`：`STATUS` 显示名映射
- `terminal_palette()`：终端 16 色与默认前景/背景
- `validate()`：分组问题列表

## 可视化色板

`EngineTools/color_catalog/` 是项目自己的编辑器插件，已在 `project.godot` 的 `[editor_plugins]` 中启用。

- 编辑器顶部（2D / 3D / Script 旁）会出现「色板」主屏幕页；点击页签切换，切回时自动刷新。
- 分区展示 `GameColors.GROUPS` 的色卡（色块 + 常量名 + hex）；点击复制 `GameColors.常量名`。
- 另有同色别名、`STATUS` 状态词、终端色板、未归类警告四个区；终端色卡点击复制 hex。
- 保存 `game_colors.gd` 或 `terminal_palette.gd` 后自动刷新；也可点「刷新」。
- 插件只在编辑器生效，不影响游戏运行/导出。

## 场景颜色

- 人物窗口底色用默认灰，分隔线用亮一档的 `PANEL_SEPARATOR`；tooltip 的暗色在这里几乎不可见。

`.tscn` 不能引用 GDScript 常量，所以场景里**不再写颜色**，由脚本在运行时赋值：

- `battle_window.gd::_ready()`：用 `GameColors.build_label_theme()` 给 `$UiOverlay/Control` 设置 Label 的默认文字色和描边色；FPS 颜色仍由 `_fps_color()` 动态计算。
- `tooltip_window.gd::_ready()`：给面板 StyleBox 设置 `TOOLTIP_BG` / `TOOLTIP_BORDER`。
- `collection_window.gd::_ready()`：设置底部提示文字色；未遇见条目的 `modulate` 也来自 `GameColors.LOCKED_MODULATE`。
- 血条、状态条、背包网格、魂器网格、调试面板在 `_draw()` / 建节点时从 `GameColors` 取色。
- `player.tscn` 保留 `tokens.png` 贴图；怪物场景的 `Body` 不写贴图，由 `MonsterData.icon` 注入。Body 阵营染色在 `BattleUnit.setup_from_scene()` 里按队伍写入，头顶名字的颜色也在那里设置。
- `soul_projectile.gd`、`poison_splash_cue.gd`、`freeze_badge.gd`、`claw_slash_painter.gd` 在各自 `_ready()` / `play_cue()` / `_draw()` 里取色。

## 魂灵 shader

- 扫描线开关只对挂 `soul_scanline.gdshader` 的物品有效；挂其他 shader 无害但也无效。

- `SoulData.material` 的颜色以 `GameColors.SOUL_LINE` / `SOUL_FREEZE` 为准，`ItemView._init()` 在 duplicate 材质后覆盖；部分旧魂灵 `.tres` 仍留有历史 `line_color` / `freeze_color` 字段，新资源不要再写。
- `Assets/Shader/soul_scanline.gdshader` 里的默认值只作兜底；改颜色时改 `GameColors`，不要改各魂灵资源。

## 例外

- `base_mods/core/cues/*.tscn` 里的 `PackedColorArray` 是多段粒子渐变（火焰、冰霜、毒雾等），属于特效资源，留在场景内调；它们不是可复用的单色语义。
- `addons/` 下的颜色属于第三方插件，不纳入本项目色板；`EngineTools/color_catalog/` 是本项目自己的编辑器插件，只展示色板，不定义颜色。

## 改颜色

1. 改单色：只改 `GameColors`，不要在脚本或场景里重新写 `Color(...)`。
2. 新增颜色：先判断属于哪个区，加常量并写注释。
3. 需要 `Color` 常量（如构造默认参数）时，在 GameColors 里加一个 `*_COLOR` 的 `Color` 常量；需要 BBCode 时继续用十六进制的字符串常量。
4. 新增颜色后，把常量名加进 `GameColors.GROUPS` 对应分组；漏加时色板「未归类」区和 `TestAPI.validate_color_groups()` 会报出来。
