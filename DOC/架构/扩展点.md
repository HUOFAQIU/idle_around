## 1. 扩展点

### 1.1 新增一颗魂灵

1. 主动魂灵：在 `base_mods/core/souls/<名字>/` 下新建技能资源（`*_skill.tres`）：
   - `SkillDefinition` 的 `id`（GAS 标签后缀：core 与魂灵 ID 对应；留空时 `ModLoader` 自动派生）；
   - 共享配置：`cooldown_seconds`、`cast_times`（多重触发次数，默认 1）、`crit_chance`、`crit_multiplier`、`cast_time`、`cast_require_all_tags`、`cast_block_tags`；
   - `self_effects`：只对施法者自己结算的 `GameplayEffect`；steps 空放也生效；
   - `steps`：按顺序执行的步骤数组，常用两种：
     - `UnitSkillStep`：`target_rule` 选 `TargetRule`（UNIT），配 `effects`，可选 `status_magnitude`（覆盖 `StatusApplyExecution` 的数值，< 0 = 用效果资源默认值）/ `hit_cue_tag` / `projectile_scene` / `projectile_speed`；
     - `SoulSkillStep`：`target_rule` 选 `SoulTargetRule`（SOUL），配 `haste_duration` / `slow_duration` / `freeze_duration` / `charge_duration`；
   - 一个技能可以混合多个步骤，例如「先打怪，再给右侧魂灵加速」；每步独立选目标、独立结算；
   - `UnitSkillStep.effects` 里的伤害效果挂 `SoulDamageExecution`（`game/battle/soul_damage_execution.gd`），填 `base_damage`；需要“每有一颗某类型魂灵 +X 伤害”时再填 `bonus_per_matching_soul` 与 `matching_soul_types`（数量取自 `BattleUnit.loadout`，包含魂灵自己）；治疗、灼烧、剧毒、生命再生不要挂；
   - 护盾效果挂 `ShieldExecution`（`game/battle/shield_execution.gd`），填 `base_shield`；
   - 落地数值（`base_damage` / `bonus_per_matching_soul` / `base_shield` / `base_heal` / `base_amount` / `status_magnitude`）请写整数；计算过程允许小数，最终写入属性前统一向下取整；
   - `UnitSkillStep` 的 `hit_cue_tag`：命中特效标签，每次结算到目标身上时播一次；必须已注册，启动时会检查；接线见 `特效/effects.md`；
   - `ModLoader` 校验每个 step：`UnitSkillStep` 的规则必须是 `TargetRule` 且至少有 `effects` 或 `projectile_scene`；`SoulSkillStep` 的规则必须是 `SoulTargetRule` 且至少有一个状态时长；未知 step 类型会报错。
   - 同一个效果资源想在不同技能里用不同状态层数时，给步骤设 `status_magnitude`，不必复制效果资源；同一步骤内多个状态共用这个数值，需要不同数值就拆成多个步骤。
2. 新建魂灵资源（`*_soul.tres`）：
   - 主动魂灵用 `SoulData`，`skill` 指向上面的技能；
   - 被动魂灵用 `PassiveSoulData`（`game/content/passive_soul_data.gd`），`passive_effects` 填 `PassiveEffect`（`game/content/passive_effect.gd`，继承 `GameplayEffect` 的标记类），不填 `skill`；`PassiveEffect` 类型不写状态日志；
   - `types` 填语义类型（如 `Soul.types.Wolf`、`Soul.types.Animal`，供触发规则和按类型数量加伤筛选）；`tags` **必须且只能**带一个尺寸标签（`Soul.tags.Small/Medium/Large`），再按需加效果标签（`Soul.tags.Damage` 等）；两者前缀和 PascalCase 后缀由 `ModLoader` 校验；
   - 尺寸中文名统一在 `Scripts/soul_text.gd` 的 `SoulText.SIZE_NAMES` 里补，语义类型中文名在 `TYPE_NAMES` 里补，不在魂灵资源里重复填；未知类型会回退到 ID 最后一段；
   - 触发规则 `SoulData.triggers` 主动/被动魂灵通用，填 `PassiveTrigger`（`game/content/passive_trigger.gd`）：
     - `event_tag` 选 GAS GameplayEvent，可选事件与 payload 见 `架构/战斗数据与魂灵.md` §魂灵触发器；必须以 `Event.` 开头（`ModLoader` 校验）；
     - `target_scope` 选事件目标 / 自己 / 全体敌人；`max_range`（格，0 = 不限）限制事件目标与全体敌人的生效距离；
     - `threshold_ratio` 只对 `Event.Health.BelowPercent` 生效；`once_per_battle` 控制一次性；
     - `required_soul_types` / `require_adjacent` 只对 `Event.Combat.SoulUsed` 生效；
     - `charge_source_seconds` 给来源主动魂灵充能；被动魂灵没有来源技能，忽略；
     - 新增事件：在 `godot_gas/tag_registry.tres` 注册 `Event.*`，在事件产生处 `asc.send_gameplay_event()`，不需要改 `SoulTriggerAbility`；
   - 可选 `tooltip_blocks`（tooltip 正文段落；格式化器用 `===================================` 连接，`{cooldown}` 替换成技能冷却；头部会自动显示尺寸标签）；
   - `item_name`、`category = "SOUL"`、`icon`（按尺寸用 `Assets/soul_small.png` / `soul_medium.png` / `soul_large.png`）、`columns/rows`（和尺寸标签一致：小 1×2、中 2×2、大 3×2）；
   - 扫描线材质（`soul_scanline.gdshader`，`enable = 0`；被动魂灵不会打开它）。
3. 放进游戏：
   - 调试用：在见闻窗口右键魂灵条目放入仓库，或调用 `TestAPI.add_soul(id)`；
   - 正式用：配置到某个怪物的 `soul_entries`，并给这颗魂灵单独配 `drop_chance`；玩家侧要先放进魂器才能战斗。
4. 在 `base_mods/core/mod.json` 的 `content.souls` 加一条 `{ "id": "<名字>_soul", "path": "souls/<名字>/<文件名>.tres" }`；ID 用原值，不加前缀，新内容统一用 `_soul` 后缀。
5. 战斗内不需要改代码：主动魂灵由 `SoulLoadout` 自动生成技能，显示名取 `item_name`；属性型被动由 `BattleSession._spawn_player()` 调 `SoulLoadout.collect_passive_effects()` 收集，并在 `setup_from_scene()` 时挂到玩家 ASC；魂灵触发器由 `SoulLoadout` 统一登记，主动/被动魂灵走同一套绑定。

### 1.2 新增一种怪物

1. 在 `base_mods/core/monsters/<名字>/` 下复制 `snake.tscn` 作为战斗场景，根节点保持 `team = ENEMY`；
2. 新建 `<名字>_monster.tres`（`MonsterData`，`game/content/monster_data.gd`），配置：
   - `display_name`、`icon`（图鉴图标 + 战斗贴图）、`max_health`、`attack_range`、`move_speed`、`spawn_distances`（刷新距离数组，默认 `[3]`；刷怪时从这些距离环的格子中合并随机选一格）；
   - `soul_entries`（携带的魂灵 + 各自的掉落几率；战斗时按列表顺序生成虚拟魂灵栏，配了哪些就排哪些）；
   - `battle_scene` 指向第 1 步的场景；
3. 配场景里的 ASC `attribute_sets`（可用 `MonsterStatsAttributeSet` 或新建）；根节点用 `CharacterBody2D` 并挂 `CollisionShape2D`（模板蛇/蝮用胶囊），场景不再写 `move_speed` / `attack_range` / 名字 / 贴图，全部从 `MonsterData` 注入，移动由 `BattleManager` 统一驱动。注意 `MonsterData.attack_range`（像素）要小于等于它攻击技能 `TargetRule.max_range` 换算后的像素值（格数 × `BattleManager.cell_size_px`），否则怪会停在技能够不着的距离空放；
4. 在 `base_mods/core/mod.json` 的 `content.monsters` 加一条 `{ "id": "<名字>_monster", "path": "monsters/<名字>/<文件名>.tres" }`；刷什么怪由地图配置决定，见 `战斗/地图.md`。

### 1.3 新增一张地图

地图暂不走 mod manifest，硬编码在 `game/content/map_catalog.gd`：

1. 在 `base_mods/core/maps/<名字>/` 新建 `<名字>_map.tres`（`MapData`），配置 `content_id`、`display_name`、`icon`、`spawn_entries`（`MapSpawnEntry` 数组）；
2. 在 `MapCatalog` 登记 id 和资源路径，并在 `get_map_ids()` 里返回；
3. `TestAPI.validate_maps()` 检查字段、怪物 id 和数量石资源；
4. 需要新的刷怪条件类型时扩展 `MapSpawnEntry.Condition`、`MapRun` 和 tooltip 文案。

### 1.4 新增一种魂器

1. 在 `base_mods/core/vessels/<名字>/` 新建 `<名字>_vessel.tres`（`SoulVesselData`），配置 `item_name`、`category = "VESSEL"`、`vessel_kind`（`COMBAT` / `TOOL`）、物品占格 `columns/rows`、内部容器 `container_columns/container_rows`、`tooltip_blocks`；
2. 需要数值效果时加 `SoulVesselEffect`（`game/content/soul_vessel_effect.gd`）；当前只支持 `DAMAGE_BONUS`，新增类型时同时补 `SoulVesselEffect.Stat` 和 `SoulRuntime` / `SoulDamageExecution` 的读取；
3. 在 `base_mods/core/mod.json` 的 `content.vessels` 加 `{ "id": "<名字>_vessel", "path": "vessels/<名字>/<文件名>.tres" }`；
4. `TestAPI.add_vessel(id)` 入仓、`equip_vessel(id)` 装进角色魂器网格、`vessel_add_soul(soul_id, slot)` 往网格里第 `slot` 个魂器放魂灵；详细规则见 `魂灵/魂器.md`。

### 1.5 新增技能（不改代码）

- 用现有 `TargetRule` / `SoulTargetRule` + `GameplayEffect` + `projectile_scene`，按 `steps` 组合即可做出大部分主动技能；
- 新的战斗单位目标模式 → 扩展 `TargetRule.Mode` 和 `resolve()`；
- 新的魂灵目标模式 → 扩展 `SoulTargetRule.Mode` 和 `resolve()`；
- 新的目标域或新的结算方式 → 继承 `SkillStep` 实现 `execute()`，放进 `steps`；`AutoCastAbility` 不需要改，只需在 `ModLoader` 校验里补该步骤类型的检查；
- 新的效果类型（中毒等）→ 先用 GAS 的 `GameplayEffect`（周期效果、modifier）实现，再补标签和 Cue；护盾参考 `ShieldExecution`；
- 单位冻结 → 参考 `freeze_unit.tres`：`DURATION` + `State.Frozen` + 持久 Cue；魂灵级冻结 → 参考 `SoulSkillStep.freeze_duration` + `ChargedAbility.apply_freeze()`；
- 新增持续伤害/生命再生 → 参考 `burn_tick.tres` + `BurnTickExecution` 或 `regen_tick.tres` + `RegenTickExecution`：周期效果只负责计时，每次 tick 用 execution 读取目标状态并返回属性变化；`effect_received` 在周期效果上只表示“已施加”，每跳叙事监听 `periodic_effect_ticked`；
- 新的“状态” → 先加到 `godot_gas/tag_registry.tres`，再用插件重新生成 `gameplay_tags.gd`。

### 1.6 新增窗口

1. 新建场景，根节点用 `Control`，挂一个 `extends BaseWindow` 的脚本；内容必须在 `_ready()` 里同步挂在根下，`BaseWindow` 会在一帧后挪进标题栏下方的 `ContentRoot`。之后动态 `add_child` 的 Control 不会被自动收纳，需要自己挂到 `TitleUI/ContentRoot`，否则会留在标题栏上方且不参与尺寸计算；
2. 在场景里设 `open_position`（或在 `control.tscn` 实例上覆盖），固定尺寸用根节点的 `offset_right/offset_bottom`；
3. 把场景实例加到 `Main/control.tscn`（游戏 UI 覆盖层，实例化在主场景的 `GameUI` CanvasLayer 下）；面板必须和根 Control 同级（不要塞进中间容器），`PanelManager` 会自动识别 `BaseWindow` 直接子节点，运行期新增的也会登记；
4. 在 `Main/control.gd` 的 `_panels` 里登记 id；主菜单按钮写在 `Main/pet_panel.tscn` 的 GridContainer 里，挂 `PanelMenuButton` 脚本并填 `panel_id`。按钮点击后 `PetPanel.panel_requested` 会经 `main.gd` 调 `open_panel()`。

### 1.7 新增特效

按 `特效/effects.md` 的三步走：写 `GameplayCueNotify` 场景 → 官方内容登记到 `base_mods/core/mod.json` 的 `content.cues`（第三方 mod 登记到自己的 `mod.json`）→ 挂到 `GameplayEffect` 的 `application/persistent/periodic/removal_cue_tags`。

UI 物品（例如魂灵格子）没有战场节点，不能直接挂 Cue；参考 `ItemView._apply_freeze_shader()`，用 `SoulData` 的状态字段驱动材质参数和 Kits 徽章。

### 1.8 通过 mod 扩展

官方内容和第三方 mod 都走 `ModLoader`：`CollectionDB` 从 ModLoader 条目构建目录，`ModCueRegistrar` 把 core 和第三方 Cue 注册进 `GameplayCueManager`。官方内容改 `base_mods/core/mod.json`，第三方改自己的 `mod.json`；ID、路径和加载顺序见 `指南/Mod制作.md`，架构见 `架构/Mod系统.md`。

### 1.9 新增角色 / 立方体面内容

新增可选角色：

1. 在 `game/content/Characters/characters/` 新建 `CharacterDefinition` 资源，填 `id`、`display_name`、可选 `portrait`，`profile` 指向该角色的 `PlayerProfile`；
2. 在 `game/content/Characters/character_catalog.gd` 的 `all()` 登记；04 面会和存档槽位自动列出；
3. 存档只记 `character_id` + `display_name`，战斗和人物窗口都从 `GameFlow.get_player_profile()` 取当前角色，不要再用固定 `player_profile.tres`；
4. 旧档没有 `player` 段时按小煤灯迁移；新增角色不影响已有档。

新增立方体面内容：

1. 继承 `FaceContent`，新建内容场景；需要点击优先时设 `ui_capture = true`；
2. 在 `cube.tscn` 对应 `face_3d.tscn` 实例的 `content_scene` 导出里指定内容场景，按需要覆盖 `viewport_size`；
3. 内容信号由 `main.gd` 接线；锁定状态交给 `GameFlow.get_face_lock_state()`，不要在内容里自己判断流程；
4. 流程状态机、锁定表和 01/02/04 面细节见 `架构/开局流程.md`。
