# 改动流程

- 方案先行：功能改动（含新增文件、改接口、动场景结构）先出方案、等确认再改代码；需求含糊先按 `DOC/spec/README.md`「先拷问再写」问清，spec 的触发条件与状态见同页。
- 临时探针（用完即拆的调试代码）按例外：可直接插、自行运行和删除，跑完即拆并把「探针已拆、git diff 干净」报给用户；期间 `addons/` 保持只读。
- 直接替换旧代码、旧命名、旧迁移与旧文档，只留一套命名；通用容错与保留项见 `DOC/指南/开发约定.md` §2。
- 新增功能/内容同步 TestAPI（域模块 + 门面转发），细则见 `DOC/INDEX.md` 写作约定 8。
- 收尾固定顺序 check → review → spec 退出 → commit → 交接；一批改动只跑一轮 `bash tools/check.sh --all`，失败后再修一轮，细则见 `DOC/指南/代码检查.md`。
