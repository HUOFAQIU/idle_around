## 1. 项目概览

| 项 | 值 |
|---|---|
| 引擎 | Godot 4.7（Forward Plus） |
| 主场景 | `Main/control.tscn` |
| 帧率 | `run/max_fps=60`；物理帧默认 60 Hz，充能按 `1/120` 秒的整数刻度累加（60 Hz 下每帧 2 刻度） |

## 3. 启动与窗口外壳

### 3.1 启动链

`Main/control.tscn` 的根节点是 `Control`，挂 `Main/control.gd`。

```
Control (control.gd)
├─ Setting (setting.gd)          → 启动时把主窗口贴到屏幕左下角
├─ StatusBarContainer            → 主窗口顶部状态栏（44px）
│  ├─ Button       "<"           → 主窗口移到左下角
│  ├─ Button2      "T"           → 切换置顶（always_on_top）
│  ├─ Button3/4/5  （空）        → 暂未接逻辑
│  └─ Button6      ">"           → 主窗口移到右下角
├─ GridContainer                 → 3×3 功能按钮
│  ├─ Button  人物  → CharacterWindow
│  ├─ Button2 魂灵  → EquipmentWindow
│  ├─ Button3 仓库  → InventoryWindow
│  ├─ Button4 商店  → ShopWindow
│  ├─ Button5 战！  → BattleWindow
│  ├─ Button6 图鉴  → CollectionWindow
│  └─ Button7/8/9（空）          → 暂未接逻辑
├─ CharacterWindow
├─ EquipmentWindow
├─ InventoryWindow
├─ BattleWindow
├─ ShopWindow
├─ CollectionWindow
├─ TooltipWindow
├─ InfoWindow
└─ ItemWindow
```

`control.gd::popup_window()` 的规则：

- 窗口已经可见 → `hide()`（再点一次就是关）；
- 是 `BaseWindow` → 调 `open_window()`，按 `open_position` 摆放，没配就居中；
- 不是 `BaseWindow` → `popup_centered()`。

### 3.2 BaseWindow

`Windows/base_window.gd`：

- `@export var open_position: Vector2i`：任一坐标为负数表示“居中”；
- `open_window()`：有位置时 `popup(Rect2i(open_position, _popup_size()))`，尺寸取 `max(当前尺寸, 内容最小尺寸)`；
- `_ready()`：禁止缩放、最小化、最大化；
- `close_requested` → `hide()`，并把 `Engine.time_scale` 还原为 `1`。
  - 这是当前临时写法：任何 `BaseWindow` 关闭都会还原全局时间倍率。

### 3.4 三个全局单例窗口

后加载的脚本通过静态变量拿单例，不依赖节点路径：

| 类 | 单例 | 关键接口 |
|---|---|---|
| `TooltipWindow` | `TooltipWindow.instance` | `show_tip(owner, layer, title)` / `hide_tip(owner)`；层级 `COORD < ITEM` |
| `InfoWindow` | `InfoWindow.instance` | `append_line()` / `clear_log()` / `toggle()` |
| `ItemWindow` | `ItemWindow.instance` | `hold(view, offset, base_size)` / `clear()` |

注意点：

- **TooltipWindow 当前没有内容节点**，只把窗口标题设成物品名或格子坐标。
  - `show_tip(owner, layer, title)` / `hide_tip(owner)` 不是立即改 `visible`，而是记账到 `_process` 里统一结算，避免同一帧“先隐藏再显示”导致 OS 窗口闪烁。
  - `COORD` 是战斗窗口的格子坐标，`ITEM` 是物品/魂灵；低层级不能覆盖或隐藏仍然有效的高层级 owner。
  - `_place_near()` 默认在鼠标右下方，右边/下边放不下就翻边，再夹回屏幕内。
  - 当前用 `DisplayServer.screen_get_size()`，不是可用区域。
- **ItemWindow** 的 `_process` 每帧同步尺寸并跟随鼠标；`borderless` 让拖拽时的物品窗口没有标题栏。
- **InfoWindow** 的战斗日志来自 `BattleManager.log_sink`，由 `BattleWindow` 在开战时接上。

### 3.5 主窗口贴边

- `Scripts/setting.gd`：`_ready()` 根据 `DisplayServer.screen_get_usable_rect()` 把主窗口放到左下角。
- `Main/status_bar_container.gd`：`<` 左下角、`>` 右下角；`T` 切换 `always_on_top`，按下态在代码里覆盖成亮绿色。
- 偏移量都来自 `GameGlobal.WINDOWPOSOFFSET`（5px）。

### 4.3 一帧的施法链路

```
BattleBrain._physics_process(_delta)
  if unit.is_dead or battle == null or not battle.is_running: return
  frozen = unit.asc.has_tag(&"State.Frozen")

  # 基础刻度：120 / physics_ticks_per_second × time_scale
  # 60 Hz、1x 时是 2 刻度/帧
  base_units = 120 / physics_ticks_per_second * time_scale

  # 第一段：所有魂灵先结算状态和自然充能
  for ability in abilities:
      charged.tick_status(base_units)        # 加速/减速倒计时
      if not frozen:
          charged.tick_charge(base_units)    # 投射物飞行/吟唱期间也继续充能
  if frozen: return

  # 第二段：按数组顺序释放 —— 数组已按魂灵栏从左到右排好
  for ability in abilities:
      if charged and not charged.is_ready(): continue
      if unit.asc.can_activate_ability(ability):
          ability.try_activate()             # 开火即忘，技能内部自己 await
```

`AutoCastAbility._activate_ability()`：

1. `commit_cost()` + `reset_charge()` —— 充满就放，不等任何东西；扫描线从头重扫；
2. `target_rule` 是 `SoulTargetRule` → 走魂灵分支：选魂灵、施加加速/减速/充能；空放也照常消耗冷却；
3. 否则 `target_rule.resolve(owner_asc, battle)` 选战斗单位；选不到就是空放（照扣冷却，只打日志）；
4. `cast_time > 0` → `await task_wait_delay()`；醒来后先检查 `is_active`，被中断就直接取消，否则**重新选目标**，避免对着尸体放大；
5. `battle.log_cast()` 报幕；
6. 有 `projectile_scene` → 每个目标发一支箭，箭落地时逐支结算；
   没有投射物 → 逐目标直接结算。

魂灵分支的日志格式与状态日志保持一致：
`角色 施放【魂灵A】→ 魂灵B`、`魂灵B 获得状态【加速】（2.0 秒）`、
状态到期时 `魂灵B 的状态【加速】结束`；减速同理；
充能是 `魂灵B 获得充能（2.0 秒）`，没有到期日志。

`BattleBrain` 与 `BattleManager` 的分工：

- `BattleBrain` 管“每个单位自己能做什么”，用 `_physics_process`；
- `BattleManager` 管“场上发生什么”，刷怪用 `_process`，每 `SPAWN_INTERVAL` 秒在距玩家 10 格以外的空格刷一只；
- 两者都受 `Engine.time_scale` 影响（加速按钮改的是全局时间倍率）。

### 4.4 冷却与扫描线

- 冷却不再使用 GAS 的 DURATION 效果，而是 `ChargedAbility.charge_units` 按 `1/120` 秒的整数刻度累加。
  - 60 Hz、1x：每帧基础 +2；加速 +4；减速 +1；加速+减速 +2。
  - 基础刻度 = `120 / physics_ticks_per_second × time_scale`，所以 2x/3x/10x 分别变成 4/6/20。
  - 输出给 UI 的秒数由 `haste_seconds()` / `slow_seconds()` 换算（单位 / 120）。
- 技能冷却时长来自 `SkillDefinition.cooldown_effect.duration`：
  - `AutoCastAbility.apply_definition()` 调用 `setup_cooldown_from_effect()`，然后把 `cooldown_effect` 置空，避免 GAS 门卫去检查它的标签；
  - `MoveAbility._ready()` 做同样的事。
- `cooldown <= 0` 时 `is_ready()` 恒为 `true`、`charge_ratio()` 恒为 `1.0`。
  - 注意：`MoveAbility` 如果忘配 `cooldown_effect`，会变成每个物理帧走一格。
- 扫描线：
  - `BattleWindow._physics_process()` 每帧调用 `soul.set_scanline_progress(ability.charge_ratio())`；
  - `SoulData` 发出 `sig_scanline_progress`，`ItemView` 直接更新自己的材质参数，不再每帧 duplicate `shader_params` 触发全量重绘；
  - 开战 `_set_scanlines(true)`，关窗/结束 `_set_scanlines(false)`；
  - 扫描线材质来自 `Assets/Shader/soul_scanline.gdshader`，参数包括 `line_color`、`band_width`、`intensity`、`enable`、`progress`。
- 同一颗主动魂灵装两份，会生成两个独立的 `AutoCastAbility`，各自充能，不去重。
- 被动魂灵没有 `AutoCastAbility`；`_set_scanlines(true)` 会跳过它，不显示扫描线。
- 加速/减速：
  - `haste_units` / `slow_units` 各自是单个剩余时间（刻度）；加速固定 2x、减速固定 0.5x；
  - 重复施加同一种状态只累加剩余时间（2 秒 + 2 秒 = 4 秒），不会提高倍率；
  - 加速和减速同时存在时，`_charged_units_for_tick()` 返回 1x 刻度；某一方到期后按另一方继续；
  - 只乘 `tick_charge()` 的自然充能，外部 `add_charge(秒)` 直接加的刻度不受影响；
  - 剩余时间归零时在战斗日志里写“状态【加速/减速】结束”；
  - 本帧施放产生的状态，下一帧才开始影响充能（两段式）。
- 充能：
  - `SkillDefinition.charge_duration` 仍是秒；`AutoCastAbility` 调 `target.add_charge(秒)`，内部换算成刻度；
  - 不受加速/减速倍率影响；
  - `add_charge()` 最多加到技能冷却，溢出丢弃，释放时 `reset_charge()`；
  - **充能后如果目标已经满，会立刻在同一帧释放**；没满则继续自然充能；
  - 充能是瞬时的，不新增状态计时/徽章。
- 状态徽章：
  - `SoulData` 保存 `haste_seconds` / `slow_seconds`（战斗显示用，按 0.1 秒取整）；
  - `BattleWindow._push_scanlines()` 每帧从 `ChargedAbility` 写入；
  - `ItemView` 用 `game/content/Kits/jiasu.tscn` / `jiansu.tscn` 显示，加速在上、减速在下，一位小数；
  - 战斗结束/重开时 `_clear_battle()` 清零。
- 顺序：
  - `BattleWindow._equipped_souls()` 按 `HEADSOUL → TORSOSOUL → ARMSSOUL → LEGSSOUL`、行内按列从左到右排序；
  - `_soul_abilities` 与这个顺序一一对应，`BattleBrain` 第二段直接按数组顺序释放；
  - 因此同冷却的魂灵在同一帧按从左到右触发。

### 4.5 投射物与命中

- `AbilityTask_Projectile.execute()` 对每个目标实例化一支箭，瞄准的是**施法那一刻**目标的坐标。
- `SoulProjectile`：
  - 默认速度 `DEFAULT_SPEED = 420` 像素/秒；技能可通过 `SkillDefinition.projectile_speed` 覆盖；
  - 每帧把移动距离拆成小步，逐步检测碰撞，避免高速穿过单位；
  - 命中半径 `HIT_RADIUS = 20`，大于 32×32 贴图的半径；
  - 只打不同阵营、还活着的单位；碰到谁算谁，不一定是原来瞄的那只；
  - 3 秒内没命中就飞空消失；空箭是设计的一部分。
- `AbilityTask_Projectile` 只把“命中支数”交回技能，不交单位名单 —— 因为先落地的箭可能已经把目标打死并释放，名单里会留下已释放对象。
- 每支箭落地都会立刻发 `projectile_landed`，`AutoCastAbility` 就地结算，不等其他箭飞完。

### 4.6 暴击、伤害、护盾与异常状态

- `SkillDefinition.crit_chance`（默认 0）与 `crit_multiplier`（默认 1.5）。
- `PlayerStatsAttributeSet.damage_bonus`（默认 0）是己方魂灵的固定伤害加成；被动魂灵可以增加这个属性。
- 每份直接伤害效果挂一个 `SoulDamageExecution`：
  - `base_damage` 写在 execution 资源里；
  - `execute()` 从施法者 ASC 读 `damage_bonus`，从 spec 读 `Data.CritMultiplier`；
  - 最终 `damage = (base_damage + damage_bonus) × crit_multiplier`；
  - 结果交给 `DamageResolver.split_damage(target, damage, 1.0)`，先扣护盾再扣生命。
- 护盾获得效果挂 `ShieldExecution`：`base_shield × 暴击倍率`，不吃 `damage_bonus`。
- 伤害 + 剧毒效果挂 `PoisonDamageExecution`：先按 `SoulDamageExecution` 得到最终伤害，再把等量数值写成目标的 `poison`。
- 单独施加灼烧/剧毒/生命再生挂 `StatusApplyExecution`：支持触发器传入数值，也支持主动技能按释放时暴击倍率放大，结果向下取整。
- 治疗挂 `HealExecution`：治疗量 = `base_heal × 暴击倍率`；净化量 = `floor(治疗量 × 5%)`，从治疗目标的 `burn` / `poison` 中分别扣除。生命再生不是治疗，不会触发净化。
- `AutoCastAbility` 对每个目标独立掷一次暴击，把倍率写进 spec 的 `Data.CritMultiplier`；不暴击时写 1.0。
- 暴击时 execution 会 `inject_tag(GameplayTags.Event_Combat_Critical)`；`BattleUnit` 用这个标签给日志和飘字加暴击样式。
- **异常状态的暴击只在释放时判定**：施加时把暴击后的数值写进状态；之后灼烧/剧毒/生命再生的每跳都不再暴击。
- 治疗、灼烧、剧毒、生命再生周期本身不挂直接伤害 execution；灼烧/剧毒/再生各自走 `BurnTickExecution` / `PoisonTickExecution` / `RegenTickExecution`。
- 伤害分流规则：
  - 普通伤害：1 点护盾吸收 1 点伤害，护盾不够的部分进生命；
  - 灼烧：对护盾伤害减半并向下取整，破盾后剩余伤害按“1 护盾抵 2 灼烧”进生命；
  - 剧毒：每秒按当前剧毒值（整数）直接扣生命，无视护盾，不衰减；
  - 生命再生：每秒按当前再生值（整数）恢复生命，不衰减，溢出部分由生命上限丢弃。
- 普通伤害/治疗叙事走 `ASC.effect_received`；周期伤害/再生每跳走 `periodic_effect_ticked`；`attribute_changed` 只负责血条和死亡判断。

### 4.7 冰冻语义（已留钩子，效果未实现）

- `ChargedAbility.FROZEN_TAG = &"State.Frozen"`（`BattleBrain.FROZEN_TAG` 是别名），目前**没有**注册到标签表，也没有 Freeze 效果；同帧充能释放前会检查 `is_frozen()`。
- 冰冻期间：
  - 自身不累加充能；
  - 不能释放技能；
  - 外部仍然可以直接调用 `add_charge()` 充能（外部充能技能走的就是这个接口）。
- 解冻后如果充能已满，下一物理帧立刻释放。

### 4.8 玩家与怪物场景

两个场景的根都是 `BattleUnit`，走同一条 `setup_from_scene()` 初始化管线。
`setup_from_scene()` 的第二、第三个参数是可选 `passive_effects` / `passive_triggers`，只有玩家会传：属性效果在血条绑定前挂到 ASC，触发型被动登记到 `passive_triggers` 并监听 `BattleManager.unit_moved`。

**`game/content/Player/player.tscn`**

```
Player (BattleUnit)          unit_name = "角色"，team = PLAYER(0)，max_health = 500
├─ AbilitySystemComponent    attribute_sets = [PlayerStatsAttributeSet]
├─ BattleBrain
└─ Body (Sprite2D)           tokens.png 区域 (32,0,32,32)，绿色
```

- 没有 `HealthBar` 子节点：角色血条显示在 `BattleWindow` 左下角的 `PlayerHealthBar`。
- 没有预挂技能：技能全部来自装备的魂灵。
- `PlayerStatsAttributeSet` 还有 `damage_bonus`（默认 0），供被动魂灵增加己方魂灵伤害。

**`game/content/Monster/snake/snake.tscn`**

```
Snake (BattleUnit)           unit_name = "蛇"，team = ENEMY(1)
├─ drops = [DropEntry(...)]
├─ souls = [SoulData...]
├─ AbilitySystemComponent    attribute_sets = [MonsterStatsAttributeSet]
│  └─ Move (MoveAbility)     ability_name="移动"，ability_tag=Ability.Move，cooldown_effect=<时长资源>
├─ BattleBrain
├─ Body (Sprite2D)           tokens.png 区域 (64,0,32,32)，红色
├─ HealthBar (UnitHealthBar) 位置 (0,20)
└─ Name (Label)              头顶名字，偏移 -32,-34 ~ 32,-18
```

- `souls` 里的魂灵会通过 `BattleUnit.add_soul_abilities()` 生成 `AutoCastAbility`，怪物因此获得对应技能。
- `Move` 是场景里预挂的能力，`setup_from_scene()` 只把它登记给 `BattleBrain`；GAS 在 ASC 入树时已经授予过。
- 掉落物也可以是魂灵；掉进 `inventory_0` 后，玩家可以按 `equip_part` 装备。

### 4.9 开战、关窗、死亡

**开战（▶）**

`BattleWindow._start_battle()`：

1. `_clear_battle()`：清掉上一场所有单位、`BattleManager`、扫描线状态；
2. `_run_id += 1`（作废还没执行的重开等待）；
3. 创建 `BattleManager`，接上地图、日志接收器、刷怪回调；
4. 清空 `InfoWindow` 日志；
5. 从魂灵窗口的 `cell_0..cell_3` 收集 `SoulData`；
6. 实例化 Player 场景，`setup_from_scene()`，放到中心格 `(0,0)`；
7. `start_battle()`：所有单位充能从 0 开始；
8. 立刻 `spawn_one()` 刷第一只，避免空场等待；
9. 打开扫描线，按钮文字改成“重开”。

**关窗**

- 标题栏 ×、主界面按钮再次点击，最终都是 `hide()`；
- `visibility_changed` → `_end_battle()`：`_run_id += 1`、`_clear_battle()`、扫描线关闭、按钮恢复 `▷`；
- 下次打开窗口就是这一关的初始状态。

**角色死亡**

- `BattleUnit._die()` 加 `State.Dead`、发 `died`；
- `BattleManager._on_unit_died()`：如果是玩家，`is_running = false`（停止刷怪）；如果是怪，掷掉落、从名册移除、释放节点；
- `BattleWindow._on_player_died()`：日志提示，等 `REVIVE_DELAY = 3` 秒；期间如果玩家自己点了重开或关了窗口（`_run_id` 变了/窗口不可见），这次等待作废；否则整场重开。

**加速按钮**

- `1x / 2x / 3x / 10x` 直接设置 `Engine.time_scale`；
- 这是全局时间倍率，不只影响战斗窗口；
- `BaseWindow` 关闭时会还原为 `1`（临时做法）。

## 5. 战斗数据 `game/content/`

### 5.1 `SkillDefinition`（`skill_definition.gd`）

一份 `SkillDefinition` = 一个技能的全部数据，新增技能不需要改代码。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 英文短 id，用于 `ability_tag = "Skill." + id` |
| `description` | `String` | 面向玩家的描述 |
| `effects` | `Array[GameplayEffect]` | 施加到每个目标的效果列表，可以多条 |
| `cooldown_effect` | `GameplayEffect` | **只读取 `duration` 当冷却时长**，不会挂到 ASC |
| `crit_chance` | `float` | 暴击率 0~1，默认 0 |
| `crit_multiplier` | `float` | 暴击倍率，默认 1.5 |
| `target_rule` | `TargetRuleBase` | 目标规则：`TargetRule` 选战斗单位，`SoulTargetRule` 选魂灵 |
| `haste_duration` | `float` | 加速时长；仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `slow_duration` | `float` | 减速时长；仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `charge_duration` | `float` | 充能秒数；直接减少目标当前冷却，仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `projectile_scene` | `PackedScene` | 留空 = 立即结算；填了 = 每个目标发一支投射物 |
| `projectile_speed` | `float` | 投射物速度（像素/秒），默认 420；≤0 时用投射物默认值 |
| `cast_time` | `float` | 吟唱时间，0 = 瞬发；吟唱结束会重新选目标 |
| `cast_requires_tags` | `Array[StringName]` | 施法条件，翻译成 GAS 的 `activation_query` |

技能显示名不在这份数据里：`AutoCastAbility.ability_name` 来自魂灵的 `ItemData.item_name`，没传时退回 `SkillDefinition.id`。

所有 `*_duration` 和 `cooldown_effect.duration` 在资源里仍然是秒；`ChargedAbility` 内部按 1 秒 = 120 刻度换算。

### 5.2 `TargetRule`（`target_rule.gd`）

`TargetRule` 和 `SoulTargetRule` 都继承 `TargetRuleBase`；`SkillDefinition.target_rule` 按实际类型分派。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.RANDOM` | 随机 `count` 个，不重复 |
| `Mode.REPEAT` | 随机 `count` 次，可重复；每次独立结算 |
| `Mode.LOWEST_HP_PERCENT` | 血量百分比最低的 `count` 个 |
| `Mode.NEAREST` | 离自己最近的 `count` 个 |
| `Mode.ALL` | 全部 |
| `Camp.ENEMY` | 敌方 |
| `Camp.ALLY` | 友方 |
| `Camp.SELF` | 自己 |
| `count` | 选几个 / 重复几次 |
| `max_range` | 只挑 `max_range` 格内的目标；0 = 不限 |
| `include_self` | `ALLY` 时是否允许选中自己 |

`resolve()` 返回“批次数组” `Array[Array[BattleUnit]]`：

- `RANDOM / LOWEST_HP_PERCENT / ALL / NEAREST` → 只产生 1 个批次（一次打多个目标）；
- `REPEAT` → 产生 `count` 个批次，每批 1 个目标，保证每次独立结算。

### 5.3 `SoulTargetRule`（`soul_target_rule.gd`）

给“以魂灵为目标”的技能用；和 `TargetRule` 一样继承 `TargetRuleBase`，但选的是魂灵能力，返回类型也不同。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.LEFT` | 同一部位行内，紧挨在左侧的魂灵；中间空一格就不算相邻 |
| `Mode.RIGHT` | 同一部位行内，紧挨在右侧的魂灵；中间空一格就不算相邻 |
| `Mode.BOTH_SIDES` | 同一部位行内，左右两侧紧邻的魂灵；各最多一个 |
| `Mode.RANDOM` | 从有冷却的魂灵里随机 `count` 个 |
| `Mode.SELF` | 自己 |
| `Mode.ALL` | 全部有冷却的魂灵 |
| `include_self` | `RANDOM / ALL` 时是否包含自己 |
| `count` | `RANDOM` 时选几个 |

`resolve(caster, rng)` 返回 `Array[ChargedAbility]`：

- 候选只来自 `caster.soul_loadout`，且 `cooldown > 0`；
- 无冷却魂灵当前没有设计，先直接排除，等以后补规则；
- `LEFT / RIGHT / BOTH_SIDES` 只比较同一 `soul_container`，不跨部位；
- `BOTH_SIDES` 同时检查左右两侧；空位、无冷却魂灵跳过，两边都没有才空放；
- 相邻判定用 `SoulSlot` 的 `column / width`：
  - 右侧：目标最左列 = 施法者最左列 + 施法者列宽；
  - 左侧：目标最左列 + 目标列宽 = 施法者最左列；
- 没有目标就返回空数组，技能空放并照常消耗冷却。

### 5.4 `DropEntry`（`drops/drop_entry.gd`）

| 字段 | 说明 |
|---|---|
| `item: ItemData` | 掉什么；魂灵就是 `SoulData` |
| `chance: float` | 0~1，默认 0.2；每条独立掷骰 |

怪物在场景根节点的 `drops` 数组里配置多条；死亡时 `BattleManager._roll_drops()` 逐条判定，成功就 `GBIS.add_item("inventory_0", item)`，失败（仓库满）就写日志丢失。

### 5.5 魂灵与技能实现经验

路径：`game/content/Souls/<名字>/`

- 主动魂灵：`SoulData.skill` 指向 `SkillDefinition`，由 `BattleUnit.add_soul_abilities()` 生成 `AutoCastAbility`；显示名取 `item_name`。冷却由 `ChargedAbility` 的充能模型管理，`cooldown_effect` 只提供时长。投射物速度由 `SkillDefinition.projectile_speed` 控制，默认 420。
- 被动魂灵：使用 `PassiveSoulData`，没有冷却、不进入自动施法队列、不显示扫描线；`passive_effects` 在血条绑定和 `_connect_asc()` 之前挂到玩家 ASC，因此不会产生开场状态日志。
  - 被动属性效果使用 `PassiveEffect` 类型（`GameplayEffect` 子类）标记，`BattleUnit` 用类型判断是否写日志。
  - 被动魂灵占格，会阻断左右相邻；`SoulTargetRule` 只从 `cooldown > 0` 的主动魂灵里选，因此不会被加速/减速/充能选中。
- 触发型被动：`PassiveSoulData.triggers` 配 `PassiveTrigger`；`BattleUnit` 监听 `BattleManager.unit_moved`，只对敌方移动触发。触发效果通过 spec 的 SetByCaller `Data.TriggerMagnitude` 传数值，不在效果资源里写死。
- 直接伤害：挂 `SoulDamageExecution`，吃施法者 `damage_bonus`，暴击在加成后计算；伤害+剧毒挂 `PoisonDamageExecution`，剧毒值等于最终伤害；治疗、灼烧、剧毒、生命再生周期本身不要挂。
- 护盾获得挂 `ShieldExecution`，不吃 `damage_bonus`。
- 单独施加灼烧/剧毒/生命再生挂 `StatusApplyExecution`，数值向下取整；治疗挂 `HealExecution`，治疗量的 5%（向下取整）从治疗目标的灼烧/剧毒中扣除。再生不是治疗，不触发净化。
- 伤害分流：`DamageResolver.split_damage()` 统一先扣护盾；普通伤害 1 护盾抵 1 伤害；灼烧对护盾伤害 `floor(伤害 × 0.5)`，破盾后剩余按“1 护盾抵 2 灼烧”进生命；剧毒无视护盾。
- 异常状态的暴击：只在释放/施加时判定，把暴击后的数值写进状态；之后灼烧/剧毒/生命再生每跳不再暴击。
- 持续伤害/再生：周期效果用 `BurnTickExecution` / `PoisonTickExecution` / `RegenTickExecution`；周期效果不会逐跳发 `effect_received`，每跳叙事由 ASC 的 `periodic_effect_ticked` 提供；`attribute_changed` 只负责血条/死亡。
- 扫描线：只有主动魂灵显示；每颗魂灵资源仍带 `ShaderMaterial`（`soul_scanline.gdshader`，`enable = 0`），被动魂灵不打开。
- 装备栏徽章：加速/减速剩余秒数显示在已装备的魂灵实例上；充能是瞬时的，不显示徽章。
- 调试入口：新魂灵暂时通过仓库窗口的调试按钮加入 `inventory_0`；正式入口由掉落/商店决定，不应写死在魂灵资源里。

### 5.6 冷却效果资源

- `game/content/effects/move_cooldown.tres`：`policy = 1`，`duration = 3.0`，给蛇的 `MoveAbility` 当移动节奏。
- 技能冷却效果目前直接内嵌在各 `*_skill.tres` 的子资源里（如 `Resource_effect_cooldown`），没有单独文件；只读 `duration`，不挂到 ASC。
- 这些效果只作为“时长数据”，不会真正施加到 ASC；`resource_name`、`granted_tags` 也不再需要。

持续效果资源：

- `game/content/effects/burn_apply.tres`：`INSTANT`，挂 `StatusApplyExecution`，写 `burn`；有 `Data.TriggerMagnitude` 时用触发器数值，否则用 base，结果向下取整。
- `game/content/effects/poison_apply.tres`：同上，写 `poison`。
- `game/content/effects/regen_apply.tres`：同上，写 `regen`，基础数值 5。
- `game/content/effects/burn_tick.tres`：`INFINITE`、`period = 0.5`、`max_stacks = 1`、`granted_tags = [State.Burning]`，挂 `BurnTickExecution`；每跳按当前整数层数结算并衰减。
- `game/content/effects/poison_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`、`granted_tags = [State.Poisoned]`，挂 `PoisonTickExecution`；每跳按当前剧毒值直接扣生命，无视护盾且不衰减。
- `game/content/effects/regen_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`，挂 `RegenTickExecution`；每跳按当前再生值恢复生命，不衰减、不净化、溢出丢弃。当前没有为再生注册 `State.Regen` 标签。
- 这些资源不填 `resource_name`，编辑器按原文件名显示；战斗日志里灼烧/剧毒/生命再生周期效果由 `BattleUnit._effect_display_name()` 统一显示为“灼烧”/“剧毒”/“生命再生”。

GAS 属性：

- 两个 `AttributeSet` 的默认生命值都是 500，但 `BattleUnit._init_attributes()` 会用场景根节点的 `max_health` 覆盖 `max_health` 和 `health` 的 `base_value`。
- `damage_bonus` 是己方魂灵直接伤害加成；`burn` 是当前灼烧层数，按整数层数结算；`shield` 是当前护盾值，无上限；`poison` 是当前剧毒值，按整数结算，每秒且不衰减；`regen` 是当前生命再生值，按整数结算，每秒恢复等量生命且不衰减。
- ASC 在 `_ready()` 时会深拷贝 `attribute_sets`，所以 `BattleUnit` 必须等节点入树后再取 `get_attribute()` 的引用。
- `pre_attribute_change()` 负责下限/上限钳制，`post_attribute_change()` 负责 `max_health` 变化时同步 `health`。
- `BattleUnit._apply_passive_effects()` 在被动最大生命变化后，用运行时 `INSTANT GameplayEffect`（health `ADD health_delta`）同步当前生命，不再直接调用 ASC 内部改属性方法；此时还没连接日志/血条，所以不会产生开场飘字。

## 7. 背包 / 仓库系统（GBIS）

### 7.1 接入方式

- 框架的 autoload 脚本是 `Windows/Inventory/grid_base_inventory_system/core/grid_base_inventory_system.gd`，全局名必须是 `GBIS`。
- `GBIS` 在启动时 `new` 出所有 Service，外部不要自己再 `new`：
  - `inventory_service`、`shop_service`、`equipment_slot_service`、`moving_item_service`、`item_focus_service`。
- `ContainerRepository` / `EquipmentSlotRepository` 是 `Resource` 单例（`static var instance`），通过 `GBIS` 的 Service 访问。
- 视图层通过 `GBIS` 的信号刷新，不直接互相引用。

### 7.2 分层与主要类

```
core/
├─ grid_base_inventory_system.gd        GBIS autoload：信号、Service、全局配置
├─ model/
│  ├─ item/ItemData                     物品基类：名称、类型、图标、占格、材质、shader 参数
│  ├─ item/SoulData                     extends ItemData：skill + equip_part + 战斗显示用剩余秒数
│  └─ container/ContainerData           网格容器：格子↔物品映射、放置规则
├─ repository/
│  └─ ContainerRepository               所有 ContainerData 的存取与存档
├─ service/
│  ├─ BaseContainerService              注册容器、按格子/名字查物品、放置物品
│  ├─ InventoryService                  背包：添加/移除/使用/分割/快速移动
│  ├─ MovingItemService                 拖拽中的物品与跟随鼠标的 ItemView
│  └─ ItemFocusService                  鼠标当前悬停的物品（tooltip 用）
└─ view/
   ├─ container/BaseContainerView       容器视图基类：网格 + 物品绘制
   ├─ container/InventoryView           背包视图（可配置类型/部位）
   ├─ container/BaseGridView            单个格子的绘制与悬停
   ├─ container/InventoryGridView       背包格子输入：左键拿/放、右键用、Shift+左键快移、中键分割
   └─ item/ItemView                     物品图标 + 堆叠数字 + shader 参数 + 魂灵加速/减速徽章
```

未接入的 `StackableData`、`ConsumableData`、`EquipmentData`、`EquipmentSlot*`、`Shop*`、`DropAreaView` 见 7.7。

`PassiveSoulData` 位于 `game/content/passive_soul_data.gd`，继承 `SoulData`，新增 `passive_effects` 和 `triggers`；`PassiveTrigger` 位于 `game/content/passive_trigger.gd`。它们属于游戏内容层，不修改 GBIS 框架本身。

### 7.3 GBIS 信号

| 信号 | 参数 | 用途 |
|---|---|---|
| `sig_inv_item_added` | `inv_name, item_data, grids` | 背包新增物品 |
| `sig_inv_item_removed` | `inv_name, item_data` | 背包移除物品 |
| `sig_inv_item_updated` | `inv_name, grid_id` | 物品数量/外观更新 |
| `sig_inv_refresh` | 无 | 整包刷新 |
| `sig_item_focused` | `item_data, container_name` | 鼠标悬停到物品 |
| `sig_item_focus_lost` | `item_data` | 鼠标离开物品 |

当前项目实际监听：

- `InventoryView`：`sig_inv_item_added/removed/updated/refresh`；
- `InventoryWindow`：`sig_item_focused` / `sig_item_focus_lost`，用来显示/隐藏 TooltipWindow 的 `ITEM` 层。

### 7.4 数据流

**注册容器**

```
InventoryView._ready()
  → GBIS.inventory_service.regist(name, columns, rows, false, avilable_types)
  → ContainerRepository.add_container()  （同名直接返回已有容器）
  → ContainerData（建立 grid_item_map）
  → InventoryView 创建 GridContainer + 格子 View + 物品容器
  → 连接 GBIS 信号
```

- `InventoryView._ready()` 在编辑器模式下只重算尺寸，不注册容器。
- 容器可见时会把名字加入 `GBIS.opened_containers`，不可见时移除；快速移动只考虑打开着的背包。

**添加物品**

```
GBIS.add_item(inv_name, item_data)
  → InventoryService.add_item()
      → item_data.duplicate()          （每件物品独立实例）
      → ContainerData.add_item()
          → is_item_avilable()         （类型 + 部位检查）
          → 找第一个放得下的位置
      → sig_inv_item_added.emit()
  → InventoryView._on_item_added()     （只处理自己的容器，且必须可见）
  → 创建 ItemView
```

**拖拽物品**

```
左键点在有物品的格子
  → MovingItemService.move_item_by_grid()
      → 从 ContainerData 移除（发 sig_inv_item_removed）
      → ItemWindow.hold(ItemView, 抓取偏移)
  → ItemWindow._process() 每帧跟随鼠标

左键点在目标格子
  → InventoryService.place_moving_item()
      → ContainerData.try_add_to_grid()
      → sig_inv_item_added
```

- `MovingItemService` 里保存 `moving_item`、`moving_item_view`、`moving_item_offset`；
- `ItemWindow` 是独立无边框窗口，物品拖出原窗口也不会被画布裁掉；
- 取消/放下时 `MovingItemService.clear_moving_item()` 会清掉 `ItemWindow`。

### 7.5 本项目的扩展：魂灵部位限制

框架原本只有 `type`（物品类型）限制；本项目在三个地方加了“装备部位”：

| 位置 | 字段 | 作用 |
|---|---|---|
| `SoulData` | `equip_part`：`ANY / HEADSOUL / TORSOSOUL / ARMSSOUL / LEGSSOUL` | 这颗魂灵能装在哪个部位 |
| `ContainerData` | `equip_part`（空 = 不限制） | 这个容器只收对应部位的魂灵；`ANY` 魂灵不受限 |
| `InventoryView` | `equip_part`：`NONE / HEADSOUL / ...` | 编辑器里配置；`_ready()` / `change_data_source()` 时把 `NONE` 归一成 `""` 写进 `ContainerData` |

`ContainerData.is_item_avilable()` 的判定顺序：

1. `avilable_types` 必须是 `ANY` 或包含物品的 `type`；
2. 如果容器有 `equip_part` 且物品是 `SoulData`，则 `soul.equip_part` 必须是 `ANY` 或与容器部位相同；
3. 否则允许。

魂灵窗口的四个容器就是四个“只收指定部位魂灵的小背包”，不是传统的单槽装备系统：

| 容器名 | 节点 | 部位 | 尺寸（实际） | 类型 |
|---|---|---|---|---|
| `cell_0` | `EquipmentWindow/VBoxContainer/Cell0/SoulView` | `HEADSOUL` | 10 列 × 2 行 | `SOUL` |
| `cell_1` | `EquipmentWindow/VBoxContainer/Cell1/SoulView` | `TORSOSOUL` | 10 列 × 2 行 | `SOUL` |
| `cell_2` | `EquipmentWindow/VBoxContainer/Cell2/SoulView` | `ARMSSOUL` | 10 列 × 2 行 | `SOUL` |
| `cell_3` | `EquipmentWindow/VBoxContainer/Cell3/SoulView` | `LEGSSOUL` | 10 列 × 2 行 | `SOUL` |

> 注意：`DOC/魂灵/开发指导文件.md` 写的是“每个部位均有 10 格”，但当前 `InventoryView` 只设置了 `container_columns = 10`，`container_rows` 用默认值 2，所以实际是 10×2 = 20 格。后续要么改文档，要么在场景里显式设置 `container_rows`。

仓库容器：

| 容器名 | 节点 | 尺寸 | 类型 | 用途 |
|---|---|---|---|---|
| `inventory_0` | `InventoryWindow/InventoryView` | 26×24 | `SOUL` | 仓库，也是怪物掉落的目的地 |

## 9. 关键流程串讲

### 9.1 敌人移动 → 触发型被动 → 持续伤害

```
敌方单位 MoveAbility 走一格
  → BattleUnit.move_to_cell()：cell 更新 + 发 moved
  → BattleManager._on_unit_moved() → unit_moved
  → 玩家 BattleUnit._on_battle_unit_moved()
      → 只处理 team = ENEMY 的单位
      → 遍历玩家的触发型被动（PassiveTrigger）
          → 对移动的怪物施加触发器配置的即时效果
          → 施加周期效果（例如灼烧）；数值由 trigger.magnitude 传入
  → 之后按周期效果的 period 结算：
      → execution 计算本跳的伤害/层数变化
      → periodic_effect_ticked 里按效果类型识别，写日志/飘字
      → 周期效果不会逐跳发 effect_received
```

### 9.2 Tooltip 与拖拽

```
鼠标进入物品格
  → InventoryView.grid_hover → ItemFocusService.focus_item
  → sig_item_focused → InventoryWindow 用 ITEM 层显示 TooltipWindow

鼠标离开
  → item_lose_focus → 本帧末确认 → sig_item_focus_lost → TooltipWindow.hide_tip(self)

拖拽
  → 左键拿起：物品从容器移除，ItemWindow（无边框、跟随鼠标）显示 ItemView
  → 左键放下：ContainerData.try_add_to_grid → sig_inv_item_added
```

- `ItemFocusService` 会把“失去焦点”延迟到本帧末再确认，避免物品跨多个格子时 tooltip 闪烁；拖拽中不切换焦点。
- 战斗窗口也会用同一个 TooltipWindow 显示格子坐标，但它只有在自己拥有焦点、且没有被更高层 owner 占住时才显示（`_update_coord_tooltip()`）。
- 魂灵窗口盖在战斗窗口上时，物品 tooltip 是 `ITEM` 层，战斗坐标是 `COORD` 层，战斗窗口的每帧调用不能覆盖或隐藏物品 tooltip。
- 战斗窗口判断鼠标是否在自己里面，用的是系统鼠标坐标 + 窗口 `Rect2i(position, size)`，因为每个 `Window` 是独立 OS 窗口。

## 10. 扩展点

### 10.1 新增一颗魂灵

1. 主动魂灵：在 `game/content/Souls/<名字>/` 下新建 `SkillDefinition` 资源（`*_skill.tres`）：
   - `id`、`description`；
   - `effects`（`GameplayEffect`，伤害/治疗用 modifier 改 `health`）；
   - 伤害效果挂 `SoulDamageExecution`（`game/content/soul_damage_execution.gd`），填 `base_damage`；治疗、灼烧、剧毒、生命再生不要挂；
   - 护盾效果挂 `ShieldExecution`（`game/content/shield_execution.gd`），填 `base_shield`；
   - `cooldown_effect`（只填 `duration`）；
   - 普通战斗单位技能：`target_rule` 选 `TargetRule`；
   - 以魂灵为目标的技能：`target_rule` 选 `SoulTargetRule`，按需配 `haste_duration` / `slow_duration` / `charge_duration`；
   - 可选 `crit_chance`、`crit_multiplier`、`projectile_scene`、`cast_time`、`cast_requires_tags`。
2. 新建魂灵资源（`*_soul.tres`）：
   - 主动魂灵用 `SoulData`，`skill` 指向上面的技能；
   - 被动魂灵用 `PassiveSoulData`（`game/content/passive_soul_data.gd`），`passive_effects` 填 `PassiveEffect`（`game/content/passive_effect.gd`，继承 `GameplayEffect` 的标记类），不填 `skill`；`PassiveEffect` 类型不写状态日志；
   - 触发型被动再加一个 `PassiveTrigger`（`game/content/passive_trigger.gd`）到 `triggers`；当前支持 `ENEMY_MOVED`，触发时把 `effects` 施加到移动的怪物；
   - `equip_part` 选部位；
   - `item_name`、`type = "SOUL"`、`icon`、`columns/rows`；
   - 扫描线材质（`soul_scanline.gdshader`，`enable = 0`；被动魂灵不会打开它）。
3. 放进游戏：
   - 调试用：在 `inventory_window.gd` 加一个 `preload` + 按钮，`GBIS.add_item("inventory_0", soul)`；
   - 正式用：配置到某个怪物的 `drops`。
4. 战斗内不需要改代码：主动魂灵由 `BattleUnit.add_soul_abilities()` 自动生成技能，显示名取 `item_name`；属性型被动由 `BattleWindow._spawn_player()` 收集 `passive_effects` 并在 `setup_from_scene()` 时挂到玩家 ASC；触发型被动同时收集 `triggers`，玩家 `BattleUnit` 监听 `BattleManager.unit_moved`。

### 10.2 新增一种怪物

1. 复制 `game/content/Monster/snake/snake.tscn`；
2. 设置根节点：`unit_name`、`team = ENEMY`、`max_health`、`drops`、`souls`；
3. 配 ASC 的 `attribute_sets`（可用 `MonsterStatsAttributeSet` 或新建）；
4. 需要移动就挂 `MoveAbility`，配 `cooldown_effect`；需要主动技能就把 `SoulData` 放进 `souls`；
5. 在 `Windows/Battle/battle_window.gd` 里 preload 新场景，并把 `_spawn_enemy()` 改成按需实例化（目前固定只刷蛇）。

### 10.3 新增技能（不改代码）

- 用现有 `TargetRule` 模式 + `GameplayEffect` + `projectile_scene` 就能组合出大部分主动技能；
- 新的战斗单位目标模式 → 扩展 `TargetRule.Mode` 和 `resolve()`；
- 新的魂灵目标模式 → 扩展 `SoulTargetRule.Mode` 和 `resolve()`；
- 新的效果类型（中毒等）→ 先用 GAS 的 `GameplayEffect`（周期效果、modifier）实现，再补标签和 Cue；护盾参考 `ShieldExecution`；
- 新增持续伤害/再生 → 参考 `burn_tick.tres` + `BurnTickExecution` 或 `regen_tick.tres` + `RegenTickExecution`：周期效果只负责计时，每次 tick 用 execution 读取目标状态并返回属性变化；`effect_received` 在周期效果上只表示“已施加”，每跳叙事监听 `periodic_effect_ticked`；
- 新的“状态” → 先加到 `godot_gas/tag_registry.tres`，再用插件重新生成 `gameplay_tags.gd`。

### 10.4 新增窗口

1. 新建场景，根节点用 `Window`，挂一个 `extends BaseWindow` 的脚本；
2. 在场景里设 `open_position`（或在 `control.tscn` 实例上覆盖）；
3. 把场景实例加到 `Main/control.tscn`；
4. 在 `Main/control.gd` 里加按钮/信号并调用 `popup_window()`。

### 10.5 新增特效

按 `DOC/effects.md` 的三步走：写 `GameplayCueNotify` 场景 → 登记到 `godot_gas/cue_registry.tres` → 挂到 `GameplayEffect` 的 `application/persistent/periodic/removal_cue_tags`。

## 11. 现状与注意点

### 已实现

- 窗口外壳、主界面按钮、状态栏置顶/贴边；
- 魂灵仓库、四部位限制、拖拽、tooltip；
- 战斗：自动施法、充能冷却、扫描线、选目标、投射物、暴击、伤害/治疗、掉落、死亡重开、加速按钮；
- 主动魂灵：加速、减速、充能、护盾、伤害+剧毒、生命再生；
- 被动魂灵：属性型被动和触发型被动；
- 护盾：`shield` 属性、`ShieldExecution`、伤害先行分流、黄色日志/飘字；
- 灼烧：整数层数、周期结算、对护盾减半、`periodic_effect_ticked` 叙事；
- 剧毒：`poison` 属性、每秒结算、不衰减、无视护盾、墨绿日志/飘字；
- 治疗：`HealExecution`，治疗量可暴击，并按治疗量 5% 净化目标的灼烧/剧毒；
- 生命再生：`regen` 属性、每秒结算、不衰减、不净化、溢出丢弃、亮绿色日志/飘字；面包主动魂灵；
- 魂灵状态徽章、玩家生命/再生/护盾/灼烧/剧毒条、战斗日志。

### 未实现 / 占位

- **负面/增益状态**：Freeze（只有 `State.Frozen` 钩子）；
- **移动状态**：迅捷/迟缓；
- **人物窗口、商店窗口、图鉴窗口**：空壳；
- **Tooltip 内容**：只显示标题；
- **存档、装备槽、丢弃区、消耗品/可穿戴/可堆叠物品**：框架支持，游戏内未接入。

### 注意点

1. `BattleManager.SPAWN_INTERVAL = 0.2` 秒，刷怪很快；正式数值待确认。
2. `BattleBrain` 用 `_physics_process`，`BattleManager` 用 `_process`；加速按钮改 `Engine.time_scale`，两者都会跟着变快。
3. `BattleUnit._die()` 会停掉大脑的 `_process` 和 `_physics_process`；`BattleBrain` 开头的 `is_dead` 提前返回作为兜底。
4. 任何 `BaseWindow` 关闭都会把 `Engine.time_scale` 还原为 1；以后多窗口同时影响时间倍率时，需要改成引用计数或统一管理。
5. `MoveAbility` 没配 `cooldown_effect` 时 `cooldown = 0`，会每个物理帧走一格；新增怪物时记得配。
6. 魂灵容器实际是 10×2，设计文档写“每个部位 10 格”，两者不一致（见 7.5）。
7. `GameplayTags` 是自动生成文件，新增标签后不要手改，走插件重新生成。
8. 内部按 1/120 秒刻度：60 Hz、1x 时普通 +2/帧、加速 +4/帧、减速 +1/帧、加速+减速 +2/帧；同一种状态重复施加只累加持续时间，不叠倍率；加速和减速同时存在时抵消为 1x。
9. 左右相邻只在同一部位行内判断，中间空一格就不算相邻；不跨部位。
10. 被动魂灵没有冷却，不在 `soul_loadout` 里；加速/减速/充能目标只选 `cooldown > 0` 的主动魂灵，被动不会被选中，但会占格阻断左右相邻。
11. 战斗中不能改魂灵装备；当前是开战快照，换装不影响本场，下一场才生效。
12. 加速/减速/充能目前只作用于施法者自己魂灵栏里的魂灵；跨单位选魂灵尚未实现。
13. 状态徽章只显示在装备栏里的魂灵实例上；仓库副本不显示战斗状态。
14. `SoulData.haste_seconds/slow_seconds` 是运行期显示字段，不导出、不写存档。
15. 直接伤害挂 `SoulDamageExecution`，伤害+剧毒挂 `PoisonDamageExecution`，护盾获得挂 `ShieldExecution`；治疗、灼烧、剧毒、生命再生周期本身不要挂直接伤害 execution。
16. 单位真正 `queue_free()` 前要调用 `cleanup_asc()`，否则会留下 active effects、Cue 和协程。
17. `AutoCastAbility` 的 `await` 之后要检查 `is_active`；技能被中止后不能继续结算，投射物落地回调也要检查。
18. 普通伤害/治疗叙事走 `effect_received`，周期伤害/再生每跳走 `periodic_effect_ticked`，`attribute_changed` 只负责血条和死亡；护盾吸收也会写黄色日志/飘字。
19. `burn_tick` 用 `max_stacks = 1` + `REFRESH_DURATION`；重复施加复用同一个周期效果，`State.Burning` 在层数归零后仍保留到效果移除。
20. 被动施加的灼烧不计算暴击；主动灼烧应在释放时按暴击后的数值写入状态，之后每跳不再暴击。当前没有主动灼烧技能；多来源灼烧复用已有周期效果，来源规则等做主动灼烧时再补。
21. 护盾分流统一走 `DamageResolver.split_damage()`：普通伤害 1 护盾吸收 1 伤害；灼烧对护盾伤害 `floor(伤害 × 0.5)`，破盾后剩余伤害按“1 护盾抵消 2 灼烧”进生命。
22. 新增 `GameplayEffect` / 资源不要改中文 `resource_name`，编辑器按原文件名显示；需要玩家可读名称时用 `item_name` 或游戏内显示逻辑。
23. 充能直接改 `charge_units`，不受加速/减速倍率影响，也不生成状态/徽章；充满后同一帧立刻释放，溢出丢弃。
24. 异常状态的暴击只在释放时判定，暴击后的数值写入状态；灼烧/剧毒/生命再生后续每跳不再暴击。剧毒忽略护盾、不衰减；灼烧按 3% 当前层数向下取整衰减；生命再生每秒恢复当前再生值、不衰减、不净化、溢出丢弃。剧毒/灼烧/再生数值都按整数处理，净化量也向下取整。
