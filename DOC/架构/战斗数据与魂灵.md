## 5. 战斗数据 `game/content/`

### 5.1 `SkillDefinition`（`skill_definition.gd`）

一份 `SkillDefinition` = 一个技能的全部数据，新增技能不需要改代码。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `String` | 英文短 id，用于 `ability_tag = "Skill." + id` |
| `description` | `String` | 面向玩家的描述 |
| `effects` | `Array[GameplayEffect]` | 施加到每个目标的效果列表，可以多条 |
| `self_effects` | `Array[GameplayEffect]` | 只对施法者自己结算的效果；目标规则空放也生效 |
| `cooldown_seconds` | `float` | 魂灵充能模型的冷却时长（秒）；不是 GAS 冷却效果 |
| `crit_chance` | `float` | 暴击率 0~1，默认 0 |
| `crit_multiplier` | `float` | 暴击倍率，默认 1.5 |
| `target_rule` | `TargetRuleBase` | 目标规则：`TargetRule` 选战斗单位，`SoulTargetRule` 选魂灵 |
| `haste_duration` | `float` | 加速时长；仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `slow_duration` | `float` | 减速时长；仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `freeze_duration` | `float` | 魂灵冻结时长；仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `charge_duration` | `float` | 充能秒数；直接减少目标当前冷却，仅在 `target_rule` 是 `SoulTargetRule` 时生效 |
| `projectile_scene` | `PackedScene` | 留空 = 立即结算；填了 = 每个目标发一支投射物 |
| `projectile_speed` | `float` | 投射物速度（像素/秒），默认 420；≤0 时用投射物默认值 |
| `cast_time` | `float` | 吟唱时间，0 = 瞬发；吟唱结束会重新选目标 |
| `cast_require_all_tags` | `Array[StringName]` | 必须全部持有才能施放，翻译成 `require_all_tags` |
| `cast_block_tags` | `Array[StringName]` | 持有任意一个就拒绝，翻译成 `ignore_tags` |

技能显示名不在这份数据里：`AutoCastAbility.ability_name` 来自魂灵的 `ItemData.item_name`，没传时退回 `SkillDefinition.id`。

所有 `*_duration` 和 `cooldown_seconds` 在资源里仍然是秒；`ChargedAbility` 内部按 1 秒 = 120 刻度换算。

### 5.2 `TargetRule`（`target_rule.gd`）

`TargetRule` 和 `SoulTargetRule` 都继承 `TargetRuleBase`；`SkillDefinition.target_rule` 按实际类型分派。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.RANDOM` | 随机 `count` 个，不重复 |
| `Mode.REPEAT` | 随机 `count` 次，可重复；每次独立结算 |
| `Mode.LOWEST_HP_PERCENT` | 血量百分比最低的 `count` 个 |
| `Mode.NEAREST` | 离自己最近的 `count` 个 |
| `Mode.ALL` | 全部 |
| `Camp.ENEMY` | 敌方 |
| `Camp.ALLY` | 友方 |
| `Camp.SELF` | 自己 |
| `count` | 选几个 / 重复几次 |
| `max_range` | 只挑 `max_range` 格内的目标；0 = 不限 |
| `include_self` | `ALLY` 时是否允许选中自己 |

`resolve()` 返回“批次数组” `Array[Array[BattleUnit]]`：

- `RANDOM / LOWEST_HP_PERCENT / ALL / NEAREST` → 只产生 1 个批次（一次打多个目标）；
- `REPEAT` → 产生 `count` 个批次，每批 1 个目标，保证每次独立结算。

### 5.3 `SoulTargetRule`（`soul_target_rule.gd`）

给“以魂灵为目标”的技能用；和 `TargetRule` 一样继承 `TargetRuleBase`，但选的是魂灵能力，返回类型也不同。

| 字段 / 枚举 | 说明 |
|---|---|
| `Mode.LEFT` | 同一部位行内，紧挨在左侧的魂灵；中间空一格就不算相邻 |
| `Mode.RIGHT` | 同一部位行内，紧挨在右侧的魂灵；中间空一格就不算相邻 |
| `Mode.BOTH_SIDES` | 同一部位行内，左右两侧紧邻的魂灵；各最多一个 |
| `Mode.RANDOM` | 从有冷却的魂灵里随机 `count` 个 |
| `Mode.SELF` | 自己 |
| `Mode.ALL` | 全部有冷却的魂灵 |
| `include_self` | `RANDOM / ALL` 时是否包含自己 |
| `count` | `RANDOM` 时选几个 |

`resolve(caster, rng)` 返回 `Array[ChargedAbility]`；选中魂灵后由 `SkillDefinition` 的 `haste_duration` / `slow_duration` / `freeze_duration` / `charge_duration` 决定施加什么：

- 候选只来自 `caster.soul_loadout`，且 `cooldown > 0`；
- 玩家和怪物都适用：玩家魂灵栏来自装备容器，怪物魂灵栏由 `MonsterData.soul_entries` 生成；
- 无冷却魂灵当前没有设计，先直接排除，等以后补规则；
- `LEFT / RIGHT / BOTH_SIDES` 只比较同一 `soul_container`，不跨部位；
- `BOTH_SIDES` 同时检查左右两侧；空位、无冷却魂灵跳过，两边都没有才空放；
- 相邻判定用 `SoulSlot` 的 `column / width`：
  - 右侧：目标最左列 = 施法者最左列 + 施法者列宽；
  - 左侧：目标最左列 + 目标列宽 = 施法者最左列；
- 相邻判定统一走 `SoulTargetRule.is_adjacent(a, b)`，`PassiveTrigger` 的“使用相邻魂灵”筛选复用它；
- 没有目标就返回空数组，技能空放并照常消耗冷却。

### 5.4 怪物魂灵与掉落（`MonsterSoulEntry` / `DropEntry`）

`MonsterSoulEntry`（`game/content/monster_soul_entry.gd`）是怪物携带魂灵的唯一配置源：

| 字段 | 说明 |
|---|---|
| `soul: SoulData` | 携带的魂灵；部位取魂灵自身的 `equip_part` |
| `drop_chance: float` | 0~1，默认 0.2；每颗魂灵独立配置 |

`MonsterData.soul_entries` 同时决定两件事：

- `soul_list()`：按配置顺序取出魂灵，交给 `BattleUnit.add_soul_abilities()` 生成技能、生成虚拟魂灵栏；
- `drop_entries()`：把每颗魂灵转成运行时 `DropEntry`（`item = soul`，`chance = drop_chance`）。

`DropEntry`（`game/content/drops/drop_entry.gd`）只负责运行时掷骰：

| 字段 | 说明 |
|---|---|
| `item: ItemData` | 掉什么；魂灵就是 `SoulData` |
| `chance: float` | 0~1，默认 0.2；每条独立掷骰 |

怪死亡时 `BattleManager._roll_drops()` 对每条掉落各判定一次，成功就 `GBIS.add_item("inventory_0", item)`，失败（仓库满）就写日志丢失。因为掉落由携带魂灵自动生成，“怪物能掉落它所有的魂灵”不需要再手配一份掉落表。

### 5.5 魂灵与技能实现经验

路径：`game/content/Souls/<名字>/`

- 主动魂灵：`SoulData.skill` 指向 `SkillDefinition`，由 `BattleUnit.add_soul_abilities()` 生成 `AutoCastAbility`；显示名取 `item_name`。冷却由 `ChargedAbility` 的充能模型管理，时长读 `SkillDefinition.cooldown_seconds`。投射物速度由 `SkillDefinition.projectile_speed` 控制，默认 420。
- 被动魂灵：使用 `PassiveSoulData`，没有冷却、不进入自动施法队列、不显示扫描线；`passive_effects` 在血条绑定和 `_connect_asc()` 之前挂到玩家 ASC，因此不会产生开场状态日志。
  - 被动属性效果使用 `PassiveEffect` 类型（`GameplayEffect` 子类）标记，`BattleUnit` 用类型判断是否写日志。
  - 被动魂灵占格，会阻断左右相邻；`SoulTargetRule` 只从 `cooldown > 0` 的主动魂灵里选，因此不会被加速/减速/冻结/充能选中。
- 魂灵标签：`SoulData.tags` 是 `Array[StringName]`，用于让特定触发效果只识别特定魂灵。当前标签不带层级分类：`Soul.Small` / `Soul.Medium` / `Soul.Large`（按占格宽度 1/2/3 列）与 `Soul.RealEstate`；所有魂灵的 `equip_part` 目前统一为 `ANY`。
- 魂灵触发器：`SoulData.triggers` 配 `PassiveTrigger`，主动/被动魂灵通用。`BattleUnit.add_soul_abilities()` 为每条触发器生成一个 `SoulTriggerAbility`（`GameplayAbility` 子类），grant 到 ASC 并把 `PassiveTrigger.event_tag` 写进 `trigger_event_tag`。它**不进入** `BattleBrain.abilities`，不会被主循环自动施放，只由 `ASC.send_gameplay_event()` 按标签唤醒；payload 里带 `target`、`used_ability`、`used_soul`、`ratio`、`trace`。
  - `Event.Movement.UnitMoved`：`BattleUnit._on_battle_unit_moved()` 只对敌方移动发送；蹈火术用。
  - `Event.Health.BelowPercent`：`attribute_changed` 里生命下降时发送，payload 带旧值/新值/比例；`SoulTriggerAbility` 按 `threshold_ratio` 严格小于判断，`once_per_battle` 控制只触发一次；温泉用（只负责冻结全体，充能拆到 `Event.Combat.FreezeApplied`）。
  - `Event.Combat.SoulUsed`：另一个魂灵技能成功激活（含空放）时由 `AutoCastAbility._notify_soul_used()` 发送；`SoulTriggerAbility` 排除来源自己，`required_soul_tags` 要求被使用魂灵带齐标签，`require_adjacent` 要求同一部位行内紧邻。命中后按 `charge_source_seconds` 给来源魂灵充能；充满时由 `BattleBrain.request_activation()` 入队、当帧末统一释放，受 20 刻激活锁限制（同一颗魂灵 1 秒最多 6 次）。冷冻间、冰车用。
  - `Event.Combat.FreezeApplied`：任何单位被冻结时，向所有以它为敌、且确实带该触发器事件的单位发送；每冻住一个目标触发一次，重复冻结同一目标也算，不区分冻结来源。温泉用（每有一只怪物被冻结，充能 3 秒）、冷冻间用（每只 +2 生命再生）。
  - `target_scope` 支持事件目标 / 自己 / 全体敌人；触发效果通过 spec 的 SetByCaller `Data.TriggerMagnitude` 传数值，不在效果资源里写死。
  - `charge_source_seconds` 在触发后给来源主动魂灵充能；被动魂灵没有来源技能，忽略该字段。
  - `trigger_name` 非空时写一行“触发【名字】”日志；留空保持原有静默行为。
  - 只有 ASC 上确实存在对应 `trigger_event_tag` 的触发器时才发送事件，避免无监听者的事件刷屏。
- 直接伤害：挂 `SoulDamageExecution`，吃施法者 `damage_bonus`，暴击在加成后计算；伤害+剧毒挂 `PoisonDamageExecution`，剧毒值 = 最终伤害 × `poison_ratio`（默认 1，最少 1 点，整数）；治疗、灼烧、剧毒、生命再生周期本身不要挂。
- 护盾获得挂 `ShieldExecution`，不吃 `damage_bonus`。
- 单独施加灼烧/剧毒/生命再生挂 `StatusApplyExecution`，数值向下取整；治疗挂 `HealExecution`，治疗量的 5%（向下取整）从治疗目标的灼烧/剧毒中扣除。再生不是治疗，不触发净化。剧毒与再生同时存在时属性原值各自保留，只在每跳结算时相减。
- 伤害分流：`DamageResolver.split_damage()` 统一先扣护盾；普通伤害 1 护盾抵 1 伤害；灼烧对护盾伤害 `floor(伤害 × 0.5)`，破盾后剩余按“1 护盾抵 2 灼烧”进生命；剧毒无视护盾。
- 异常状态的暴击：只在释放/施加时判定，把暴击后的数值写进状态；之后灼烧/剧毒/生命再生每跳不再暴击。
- 持续伤害/再生：周期效果用 `BurnTickExecution` / `PoisonTickExecution` / `RegenTickExecution`；剧毒与再生每跳先按整数层数相减，数值大的一方生效（差值结算，相等时两边都不结算）；周期效果不会逐跳发 `effect_received`，每跳叙事由 ASC 的 `periodic_effect_ticked` 提供；`attribute_changed` 只负责血条/死亡。
- 扫描线：只有主动魂灵显示；每颗魂灵资源仍带 `ShaderMaterial`（`soul_scanline.gdshader`，`enable = 0`），被动魂灵不打开。
- 装备栏徽章：加速/减速剩余秒数显示在已装备的魂灵实例上；充能是瞬时的，不显示徽章。
- 调试入口：新魂灵暂时通过仓库窗口的调试按钮加入 `inventory_0`；正式入口由掉落/商店决定，不应写死在魂灵资源里。

### 5.6 冷却与持续效果资源

- 技能冷却不再有 `GameplayEffect` 资源：`SkillDefinition.cooldown_seconds` 是唯一时长来源，`ChargedAbility` 按充能模型管理；`GameplayAbility.cooldown_effect` 保持为空。
- 怪物移动已改为即时制；速度配在场景根的 `BattleUnit.move_speed`（像素/秒）。

持续效果资源：

- `game/content/effects/burn_apply.tres`：`INSTANT`，挂 `StatusApplyExecution`，写 `burn`；有 `Data.TriggerMagnitude` 时用触发器数值，否则用 base，结果向下取整。
- `game/content/effects/poison_apply.tres`：同上，写 `poison`。
- `game/content/effects/regen_apply.tres`：同上，写 `regen`，基础数值 5。
- `game/content/effects/burn_tick.tres`：`INFINITE`、`period = 0.5`、`max_stacks = 1`、`granted_tags = [State.Burning]`，挂 `BurnTickExecution`；每跳按当前整数层数结算并衰减。
- `game/content/effects/poison_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`、`granted_tags = [State.Poisoned]`，挂 `PoisonTickExecution`；每跳先与再生相减，剧毒更多时按差值直接扣生命，无视护盾且不衰减。
- `game/content/effects/regen_tick.tres`：`INFINITE`、`period = 1.0`、`max_stacks = 1`，挂 `RegenTickExecution`；每跳先与剧毒相减，再生更多时按差值恢复生命，不衰减、不净化、溢出丢弃。当前没有为再生注册 `State.Regen` 标签。
- `game/content/effects/freeze_unit.tres`：`DURATION`、3 秒、`REFRESH_DURATION`、`max_stacks = 1`，`granted_tags = [State.Frozen]`、`persistent_cue_tags = [Cue.Status.Freeze]`；没有 execution，只负责挂标签和持续 Cue。
- `game/content/effects/freeze_unit_short.tres`：同上，`duration = 1.0`，给冷冻间/冰车的单位冻结用；文件名不写数值。
- `game/content/effects/wen_quan_burn_apply.tres` / `wen_quan_regen_apply.tres`：温泉专用。灼烧固定 24；再生不写死，`RegenFromBurnExecution` 在施放时读取灼烧效果里 `StatusApplyExecution(burn)` 的结算值，灼烧数值被调整后再生自动跟随。周期部分复用 `burn_tick.tres` / `regen_tick.tres`。冷冻间的冻结再生触发直接复用 `regen_apply.tres` + `regen_tick.tres`，用触发器 `magnitude = 2` 覆盖基础数值。
- 这些资源不填 `resource_name`，编辑器按原文件名显示；战斗日志里灼烧/剧毒/生命再生周期效果由 `BattleUnit._effect_display_name()` 统一显示为“灼烧”/“剧毒”/“生命再生”，冻结按 `State.Frozen` 显示为“冻结”。

### 5.7 怪物数据与见闻清单

见闻窗口的“全部条目”不手写目录，而是两份 YARD registry + 一个 Autoload：

| 位置 | 作用 |
|---|---|
| `game/content/Collection/soul_registry.tres` | `SoulData` 全量清单；扫 `game/content/Souls/`，正则 `_soul\.tres$` |
| `game/content/Collection/monster_registry.tres` | `MonsterData` 全量清单；扫 `game/content/Monster/`，正则 `_data\.tres$` |
| `Scripts/collection_db.gd` | 运行时索引、已遇见状态、`user://collection.cfg` 存档 |

- registry 的字符串 ID 默认取文件名（`xiao_lu_soul`、`snake_data`），它同时是“已遇见”存档的键；文件改名/移动不会丢记录；
- registry `.tres` 自身必须带合法 `uid`：YARD 用 UID 作为编辑器打开状态的键，没有 UID 会报 “UID could not be added to the cache”；
- 新增魂灵/怪物文件后，编辑器里的 YARD 扫描自动登记，不需要手改清单；
- `SoulData` 增加了图鉴文案 `description`；主动魂灵留空时窗口回退到 `skill.description`；
- 解锁时机：怪物首次刷出即记录；魂灵首次进背包即记录。`GBIS.add_item()` 会 `duplicate()` 物品，副本没有 `resource_path`，所以 `CollectionDB` 用 `item_name → registry ID` 映射反查；
- 未遇见条目仍占位显示，但不暴露名字、图标和详情。
